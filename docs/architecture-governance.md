# 架构治理工作记录

工作树基于 `36af0151`，覆盖 Companion、Chrome 扩展、Mini、原生桌面进程和发包工具。业务拓扑与能力边界沿用 [项目架构](architecture.md) 及 [ADR 索引](adr/)。本文件记录有代码证据的偏离、迁移与验收。历史审计补丁和已发布版本是研究资料。

## 运行拓扑与状态所有权

| 范围 | 状态或规则的写入方 | 消费者及约束 |
| --- | --- | --- |
| 会话与计划 | Companion 的 `threads/thread-manager.ts` 管理线程索引及消息文件。Board、Loop、Orchestrator 分别负责任务板、无人值守循环与工作者调度 | Side Panel、Mini 和桌面通过路由访问。聊天记录与 `history/store.ts` 的操作事件数据库有不同生命周期 |
| 配置、环境与缓存 | `config.ts` 管理配置快照、修改事件与数据目录。`paths.ts` 解析随应用安装的资源。MCP 的确认缓存和 LLM 的视觉能力缓存分别由其域维护 | 目录存在启动时取值与逐次取值两种契约。`config-data-dir-live.test.ts` 验证切换目录后的差异 |
| 身份与授权 | `ws-auth.ts` 管理本机配对，`ws/handshake-surface.ts` 区分连接来源，MCP 授权及 outbound grants 各有调用者与存储边界 | 一个界面的允许操作不能直接充当另一个界面的授权。参见 ADR-017、020、022 |
| 语音与会议 | `voice/stt-session-service.ts` 管理采集，`meeting/meeting-store.ts` 管理会议元数据、转写和纪要。录制文件、视觉证据和连续采集检查点有独立的落盘与恢复要求 | Mini、Side Panel、Summoner 都能使用会议；消息校验、数据持久化、历史摘要和下载是独立的验收入口 |
| API 与模型规则 | `ws/validate.ts`、`message-router.ts` 和分域 handlers 接收来信；`llm/providers/` 负责提供方协议，`bridge/` 描述可调用工具 | 浏览器的设置界面也解释推理力度和输出上限。两端打包方式不同，模型规则需要共同来源 |
| UI 状态与设计 | `sidepanel/store/agentStore.tsx` 管理侧栏投影；面板 Host 管理导航与关闭保护；`DESIGN.md` 与 `sidepanel/ui/tokens.ts` 管理设计约定及 React 令牌 | MV3 background 持有浏览器操作能力。桌面宿主和 Mini 有各自生命周期。视图不能接管配对、录制或业务持久化 |
| 错误、日志与重试 | `logger.ts` 和 `log-rotation.ts` 管理日志；`io.ts` 的重试专用于同卷原子替换时的 Windows 瞬态错误；LLM 传输错误由 `llm/transport-error.ts` 解释 | ACP、MCP 与录制中止各有不同可恢复性。合并重试策略前应验证超时、重放副作用和错误码 |
| 构建与原生边界 | 两个 npm 包各有锁文件。Companion 用 TypeScript 编译并由 esbuild 打包；扩展用 Plasmo。原生宿主、语音二进制和安装包分别由平台脚本构建 | Makefile、CI 与安装包工作流是独立消费者。Companion 测试统一从 `node scripts/run-tests.mjs` 启动，数据由每个测试进程独占 |

## 基线与优化任务池

基线对两个产品源码树的 885 个 TS、TSX、JS 文件分析了编译后可解析的相对字面量依赖，得到 2,287 条同步加载边与 235 条延后加载边。强连通分量有三组。此计数不包含原生链接、生成脚本、进程间消息或运行时计算的模块名。另对命名函数体去注释后比对，得到 72 组重复候选，包含生成物与注入脚本，不能直接当作 72 个缺陷。

| 优先处理 | 已定位的实现与下一项验收 |
| --- | --- |
| 配置与平台循环（已消除） | `config.ts` 与 `platform.ts` 互相加载。锁和 PID 在 CLI、后台和托盘消费，须保持命名管道、套接字与实时配置目录语义 |
| 面板导航循环（已消除） | `ContextPanelHost`、`PacksPanel`、`ShellEnableActions` 在模块初始化时互相加载。导航调用不应初始化会议与场景面板 |
| 会议存储循环（已消除） | `meeting-store`、`meeting-visual-store`、`meeting-visual-schema` 互相加载。保留证据损坏隔离、纪要失效和会话恢复 |
| 跨客户端模型契约（已迁移） | 推理力度和输出预算分别出现在 `companion/src/llm`、`chrome-extension/src/sidepanel/utils`。对照双方打包、所有导出以及浏览器端保存到服务端执行的行为 |
| 原子存储（已迁移） | `io.ts` 中 JSON 与文本替换执行相同清理；会议另有本地写入器。区分建目录、发布前权限、持久化和失败传播后再迁移 |
| 浏览器注入与公共工具 | NotebookLM 有相同 DOM 操作函数体。检查函数是否序列化进不同执行上下文，再决定如何复用；各客户端的文件类型、图像估算和线程关联也需核对 |
| 防回归检查 | CI 已覆盖静态导入环。继续审查含 require 和动态导入的六组模块、生成资产和原生协议 |

## 决策与进度

### 001 会议配置测试隔离

直接执行检查点夹具时，测试会写入进程默认的语音配置。常规运行器在加载业务模块之前分配独立目录。会议测试复用该目录，单独运行则创建自己的临时目录并在退出时清理。保留已有单文件调试入口。用只含模拟配置的目录运行真实检查点用例，断言其内容和目录项均保持原样。另用 TAP、spec 及 Windows census 报告器检验子进程。首次人工基线绕过隔离入口写到了本机语音配置，后续基线已通过隔离入口重跑。

### 002 守护进程地址

`config.getLockFilePath` 与 `getPidFilePath` 是唯一实现。CLI、WebSocket 生命周期及托盘使用相同地址，daemon 保留既有测试和调用契约使用的两个导出名，直接绑定到该实现。移除了平台层对配置的依赖和配置对平台层的反向依赖。为两行路径解析增加独立模块会增加调用层数。隔离运行配置/daemon/跨进程集成测试共 79 项，本机通过 74 项，5 项按平台跳过；两个独立评审均确认 Windows 管道字面值及 POSIX 路径未变。

### 003 侧栏面板导航

保留现有 Host 作为导航状态、关闭保护及事件订阅的唯一提供者。`ContextPanelBody.tsx` 负责实际视图，应用和会议关闭夹具都在组合入口挂载它。这比把全部导航消费者改为依赖另一个 context 更小。关闭录制、Esc、样式和面板顺序沿用原行为。单测用真实模块缓存确认导入导航时七个视图模块均未初始化；测试编译显式覆盖视图。扩展全量 2,052 项通过，Plasmo 生产构建完成，实际会议关闭浏览器夹具生成成功。独立复审确认迁移了夹具并补齐测试类型声明。

### 004 会议存储与证据

会议目录、ID 和包含关系由 `meeting-paths.ts` 定义。读取并验证已有证据是 `meeting-visual-evidence.ts` 的职责；写入和隔离损坏材料仍由 `meeting-visual-store.ts` 负责，成功提交后才刷新纪要状态。会议详情读取证据时不再导入修改器。将刷新责任分给各个 UI 调用者会使同一份证据产生不同的历史状态，故保留在修改入口内。录制、翻译、消息校验及 #492 夹具均已迁移。会议相关 202 项通过，另以独占目录实际打包、启动 #492 服务。复审发现的夹具旧导入已修复并复核通过。

### 005 模块依赖防回归

两个 JS 应用共用一项 CI 检查。安装 Companion 的锁定依赖后，从根目录运行 `node scripts/architecture-dependencies.mjs`。静态导入或再导出形成环时命令返回 1。使用 `--json` 获取每个模块的解析依赖、边的种类及强连通分量。esbuild 移除仅供 TypeScript 使用的引用。原生链接、进程间消息与运行时计算的模块地址另行审查。

同一检查在基线上复现上表三个静态环，迁移后 891 个输入中静态环为零。加入 `require()` 和动态 `import()` 后有六组待核对：ACP 与 Windows 进程生命周期、Board 与运行时组合、应用类型与计算机策略、配置与日志及会议读取、上下文预算与交接、outbound MCP 配置。夹具覆盖自环、再导出、类型导入与延迟加载，另在临时目录加入实际双文件环验证退出码。

### 006 会议与配置文件的原子替换

`io.atomicWriteText` 负责写入、限次重试重命名、重命名失败时清理临时文件以及文件权限。`atomicWriteJSON` 在同一入口前执行 JSON 编码。会议创建时创建私有目录，之后的元数据、证据与 Markdown 都使用标准写入器。进程组回执及需要发布前强制修改权限的文件保留各自的持久性契约。会议、配置及 IO 隔离用例 320 项通过，独立复审另核对了 #732 的实际文件内容及权限。每个文件独立原子替换；跨文件的恢复仍由会议存储处理。

### 007 上下文交接与模型生成

`llm/context-handoff.ts` 定义持久化结构、清洗、格式及哈希输入。线程元数据读取与预算恢复直接使用该模块。`context-handoff-generator.ts` 在请求模型时组合已有预算和抽取服务。原来的运行时反向依赖已删除，图中含延后加载的循环组从六组降至五组。定向的 92 项上下文与线程进度用例通过。独立检查对照了迁移前后的 23 个声明，另在新进程验证读取元数据只加载数据模块。

### 008 模型目录与输出预算

`companion/src/llm/reasoning-effort.ts` 及 `chat-output-policy.ts` 是模型推理力度、目录和输出预算的编辑入口。在仓库根目录运行 `node companion/scripts/generate-model-policy.mjs` 可刷新扩展自带的两份派生代码；`--check` 在内容偏离时失败。保留两个 npm 工程现有的编译根目录、导出路径，以及直接读取浏览器源码的设置测试。独立扩展打包沿用仓库内已生成的文件，Companion 构建、测试与标准发布会检查同步。两个生产构建通过，23 项 Companion 用例与 12 项设置缓存控制通过。单独在仓库外目录验证了生成、漂移拒绝及混合 LF/CRLF 检出。

### 009 Windows 系统程序的路径

`process-path.ts` 持有 macOS 的 osascript 路径和 Windows 三个系统程序的绝对路径。ACP、Job 控制器、PTY 及 Mini 直接查询该模块，恢复、终止及原生命令的构造仍由各自的调用方负责。保持系统目录的环境变量优先级和已有 PATH 搜索规则。含 ACP/Job/PTY 的四模块循环消失，剩余四组含延后加载的环。204 项定向检查通过 193 项，其余 11 项按平台跳过。独立评审另执行了 #476 的七个源码 VM 用例。

### 010 本机 HTTP 文本接收

设置页和小窗分别对每个网络分块执行 UTF-8 解码。把「周会🎙」的首字拆在两个 Buffer 中时，旧入口都得到三个替代字符。`http-body.ts` 现在按字节执行原上限，并用同一个有状态解码器处理完整请求。出站 HTTP JSON 也使用这一接收器，空白体、解析错误及超限错误名继续由原协议决定；会议录制文件保持二进制流。通过 169 项 HTTP、设置、会议和出站协议测试。
