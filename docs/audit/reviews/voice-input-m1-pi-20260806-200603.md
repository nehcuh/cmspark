## Blocking issues

**1. Error banner is always clobbered — locked §6.6 error map is effectively dead** (`chrome-extension/src/sidepanel/voice/session-reducer.ts:170` + `:188-197`)

The engine always fires `onerror` followed by `onend` (Web Speech spec; Chrome conforms). `ENGINE_ERROR` sets `phase:"error"` with the correct banner, but the immediately-following `ENGINE_END` hits the empty-finals path (`isEmptyFinals` on the cleared `finals`) and replaces the banner with "未识别到内容". Verified empirically:

```
network err + end:      {phase:"idle", banner:"未识别到内容", committed:true}
not-allowed err + end:  {phase:"idle", banner:"未识别到内容", committed:true}
```

So users hitting a network failure get "未识别到内容", and — worse — the permission-denied guidance ("无法使用麦克风：请在 Chrome 站点设置与系统隐私中允许本扩展 / Chrome") that tells users *how to fix* mic access is never shown. The unit test `"not-allowed → error banner"` passes only because it stops at `ENGINE_ERROR` and omits the mandatory `ENGINE_END` — it asserts a state that never exists in the real flow. Missing test is a symptom of this bug, not the bug itself. Fix: in `ENGINE_END`, preserve the error banner when `state.errorCode` maps to a non-empty, non-`no-speech` error (or short-circuit when phase was `"error"`), and add an `error → end` sequence test.

**2. Permission bootstrap deviates from locked §7.1** (`chrome-extension/src/sidepanel/hooks/useVoiceInput.ts:152-161`)

SoT §7.1 step 3 locks: query mic permission; 非 `granted` → `chrome.tabs.create` the `voice-permission.html` bootstrap. The implementation only bootstraps on `st.state === "denied"`; for `"prompt"` (the normal first-run state — and exactly the side-panel "Permission dismissed 无弹窗" failure mode that M0.5 G9 was left PENDING human to gate) it calls `begin()` → `rec.start()` directly. If Chrome silently dismisses the prompt and fires no engine events: the 45s TIMEOUT fires → `stop()` → and if `onend` never arrives the session sticks in `"stopping"` — mic renders listening, `toggle()` and `USER_TOGGLE_STOP` are both no-ops (`stopping` excluded from both), so there is no UI exit except thread-switch/unmount. At best the user sees the misleading "已达单次听写上限" for a permission problem. Bootstrap should also trigger on `"prompt"`.
