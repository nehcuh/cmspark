I have now verified all five P0s against real sources, run both test suites, and hunted for lane misses. Summary of independent findings:

## P0 verification (evidence from real sources)

**P0 #1 — skill_install Trust — CONFIRMED, but the HIGH "no L2" framing is substantially overstated.**
- Real: `skill_install` absent from `L2_GATE_TOOLS` (`server.ts:783-797`), executor has no `security_token` (`server.ts:3244-3263`); `content` branch installs with zero path check/cap/audit (`skill-install.ts:114-127`); silent overwrite via `fs.rmSync(destDir,{recursive:true})` (`skill-engine.ts:849/978`) and unconditional `writeFileSync` (`skill-engine.ts:823`); `SKILL_INSTALL_CAPABILITY` claims "source path allowlist" which does not cover `content`.
- **Refuted as blocker:** the "first agent-callable permanent skill write / inverted trust monotonicity" claim is false — `record_experience` (`server.ts:2169, 3351-3390`) already provides an **ungated** agent-callable durable write into the same `skillsDir` via `createExperienceSkill` (`skill-engine.ts:1177+`), also loadable through ungated `use_skill` (`server.ts:3340-3349`, `loadContent` `skill-engine.ts:348-351`). The product's trust model already permits this write class; `path`/`zip_path` are actually *more* gated (Downloads/tmp allowlist) than `record_experience`. The genuinely new, defensible items are silent **destructive overwrite** (record_experience appends, never deletes), missing audit line, and no `content` cap — MEDIUM-HIGH, not a CRITICAL.

**P0 #2 — zip compressed-only budget — CONFIRMED (MEDIUM).** `MAX_ZIP_BYTES` on the on-disk zip only (`skill-install.ts:72,151-155`); `importSkillFolder` extract loop (`skill-engine.ts:857-886`) has zip-slip checks but no running uncompressed-total or entry-count budget.

**P0 #3 — zip `dest_path` honesty — CONFIRMED (MEDIUM).** Zip success returns `dest_path: root` with no `name` (`skill-install.ts:157-162`); engine actually writes `skillsDir/<safeName>`. Tests use a stub whose `importSkillFolder` throws "not implemented" and never assert `dest_path` (`skill-install.test.ts`).

**P0 #4 — config.test empty base_url — CONFIRMED (MEDIUM; lanes' HIGH is overstated).** `base_url: String(override?.base_url ?? config.llm.base_url)` (`message-router.ts:346`) — empty string wins. Side panel always forwards `base_url` (`SettingsSlideout.tsx:483,489-491` → `background/index.ts:576`); "Coding Plan 中继" preset sets `base_url: ""` (`SettingsSlideout.tsx:2052-2062`). Impact is a false "Base URL 未配置" on Test after preset click (probe rejects empty at `connection-test.ts:88-90`), not a security issue.

**P0 #5 — argv `FOO=1`/`~` — CONFIRMED (MEDIUM-HIGH functional regression, fail-closed).** `tryParseSimpleArgv` (`shell.ts:118-163`) rejects `$VAR`/globs but not `/^[A-Za-z_][A-Za-z0-9_]*=/` or unquoted `~`; POSIX `shouldUseArgvSpawn` returns true → `spawn("FOO=1", ...)` ENOENT, and `ls ~/x` passes literal `~`. Both previously worked under `shell:true`. Fail-closed (error, not injection); tests (`shell-progress-windowsHide.test.ts`) don't cover either form.
