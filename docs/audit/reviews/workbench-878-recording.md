# #878 工作台录屏验收

2026-11-21 在 Windows 和已安装的 Chrome 157.0.8103.79 上，用一次性浏览器配置加载本地 MV3 生产构建。选定的来源是仅显示测试时钟的浏览器标签页。浏览器测试参数按标题自动选择该页，录制使用真实的 `getDisplayMedia`、`MediaRecorder` 和 IndexedDB。录屏实现提交为 `1a0c8f77`。以下测量来自本地集成构建，尚未复验发行包。

| 操作 | 观察 |
| --- | --- |
| 以默认无声设置录屏，再切换今日、会议、录屏 | 返回后可继续停止同一录制，第二个工作台标签页显示占用并提供返回入口。 |
| 停止、预览、导出，并用独立标签页读取下载文件 | 导出的 WebM 为 35,388 字节。Chrome 从文件解码出 1280 × 720 视频，观测播放进度达到 0.2555 秒。刷新后录屏仍在，确认清除后 IndexedDB 记录数为零。 |
| 录制中收紧该测试扩展来源的 Chrome 存储配额 | 写入失败后自动停录，页面显示本机空间不足和已保存分块数。19 个连续分块、213,910 字节保留在本机。 |

同一生产组件在独立测试页面中还验证了以下路径。

- 关闭页面时 Chrome 触发 `beforeunload`。选择留下后继续收录。让录制页的 renderer 崩溃后，另一个页面找回 3 个已提交分块，共 35,105 字节，并在 Chrome 中实际播放至 0.2587 秒。该样本可播放，无法推及任意中断时刻。
- 关闭正在共享的测试来源标签页，浏览器轨道结束事件触发收尾，界面显示「共享来源已停止」。
- Chrome 的 `display-capture=()` 权限策略拒绝采集，界面显示未获授权，保存数为零。另一次在实际来源选择待定时点击测试页面的取消操作并关闭原文档，同样留下零条录屏。

四项 Node 回归覆盖同标签页共同持有麦克风与屏幕、默认排除音轨、写入顺序和尾块、配额失败与排队尾部丢弃、选源取消以及轨道结束。独立页面和扩展测试都运行于 headless Chrome。未人工选择系统桌面或实体音频设备，未在 macOS、Linux 上复验。
