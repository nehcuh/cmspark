# Windows 原生桌面操作验收

2026-11-25，Windows x64，系统 build 28000，Windows PowerShell 5.1，Node 22.23.4 x64。初始候选为 `58d993fc`。后续 `b90ef34a` 修正发布文案，Companion 代码与候选相同。下表标出原候选及后续修复的实测结果。测试使用自建 WinForms / WPF 窗口、一次性配置和合成内容。

| 场景 | 实际结果 | 证据范围 |
| --- | --- | --- |
| 登录桌面填写与提交 | 真实 `host_computer` 执行器将 `Pad42` 输入自有 WinForms，再按 Enter。工具将两个动作记为已投递，应用自己的提交计数为 1，提交值与输入框读回均为 `Pad42`。 | 使用真实窗口、前台、键盘输入、急停心跳和任务 token。该 token 由隔离测试创建。 |
| 输入中途停止 | 输入 80 字符的独立任务在目标收到首字符后，通过 WebSocket 停止。原候选两次将停止错误包装为 `TYPE_NO_EFFECT`。修复后返回 `TASK_ABORTED`，停止回执匹配 1 个任务，等待 1 秒后控件仍只有 `a`，提交次数 0，丢失焦点次数 0。 | 使用活动输入桌面。回归另覆盖首次错误、恢复焦点中和重试中收到停止；确认为无效果且仍获授权时保留有限重试。 |
| 后台 UIA 与捕获 | 自有 WPF 按钮通过 AutomationId 绑定。停止标记存在时 Invoke 终止，应用无变化；移除标记后，同一按钮读回 `Clicked OK`，目标自己写出业务回执。私有桌面从还原的窗口得到真实 560 × 400 PNG。 | 独立回读实际目标。键鼠任务在无法访问输入桌面时返回 `DESKTOP_DENIED`。 |
| 单帧图像授权 | Windows 真实 PrintWindow 捕获自有 720 × 390 窗口，本机 OCR 读出 `Synthetic review`。允许后，测试接收端收到 1 张 10,125 字节的 JPEG，其 SHA-256 与确认预览一致。拒绝、确认中撤权均为 0 张。 | 使用实际截图、预览和模型协议。该计数来自隔离的本机 HTTP 接收端。 |
| Windows x64 安装产物 | 候选 `08080a12` 的下载摘要与构建记录一致。ZIP 的 6,617 个发布文件与 Setup 中的同名文件逐一通过 SHA-256 核对。新版 `computer-capture.ps1` 与该提交的源码仅有 Windows 换行差异。包内 CLI 返回 `cmspark-agent v1.10.0`，桌面宿主、原生模块与 UIA DLL 均为 x64。31 个宿主脚本解析成功，Qwen 工作进程完成离线启动和关闭。 | 使用解包副本核验。公开发行资产摘要见[发行回执](../../release-status.md#1100-正式发布)。本轮未执行 Windows 原位覆盖安装。[精确候选构建](https://github.com/nehcuh/cmspark/actions/runs/45559226549/job/139018627111) |

在相同的生产适配器与执行器上注入可控的 Win32 部分投递回执，原候选输入 20 字符，前 16 字符重复了一次。修复后，失焦前已投递字符或 SendInput 已发出部分按键事件时，执行器保留原错误并终止该动作。独立子进程测试还复现了无回执异常退出后将 `pad` 重发成 `ppad` 的路径。输入进程在给出投递结果前超时或终止时，CMspark 现在报告结果未知并停止。宿主明确报告零投递的情形另有重试控制。

**多词 OCR 与 150% 缩放。** 自绘窗口的 OCR 已读出 `Review` 和 `sample` 两个词，原定位器丢失词间空格。修复词匹配后，还在旧式 DPI-unaware 窗口复现了第二个问题。该窗口的逻辑客户区为 700 × 270，物理客户区为 1050 × 405，原 PrintWindow 将逻辑大小的绘制结果放在物理位图的左上角。按图点击返回已投递，应用提交计数仍为零。按目标窗口实际 DPI 上下文渲染、再映射到完整物理位图后，相同目标在同一显示器上通过 OCR 定位并提交一次，错误操作为零。Win32 按线程上下文对部分窗口 API 做 DPI 虚拟化。[Microsoft 高 DPI 桌面开发说明](https://learn.microsoft.com/en-us/windows/win32/hidpi/high-dpi-desktop-application-development-on-windows)

**模型坐标契约。** 在同一个本机 Gemma 4 12B、相同的 JPEG、512 token 上限及严格解析器下，旧定位提示在四种不同布局上命中 0/4，新提示命中 4/4。对调提示次序复测两种布局，旧提示 0/2，新提示 2/2。缺失目标时两组均为 2/2 返回 `null`。共 16 次请求，首轮中位耗时分别为 2.02 秒和 3.64 秒。这里的命中以合成图中目标的真实像素范围计分；桌面任务另外核对应用动作。本次实验未放宽坐标解析。

配对测试使用独立 Chrome 配置、同版本扩展、一次性配对密钥及本机 LM Studio 的 Gemma 4 12B。已验证真实普通对话经签名配对、流式回传，并将包含任务标识的回复写入会话。开发机已有 1.9.1 实例运行，因此隔离副本使用了单独的端口与进程锁。设备报告 Windows Hello 不可用，首次授权的人工验证码流程未纳入自动化成绩。

### Windows 普通对话的四组对照

在 150% 缩放的登录桌面上，针对已授权的测试应用发起八次独立的普通侧栏对话。每种任务各运行一对。A、B 都先用 UIA 和 OCR 定位，B 在本机定位未命中时可向本机 32k 上下文的 Gemma 4 12B 发送单张目标窗口图。每次确认均在产品界面完成，成功以应用自行记录的操作结果判定。

| 任务 | A 原生 | B 原生加按需看图 | 确认数 A / B | 发图数 A / B |
| --- | --- | --- | --- | --- |
| 填写并提交 `CEDAR` | 成功，86.9 秒 | 成功，73.9 秒 | 1 / 1 | 0 / 0 |
| 点击无文字星形图标 | 125.1 秒内未完成 | 成功，66.9 秒 | 1 / 3 | 0 / 1 |
| 点击自绘双词按钮 | 成功，65.9 秒 | 成功，61.9 秒 | 1 / 1 | 0 / 0 |
| 布局变化后点击目标 | 125.2 秒内未发出桌面工具指令 | 成功，112.1 秒 | 0 / 1 | 0 / 0 |

A 完成 2/4，B 完成 4/4，应用记录的错点均为 0。唯一发图的是星形图标，三次确认分别用于任务、发图与落点。布局变化的 B 组由本机 OCR 完成。单台机器每种任务仅一对，无法据此估计总体成功率，或把未发图场景的差异归因于模型。[逐项 PR 回执](https://github.com/nehcuh/cmspark/pull/909#issuecomment-7154870852)

四组对照使用包含当时四项修复的隔离候选包。随后在 `08080a12` 构建的精确 ZIP 上单独复测 B 组表单，耗时 110.0 秒，任务确认 1 次，发图 0 张，应用记录成功提交 1 次、错误操作 0 次。此项单独计数。[精确候选构建](https://github.com/nehcuh/cmspark/actions/runs/45559226549/job/139018627111)
