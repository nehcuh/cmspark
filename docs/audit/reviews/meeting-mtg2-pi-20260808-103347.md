Verified empirically: `注意：…`, `他说：…`, `结论：…`, `备注：…` all parse to fake speakers (`{"speaker":"注意",…}`), while the numeric/time guard works. Since `silenceCutText` is now the **default** in `set_transcript` (paste + generate), `import_text`, and `apply_silence_cut`, these labels flow into the minutes LLM via `transcriptToText` (speaker → `"sp: text"`), contradicting the pack's own "仅当用户手标" rule. 2. **`meeting.updated` now overwrites the textarea** from server state on every update (`MeetingPanel.tsx` ~388) — new vs Mtg1; can clobber an in-progress user edit during live capture. Consider a dirty-guard.

4. **Mid-import failure UX**: after a segment error, `setImportStatus` still reports "音频导入完成" while `setError` shows the failure; partial import proceeds silently.
5. **Text import silently truncates** files >80KB (`text.slice(0, 80_000)` in `onImportTextFile`) with no user warning.
6. **Untested branches**: the `silence_cut:false` opt-out path and the numeric-time rejection in `parseSpeakerPrefix` have no test coverage despite existing guards.
