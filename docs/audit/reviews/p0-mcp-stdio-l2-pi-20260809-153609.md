## Blocking issues

**1. `mcp.update` `{enabled: true}` spawns a disabled stdio server with NO L2 confirm — bypasses the DoD-5 control and violates the declared fail-closed trust property.**
- `companion/src/message-router.ts:3535-3559` — `mcpStdioSpawnSurfaceChanged` compares transport/command/args/cwd/env only; `enabled` is not part of the surface.
- `companion/src/message-router.ts:1877-1880` — gate skipped for `patch = { enabled: true }` on a disabled stdio server; `replaceMcpServers` proceeds.
- `companion/src/mcp/manager.ts:127-132` — `applyConfig` then calls `startClient(...)` (process spawn) on the enabled toggle.
- `companion/src/message-router.ts:1902-1921` — the sibling `mcp.toggle_server` path *does* re-confirm, so the identical trust decision is enforced inconsistently; any authenticated peer can re-enable all disabled stdio servers with zero confirmation. Empirical check confirmed: surface-changed = `false` for an enabled-only patch. Trust monotonicity / "fail closed without requestConfirmation" is not upheld.

**2. Redaction breaks the edit-form round trip — real env/header secrets get overwritten with literal `***` in persisted config.**
- `companion/src/message-router.ts:3560-3581` — `redactMcpServersForBroadcast` masks env/headers to `"***"` in `mcp.list` / `mcp.servers.updated` / `mcp.server.status_changed`.
- `chrome-extension/src/sidepanel/hooks/useWebSocket.ts:1165, 1389` — feeds those redacted metas into `state.mcpServers`.
- `chrome-extension/src/sidepanel/components/McpServerForm.tsx:76-96` — edit form prefills env/header entries with the `"***"` values; `buildConfig` (lines ~154-160) drops only blank keys, so `***` is sent back.
- `companion/src/message-router.ts:1872` — shallow merge replaces `env`/`headers` wholesale. Result: merely opening the edit form and saving (e.g., a trust_level-only change, which per DoD 4 needs no re-confirm) corrupts the persisted config and the next spawn runs with `API_KEY=***`. This is a new regression from this PR (mcp.list previously returned raw values).
