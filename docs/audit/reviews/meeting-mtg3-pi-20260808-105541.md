### Nits (non-blocking)

1. **Silent default-speaker regression on audio import** — `MeetingPanel.tsx` import loop (~758–777). Pre-Mtg3, each STT line was appended via `appendLocalAndRemote(r.text, id)` → `meeting.append_transcript` carrying the default speaker. Now `appendLocalAndRemote(r.text, null)` (local preview only) is followed by a single `meeting.set_transcript` with **no speaker**, and `void sp` explicitly discards the default label. Users who set 默认说话人标签 and import audio (with auto-diarize off) now get unlabeled lines, while the field label still claims "录制/导入 STT 追加时使用". Easy fix: after `set_transcript`, send `bulk_speaker` when `defaultSpeaker` is set and auto-diarize is off (bulk preserves line count, so alignment is unaffected).

2. **Feature formula duplicated** in `chrome-extension/.../meeting-audio-import.ts` and `companion/.../auto-diarize.ts` — byte-identical today, but nothing enforces sync; a future edit to one silently degrades clustering.

3. **Manual labels are overwritten by both diarize modes** — `applyDiarizeToLines` replaces every speaker, and text_gap re-parses the textarea (stripping `姓名:` prefixes) before alternating. Design §4 claims manual labels "优先"; a transcript with partial manual labels loses them. Buttons are labeled clearly enough that this is a copy/expectation nit, not a bug.

4. **Minor race**: clicking 自动标说话人 immediately after import (before the `set_transcript` round-trip lands) can yield `features_mismatch`; harmless (surfaced as an error, retry works). The auto-after-import path is safe (same-socket ordering + 120 ms).

5. **Stale pack copy**: `pack.yaml` `ui.suitable_for` still says "暂不分说话人" despite Mtg3 now labeling.

6. **Test gap**: no tests for `features_mismatch` / `features_required` / `origin_denied` on `auto_diarize`, and no validator-level test.
