## Nits

1. **Pin 7 wording ambiguity:** “Origin 必须是精确 `http://127.0.0.1:<port>`（localhost / `[::1]` 对齐 hostOk）” has two readings — only-127.0.0.1, or all three loopback forms (parity with `hostOk`, summoner-web.ts:188-191). Since `--app` always navigates via 127.0.0.1, the strict reading is sufficient and safer; either is safe (all forms are loopback, unreachable by cross-origin attackers) and neither trips Rule 1. Implementer should pick strict and move on.
2. **NEVER “overlay Allow/Deny” vs SSE EVENT_ALLOW:** the NEVER clause and pin 10's mandated `SUMMONER_WEB_EVENT_ALLOW += thread.updated` can read as conflicting to a cautious implementer. They're different sets (dispatch/auth allow vs SSE event mirror); pin 10 + file map + DoD D5 resolve it. One disambiguating sentence in the spec would prevent a freeze.
3. **Post-D3 honest threat statement:** with cookie-on-`GET /`, any local process can fetch the cookie and forge `Origin` (it's just a header to curl) — the port becomes the secret against local processes. This is **not** a regression (argv leak publishes the token to local processes today, which is exactly D3's point), but the spec should record explicitly that overlay auth is an anti-*website* boundary, not an anti-local-process boundary, so nobody later treats the Origin check as an anti-curl control.
4. **Dual-write allowlist omits `chat.steered` / `chat.enqueued`** although the SSE list already carries both (summoner-web.ts:92-93): a watching face won't see *why* its run changed. `run_status`/`thread.updated` reconcile state, so cosmetic — fine to leave out of this batch.
5. **D1 must land as one commit:** removing `saveIndex` from `get()` without the singleton bind (or vice versa) leaves either the read-path disk write or the stale-snapshot clobber alive. The spec's single-D1-commit shape already enforces this; just don't split it during implementation.
