## Nits

### N1 (non-blocking) — StatusRail menu loses frosted transparency

StatusRail ⋯ popup `background` changed from `rgba(255, 255, 255, 0.96)` to `tokens.bgElevated` (`#ffffff`). The old value had a whisper of translucency consistent with the frosted rail aesthetic. The new opaque white is still consistent with MD3 elevated surfaces and matches all other menus, but is technically a contrast with the rail's frosted design language.

**Severity:** Visual-only; no correctness impact. The popup is a detached surface, not part of the rail itself, so full opacity is defensible.

### N2 (non-blocking) — surfaceChip accent tone change

The "Surface L0 聊" chip in ComposeDrawer changed from `bgMuted`/`textSecondary` (muted gray palette) to `accentSoft`/`accentText` (indigo palette). This shifts the chip from neutral chrome to brand-colored. Within P-G5 ("Accent as spark") this is a small decorated element, not a full-bleed header, so it remains in-bounds. Worth noting as intentional — reviewers should confirm it doesn't visually compete with the section list.

**Severity:** Visual-only; matches P-G5 spirit; no functional impact.

### N3 (non-blocking) — No hover state on section list items

The new borderless `sectionBtn` has `background: "transparent"` with `transition: background 150ms ease`, but no explicit `:hover` background rule in the style object. (If hover is handled via a CSS class or `onMouseEnter`/`onMouseLeave` not in this diff — or is deferred — that's fine, but worth noting for interactive polish.)

**Severity:** UX polish; users may expect a hover highlight on tappable rows inside an elevated card. Not blocking for this visual pass.
