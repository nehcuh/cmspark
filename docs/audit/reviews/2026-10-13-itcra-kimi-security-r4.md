  ## 2. Capability and threat-boundary assessment

  The feature adds a narrow, opt-in enterprise actuator path alongside — not inside — the existing personal/HITL gates. Threat boundary, as implemented:

  - **Authority is administrator-owned and never request-parsed.** Policy/instance identity is registered via local CLI only (`grant-cli.ts` `register-instance`), immutably binding `{instance_id, profile_id, subject}` (`enterprise-policy.ts:114-131`). `parseEnterprisePolicy` rejects unknown keys, ambiguous URLs (backslash, dot-segments, `%` in path, userinfo), non-ed25519 keys, expired policy, context profile, tool sets outside the seven constrained browser tools ∩ the grant's existing profile tools, and credential-class `type` targets. A rule with no attribute/text constraint is rejected.
  - **No new general capability.** Tools are a subset of existing profile tools; legacy invoke hard-fails enterprise-bound keys with `ENTERPRISE_SESSION_REQUIRED` (`companion-http.ts:512`); raw `__enterprise_guard` in any caller params is stripped unconditionally in `server.ts:473` before admission; the extension independently requires `guard.profile_id === enterpriseProfileId()` and guard `version === 1`. A JSON lookalike permit is worthless (`permits` WeakSet).
  - **Effect boundary is frozen and checked atomically.** Target identity is a per-document ISOLATED-world WeakMap token; the final effect runs in one JS tick re-verifying deadline, exact URL, visible login/ready markers, full target descriptor (token/tag/attributes/text/visibility/disabled) before `click()`/native setter. Identical replacement nodes, attribute mutation, same-URL reload, marker flip, and deadline expiry all fail pre-effect (confirmed both in unit tests and the native Chrome rehearsal).
  - **Human authority is separate, single-use, purpose-bound.** Approval (purpose `approval`, payload + `decision`) and QR presentation (purpose `login_view`, no decision/operation) are distinct challenges; each is bound to grant/subject/change/instance/profile/revision/policy digest/peer epoch/session/operation digest/nonce/expiry and verified by exact canonical-JSON equality plus ed25519. Presentation never approves; approval never captures images.
  - **Data boundary.** Durable state stores handles, states, and SHA-256 digests only; tests assert the state file contains no `https://`, secrets, selectors, or typed values. Login images return `audience: "human_only"`, no-store, no URL/title. Text evidence self-declares `coverage: "incomplete"`, `workbook_complete: false`; A12 is structurally unpassable (`workbook_export: false` hard-fails before driver dispatch).
  - **What the boundary does not cover (by design, documented):** administrator misclassification of a `read_only` rule's real site semantics (contract says this is a trust input, not auto-repaired); a local attacker who already controls the companion↔extension websocket (pre-existing system trust model); cancellation after dispatch (reported `outcome_unknown`, no rollback promise).

  ## 6. Findings

  No P0 or P1 source finding. No confirmed residual from S6/S7. Four low-severity nits (none waive-worthy, none blocking):

  - **N1 (P3, diagnostic):** `server.ts:473` — `if (enterprisePermit && !checkEnterprisePermit(...)) return { success:false, error:"PERMIT_INVALID" }` is effectively dead: `checkEnterprisePermit` *throws* `PERMIT_MISMATCH` for any branded mismatch and only returns `false` for non-branded objects the type excludes. Recheck failures (e.g. `TAB_LEASE_LOST`) likewise propagate as thrown `EnterpriseError` rather than a result envelope. Fail-closed and correctly mapped by the HTTP layer (403/409 fixed code); impact is only uniformity of error surfaces.
  - **N2 (P3, operability):** `enterprise-browser.ts:211-214` — the fixed error allowlist omits two *service-generated* codes, `TAB_HISTORY_CAPACITY` (~`:57`) and `FRAME_UNAVAILABLE` (~`:100-103`), and Chrome's "document no longer available" scripting error, collapsing all to `ENTERPRISE_BROWSER_UNAVAILABLE`. Fail-closed; operators lose specificity for capacity/frame races.
  - **N3 (P3, robustness):** `enterprise-service.ts` `loginSnapshot` — the presentation challenge is rotated *before* the `login_required` state check, so a validly signed proof presented after readiness consumes the challenge and then fails `LOGIN_VIEW_UNAVAILABLE`. Only the ITCra backend (grant + authority key) can trigger it; consequence is a forced QR refresh, i.e. self-DoS. Validating state before rotation would be cleaner.
  - **N4 (P3, disclosure hygiene):** all frames' URLs — including out-of-scope third-party frames that may carry ticket-like query strings — enter the in-memory snapshot, operation digests, and challenges. Bounded (≤128 frames, 64 KiB snapshot budget), never persisted, never in public operation evidence, so the written contract is not violated; but "no private URLs" is currently proven only for durable/public surfaces. Recommend one contract sentence stating frame URLs are service-process-internal.

  Behavior note (not a defect): `scoped()`/`canonicalURL` reject *any* `%`-encoding in the path portion, so legitimate in-scope URLs containing `%20` etc. fail closed at the extension. Administrators must configure decoded paths. Acceptable for v1; worth a contract line.
