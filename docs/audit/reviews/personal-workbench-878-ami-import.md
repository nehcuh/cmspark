# #878 实录导入、纪要与文本翻译验收

2026-11-21 在 Windows x64 的独立 Chromium 配置中打开未打包的 1.5.0 扩展。120 秒英语会议片段经工作台文件选择器、本机转写、手工保存和接收方确认，生成纪要并从「最近会议」重开。第一组使用 `large-v3-turbo` 与本机 0.6B 文本模型，暴露出开头漏词和纪要补写细节。复测使用可选的小型多语种 Whisper 和实际配置的文本服务，保留开头两个标注词和末句，并产出可逐条核对的中文纪要。

### 首尾与内容核对

- 人工标注中，片段的前两个词为 “Okay” 和 “Right”，在原录音 50.42 和 53.56 秒出现。转写从 “Well, this is the kick-off meeting for our project” 开始，漏掉这两个词及其后的语气词。文件包含这段范围，首句逐字目标未达到。
- 结尾保留 “and repeat that process”。讲话人 Craig 在自我介绍处被识别为 Greg，在随后点名处又识别为 Craig。纪要采用了 Greg。
- 纪要保留了设计原创、易用遥控器的目标。转写提到设计有三个阶段，但未列出名称。纪要自行写为设计、原型开发、测试与迭代，并添加确认截止日期的待办。这些结论需要对照原录音核实。
- 先前使用同一音频、同一模型和同一 UI 的运行，三段在 70.203 秒完成，产生中英文混合原文，末段仅一短句。该次旧编译件只把所选语言传给连续捕获，文件导入使用默认语言。旧 `stt-handlers.js` 的 SHA-256 为 `9dea46c6c4481ece4eec86b42bb9335707c6dd551881cdbd07f4641c0462d1b3`。上述正式数据来自重新编译后在全新会议目录的复测。
