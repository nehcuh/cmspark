## BLOCKING（必须修才能合）

### [P0] `scripts/release-guard.sh:70` — dirty 断言在 git 失败时**静默放行**（fail-open），与「默认 fail-closed」声明相反

```sh
70: DIRTY="$(git status --porcelain --untracked-files=no 2>/dev/null || true)"
```
`|| true` 把 git 的任何失败压成空串，`if [ -n "${DIRTY}" ]` 为假 → 走到 `:84 ok "工作树干净（tracked）"`，脚本可能 exit 0（第 1 条断言是唯一会因“查不出”而放行的）。

**实测反证**（导出 `71ff2ff9` 造 repo，故意 `M CHANGELOG.md`，再破坏 git）：
```
$ git status --porcelain --untracked-files=no
 M CHANGELOG.md
$ env GIT_DIR=/nonexistent CMSPARK_RELEASE_STRICT=1 CMSPARK_RELEASE_TAG=v0.6.10 bash scripts/release-guard.sh
  ok: 工作树干净（tracked）
  (tag 来源: CMSPARK_RELEASE_TAG)
  ok: HEAD tag == v0.6.10
  ok: [Unreleased] 段为空
[release-guard] 全部通过
rc=0
```
非 git 目录同样 rc=0。触发条件是真实存在的环境类问题：git 未安装/不在 PATH、源码 tarball 打包、容器/CI 常见的 `detected dubious ownership in repository`（`GIT_DIR` 破坏即同一路径）。此时守卫**声称干净**并放行带未提交改动的包 —— 正是 #547 要挡的东西。提交信息与脚本头都写「默认 fail-closed」，属 over-claiming。
（在飞 WT 版本已加 `git rev-parse --git-dir` 硬失败分支，但未提交、也未加测试。）

### [P1] `.github/workflows/release.yml:39-43`（+`:120-121`）— `workflow_dispatch` dry-run 被整体打死，且与文件自带文档冲突

strict + `CMSPARK_RELEASE_TAG: ${{ github.ref_name }}` 在 dispatch 时 `ref_name` 是分支名 → `release-guard.sh:109` 硬失败。实测（`71ff2ff9` 导出 + tag v0.6.10 模拟）：
```

strict + CI_TAG=main    → rc=1   （dispatch 第一步 preflight 即失败）
```
但 `release.yml:6-8` 仍写着「`workflow_dispatch` lets the matrix be dry-run on main WITHOUT creating a release — use it to verify the 3-platform build **before tagging**」，`release` job 也专门用 `if: startsWith(github.ref, 'refs/tags/v')` 为 dispatch 让路。本 PR 之后该能力归零（dispatch 必然 preflight 红），于是**打 tag 前无法再验证三平台构建**——与 #547 的“降低发布脱节风险”目标相反。脚本注释单方面宣布「这是期望行为」，却没有同步删 trigger/改注释，也没有任何测试覆盖 dispatch 路径（唯一相关断言是 `test-package-gates.sh:754-755`，断言的是**拒绝**）。属静默能力删除 + 文档自相矛盾。
在飞 WT 已引入 `CMSPARK_RELEASE_REF_TYPE`（并在 release.yml:48/128 传 `github.ref_type`）来区分 tag/branch —— 但**未提交**，因此对 cc48a924 无效。
