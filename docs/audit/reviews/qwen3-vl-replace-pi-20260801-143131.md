## Summary

The TinyClick→Qwen3-VL replacement is architecturally sound on the safety-critical surface: all six rejection gates (R1–R6) hold, the per-hit re-L2 human gate is airtight (including the refresh-path bypass closed), the settings belt is double-enforced, and the license door has been honestly rewritten for Qwen3-VL. However, the patch ships three material defects: (1) a guaranteed companion-daemon crash when python is missing at runtime (`spawn` ENOENT with no `error` handler, empirically reproduced), (2) the coordinate normalization heuristic is broken for pixel-space answers on any screen wider than 1000px (empirically reproduced — the dominant real-world case), and (3) the patch's own chrome-extension test suite is red (mirror-interlock test fails against the new copy), while the companion-side mirror copy was left stale and still brands the layer "TinyClick". Runtime/download/session modules have zero unit coverage, and the Qwen download path drops the old sha256 pinning and disk-budget enforcement.

## Runtime / Architecture

- **Crash on missing python (see Blocking #1).** `PythonLineTransport.ensureChild` has only `stdout`/`stderr`/`exit` listeners — no `child.on("error")`. `spawn` ENOENT emits an unhandled `error` event that throws and kills the Node process. Reproduced: `node spawn-test.js` with a nonexistent binary → `Unhandled 'error' event … Node.js v24.16.0, exit code 1`. Sequence: admission passes (files on disk, license ok) → `session.prepare()` → `runtime.prepare()` → `transport.load()` → `ensureChild()` → crash of the **whole companion daemon**, not a per-layer degrade. The download path handles missing python gracefully (`defaultRunPython` has `child.on("error")` → code 127), so the two paths disagree. [executed]
- **Worker crash respawn doesn't reload.** After `exit`, `child=null` but `QwenVlRuntime.prepared`/`status:"ready"` persist; a respawned worker answers `model-not-loaded` → faults++ → circuit after 3. Fail-closed but wasteful; no re-load path. Acceptable, noted.
- **Coordinate heuristic is broken for the common case (see Blocking #2).** Empirically, on 1280×720 the model's correct pixel answer (640,360) is re-mapped to (819,259); on 1920×1080, (900,600)→(1728,648); only coordinates with x>1000 pass through as pixels on wide screens, and 1024-wide screens are mis-scaled too. The prompt explicitly asks the model for "image pixel coordinates", so this misfires on virtually every real desktop screenshot. The human gate + annotated preview limit the safety damage (a human can see the crosshair is wrong), but "close enough" approvals can land on a *different* interactive element, and the layer is functionally broken for its main use case. [executed]
- Line protocol is otherwise sound: JSON-per-line with request ids, timeouts on load(600s)/infer(120s), pending map rejection on exit, best-effort dispose via `shutdown`+SIGTERM. Busy flag + sequential worker loop prevent protocol corruption; `infer-timeout`/`worker-exit` map to locator error → chain degrade.
- Worker Python syntax OK; lazy imports keep `ping` light; `trust_remote_code=True` on both processor and model load executes code from the downloaded repo (see Nits #4). [executed]

## Blocking

1. **Runtime crash when python is missing at inference time.** `PythonLineTransport.ensureChild` (`qwen-vl-runtime.ts`) lacks a `child.on("error")` handler; `spawn` ENOENT throws an unhandled `error` event that kills the entire companion process (reproduced with a spawn test, exit code 1). The "python-missing" state message exists only for the download path; the runtime path must catch spawn errors and fail closed per-layer (add an `error` listener → reject pending with `ModelRuntimeError("worker-spawn-failed", …)`, mirroring `defaultRunPython`'s code-127 handling).
2. **Coordinate heuristic mis-scales correct pixel answers on screens >1000px wide.** Reproduced: (640,360) on 1280×720 → (819,259); (900,600) on 1920×1080 → (1728,648). The worker prompt requests pixel coordinates, so this is the common path, not the edge. The 0–1000 heuristic cannot distinguish relative from absolute; at minimum the relative branch must be gated on evidence of relative output (e.g., model instructed to emit relative + explicit signal), and the parsing/normalization must be covered by tests (they are currently untested Python). This is the core feature of the PR.
3. **CI is red and the copy mirrors have diverged.** The patch edits `layerSemantics` ("当前任务结束后生效" removed) but leaves the "镜像互锁" test asserting the old phrase (reproduced failure) and leaves the companion mirror `MODEL_SWITCH_COPY` in `model-state-messages.ts` untouched — it still says `switchLabel: "实验层：TinyClick 本地视觉定位"` and `model-file-missing` still says "TinyClick 模型未下载或已被删除". Update the test and the companion mirror together.

## Nits

1. `executor.ts:1091` records the denial attempt with `layer: "tinyclick"` while the hit was logged as `"qwen-vl"` — audit-trail naming inconsistency (typechecks via the legacy alias, but confusing).
2. `resolveTinyClickAdmissionSafe` alias + `// WP5-I4 TinyClick admission` comment at `server.ts:3921-3924` — stale naming; fine for smoke scripts but the comment should say Qwen3-VL.
3. `QwenVlRuntime.resetCircuitBreaker` broadcasts `modelStatus: "absent"` when status is `idle` — inconsistent with `get_state`'s probe-based status.
4. `trust_remote_code=True` in the worker `_load` executes arbitrary repo code from a directory whose contents were downloaded with **no checksum verification** (no sha256 pin, unlike TinyClick's manifest+tokenizer verification). Pinned to Qwen repos only, but it's a supply-chain trust decision worth an explicit ADR-style note and a THIRD_PARTY_NOTICES update for the Qwen license terms actually governing the weights.
5. Dead `progress()` callback in `qwen-vl-worker.py` (never passed to `snapshot_download`) plus wrong units (file count vs bytes) — either wire it to a real per-file heartbeat with byte totals or delete it and state "no progress" honestly.
6. `modelDiskBudgetMB` is now decorative (see Product honesty) — either enforce it in `downloadQwenVlVariant` or remove it from config/docs to avoid the false sense of control.
7. `probeQwenModelDir` treats "config.json present" as `ready`; consider probing for at least one safetensors/pytorch weight file to avoid the partial-snapshot false ready state.
8. `qwen-vl-session.prepare()` probes with the default dir while loading from `deps.modelDir` — harmless in production (deps.modelDir unset) but a latent test seam inconsistency.
9. `modelMirror` → `HF_ENDPOINT` reuse is a silent semantic change for legacy configs; a loud log on reuse would be prudent.
