# #826 协调裁决：新增CPU测试按标准构建→运行验证分离

当前head0666fc8d。新增Windows CPU驱动的编译门在fc4a2546、64dbdaaf、0666fc8d三次有目的实际CI中失败；native VM同源控制可通过。已证原来新测试耦合工具链发现、构建和业务于30秒case，内设20秒编译；未证MSVC/link/vctip物理原因，file-pipe实验仅证明一类可达机制，不能充当当前根因。

负责人root选择结构性重想：编译纳入已有testFixtures构建，以当前源/产物身份交接到明确后置Windows消费者；全部原runtime/same-wire/UNKNOWN/BigInt/live-fd断言必须真实执行，两个Windows lane均不可缺失，Mac/Linux原控制保持。不继续猜flags、重复SLIM或无变化rerun。

这确实将Windows新增CPU编译接受上限从20秒移至已有checked构建120秒，并使原30秒case成为不含编译的runtime测量；旧端到端总界限不保持。MCP20秒、每exe6秒、CPU运行30秒和全部原业务/权限/清理不改。编译失败仍必须阻断构建/发布；产物缺失/源已变/错误平台/摘要不符直接拒绝，不用存在性或现场重编译回退放行。
