  ## Findings

  **P1 — lock release has an A-B-A unlink race** — `enterprise-state.ts:25-28`
  The release does `closeSync(fd); unlinkSync(lock)` unconditionally. If an operator removes a "confirmed stale" lock while the old writer is still exiting (the docs at `docs/itcra-enterprise-capacity-recovery.md` explicitly instruct manual lock removal after verifying writers stopped — verification is human and fallible), and a new writer acquires a freshly created lock file, the old writer's `unlinkSync` deletes the *new owner's* lock file. A third writer can then acquire, and two writers both believe they hold exclusive ownership — silently breaking the core invariant this change exists to provide. Fix: only unlink when the path still refers to the same inode (`fs.statSync(lock).ino === fs.fstatSync(fd).ino`). Same pattern exists in the pre-existing `mutateGrants` finally (`outbound-grants.ts`, not changed in this diff — worth the same guard). Normal-path exclusion is solid and tested; this only manifests on the operator-recovery path, so I rate it P1 rather than blocking.

  **P2 — inconsistent error surface for malformed session/op entries** — `enterprise-state.ts:34-37`
  `identifier(session.handle)` / `identifier(op.session)` throw outside the `try`/`deny("STATE_CORRUPT")` wrapper, so a structurally-malformed entry surfaces as whatever `identifier` throws rather than `STATE_CORRUPT`. Still fails closed, state preserved, CLI exits 1 — cosmetic inconsistency only.

  **P2 — rotate's 2 MiB cap can reject a legitimately full store** — `enterprise-state.ts:27`
  1024 operations with large request keys/digests could plausibly approach 2 MiB; such a store would be denied rotation as `STATE_CORRUPT` despite being valid. Fail-closed with a manual-recovery escape hatch, so low impact, but the cap is on byte length rather than structural validity.

  **P2 — cross-process test depends on runtime TS loading** — `companion/tests/enterprise-service.test.ts` (spawn test)
  The child runs `node -e require(<resolved .ts path>)`; that only works if the runtime can `require()` TypeScript (Node ≥ 23.6 strip-types or a dist mirror). Machine card shows 35/35 on host and linux_arm64, so the environment supports it — but the test is coupled to the Node version in a way the rest of the suite may not be. A compiled-dist variant would be more robust.
