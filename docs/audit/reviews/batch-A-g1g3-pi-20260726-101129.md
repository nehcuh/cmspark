## Non-Blocking Nits

1. **`executor.ts` ~1267 — TYPE_NO_EFFECT counter reset on recovery:** When the re-focus retry succeeds, `typeNoEffectCounts.set(typeKey, 0)` resets the counter. This means the same text can cycle through multiple retry events across a long task (each requiring a fresh failure → reset → failure again). The `priorFails >= 2` guard still caps each failure event at 2 attempts, so infinite storms are prevented. But this slightly exceeds a literal "1 retry total per text" reading of Q5=B. Practical risk is negligible since each cycle requires a real type failure — not a strict deviation.

2. **`executor.ts` ~1297 — dead `else` branch in TYPE_NO_EFFECT handler:** The `else` (when `priorFails !== 0`, i.e. `=== 1`) is unreachable in normal operation — `priorFails` is only transiently 1 inside the same catch block before the retry. The `priorFails >= 2` guard at the top catches the re-entry path. This dead code is harmless but misleading for future maintainers.

3. **`server.ts` ~2468 — `posted_steps`/`verified_steps` note for non-injective-only tasks:** A task consisting entirely of `wait`/`screenshot`/`describe` actions will have `posted_steps === 0` and `verified_steps === 0`, so the note "Some inject steps posted events but were not semantically verified" won't fire (0 < 0 is false). But a mixed task where some inject steps lack verification triggers the note correctly. No false positive for pure-read tasks. Fine as-is.
