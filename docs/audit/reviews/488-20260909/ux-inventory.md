## 入口完整性

窄屏从顶栏“导航”进入工作区；宽屏左栏常驻。以下“资料与工具”均为同一个可展开 summary；资源面板纵向滚动并保留输入区。能力模式的 primary + overflow 覆盖注册表全集，没有因聊天模式关闭 MCP、知识、会议等能力。

## 确认缺陷

### P1：会议“结束并收起”丢弃未识别末段（既有缺陷）

`ContextPanelHost.tsx:293` closePanel 立即卸载；`MeetingPanel.tsx:603` cleanup 先发 meeting.end 后 destroyAdapter。`local-stt-adapter.ts:1166` destroy 设置 dead/aborted、取消 PCM 和 STT session，未产生最终结果。内层结束收起按钮 `MeetingPanel.tsx:1223` 直接 finalizeCapture 也在 :403 销毁 adapter，同样绕过正常 `stopLiveCapture:798 → adapter.stop → onResult → onEnd → finalizeCapture`。录制末段尚在 capture/infer 时点任一收起即可触发。源代码证据确定；尚未声称真实用户录音复现。修复需让所有用户导航/关闭等候现有正常停止链，并有处理状态、失败保留、有限等待；单改文案不充分。

### P2：装配入口把全局管理表述成只作用于本对话

`composer/meta-slash.ts:composeAttachLine` 给所有项目套用“挂到当前线程 · Surface Lx”，`ComposeDrawer.tsx:SectionRowButton` 每行重复。实际 `McpPanel.tsx` 有全局开关、服务器启停/删除；SkillsPanel 导入/删除全局技能，不是一次本对话挂载。重现：打开装配 → MCP/技能，前后所暗示作用域不同。建议入口描述“配置资源，并选择本对话使用方式”，在面板局部分开“全局管理 / 本对话使用”，保留所有操作，不改权限。MCP 面板已有“全局 MCP”标识，故不把它上升为越权安全漏洞。

## 体验与审美建议（不冒充行为回归）

- 默认小牛标识是 `ui/icons.tsx:212 CompanionMark` 硬编码 SVG，仅 size 参数；StatusRail、ChatView 空态、WorkspaceFrame 直接使用，没有用户头像开关。与既有连接火花应用/托盘品牌不一致，可统一默认标识，无个性化数据需要删除。
- 新对话用户无法从导航直接发现“编程接力”，输入 / 或先生成消息才出现入口。建议资料与工具新增清晰的“代码与终端”入口，复用现有面板，不把外部 Agent 变成必需条件，不移除原 /code 与消息接力。
- 装配页重复英文名、Surface L0 聊、每行挂载说明，占用窄屏；320×480 实测第一屏只能看见技能、知识及场景开头。保留所有行，中文任务名称作主层，作用域说明放页首/对应控件附近。
- 技能工具栏没有 flex-wrap；320px 实测五个按钮被挤成宽 38–60px、高 58px 的多行字。没有横向溢出或入口丢失，故这是视觉/点击质量问题，不报隐藏功能。推荐工具栏换行且按钮保持完整短标签；24px 模式键/收起键也低于根设计的32px目标。
- 宽屏知识/技能等仍是高度受限的底部面板（与输入/正文非同阅读宽度），适合临时引用，完整管理空间偏小。需要后续有真实接受标准的资源管理布局，不能通过删掉安装/图谱/导入等功能来制造整洁。
- 最近搜索标题 vs 对话管理标签全文搜索、历史面板其实是操作历史，存在同词歧义。保留两个数据面，标签写清“最近对话 / 操作记录”并解释搜索范围。

本报告不宣称完成整体 UI 改版；图谱/会议/复杂配置的真实数据可用性仍需后续专项验收。主代理负责对话批量选择、删除与完整管理布局复审。
