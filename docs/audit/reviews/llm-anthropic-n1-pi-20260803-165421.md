## Blocking issue

**Trailing-dot FQDN bypasses L7** — headers.ts:108-116 (`hostnameFromBaseUrl` → `new URL(...).hostname`) and headers.ts:92-102 (`isAnthropicFirstPartyHost`).

`new URL("https://api.anthropic.com./v1").hostname` returns `"api.anthropic.com."` (trailing dot preserved). DNS-wise `api.anthropic.com.` is the **identical official host**. Neither the exact match, `.anthropic.com` suffix, nor `.claude.ai` checks fire. Empirically verified:

```
isAnthropicFirstPartyHost("api.anthropic.com.") → false
assertHeaderPolicy({baseUrl:"https://api.anthropic.com./v1", client_header_profile:"claude_code_compat"}) → ALLOWED
```

So `buildRequestHeaders` will emit `user-agent: claude-cli/2.1.220 (external, cli)` + `x-app: cli` to the real Anthropic API — exactly the L7 red-line scenario the design forbids ("官方 Anthropic 主机不允许 Coding Plan 兼容头…拒发请求", red line "C 永不做"). This is a one-character host spelling away from the guardrail the whole node exists to enforce, and the design's denylist is specified as "至少" (minimum). Fix is trivial: strip a single trailing dot (`.replace(/\.$/, "")`) in `hostnameFromBaseUrl` or `isAnthropicFirstPartyHost`, plus a regression test for `https://api.anthropic.com./v1`.
