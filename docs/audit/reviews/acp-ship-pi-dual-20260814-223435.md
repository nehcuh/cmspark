## Issues

**blocker**
1. **R1 applyable dead contract — still broken.** `manager.ts:133` emits `pending_diffs` (no `applyable`) on `acp.session.event`; `lifecycle.ts:542` adds `applyable` only on `acp.handback.message`; reducer (`agentStore.tsx:953`) requires `applyable===true`. finishSession calls handbackSink **before** emitProgress (`manager.ts:444→452`), so the closed event lands last and flips `hasPendingDiff` true→false. Empirically simulated: after both events `hasPendingDiff=false` → no Apply button in Panel (`CodingAgentPanel.tsx` `session.hasPendingDiff` gate) or Chip (`CodingSessionChip.tsx:21`), and the chip's 12s auto-dismiss proceeds (diff unapplied, CTA gone). Fix: add `applyable` to manager's emitted `pending_diffs` or derive it locally in the reducer; add a regression test (none exists for this flow today).

**bug**
2. **CLI Stop frames truncated output as "完成".** `manager.ts:698` close handler → `finishSession(..., code=null)` → `partial = partial || (code!==0 && code!=null)` = **false** on SIGTERM-cancel → chat inject says 「完成」 with truncated body. This is the Stop-honesty cluster's own scope; a cancelled bridge must be 「部分输出/已停止」.
3. **ACP Stop shows error "killed".** `cancel()` sets `session.error="cancelled"`, then `client.kill()` rejects the pending prompt → start() catch (`manager.ts:544`) overwrites to `"killed"` → user pressed Stop, UI reports "killed". Prefer keeping "cancelled".
4. **emitProgress 800ms throttle is dead code — new unthrottled WS path.** Every call site passes `force=true`; the residual's `onChunk` change (`manager.ts:680`) removed the last throttled emission. Per stdout/stderr chunk the WS now carries ≤12 KB tail **plus** the full 80-item timeline (items ≤2 KB detail ⇒ worst-case ~160 KB/event) at chunk rate — WS/React flood risk on fast agents. Throttle to ~250 ms, force only on close/error.
5. **R3 pending banner still lies at edges.** `manager.ts:101-107` falls back to `"pending"` from snapshot whenever `local_terminal` unset — so "正在打开本机终端…" shows in `offered` state (pre-L2) and after cancel. 6. **R11 panel close doesn't clear `pendingStartAfterPickRef`.** `CodingAgentPanel.tsx:342-346` (falling branch) clears timers/`starting` but not the ref (only threadId change clears it, line 342).
