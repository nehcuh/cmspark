## Blocking issues

**B1 — `skill_install` is dead on arrival; Track 3 DoD fails.**
The tool is injected into the LLM catalog (`companion/src/bridge/tool-definitions-inject.ts:16-18`) and a handler exists (`companion/src/server.ts:3243`), but `COMPANION_TOOLS` (`server.ts:2161-2187`) does **not** include `"skill_install"`, and `executeCompanionTool` is only reached from `COMPANION_TOOLS.includes(toolName)` (`server.ts:2190`). The call falls through to the extension dispatch (`server.ts:2278`), where `chrome-extension/src/background/browser-bridge.ts:139` returns `{ success: false, error: "Unknown tool: skill_install" }` — the extension has no handler (grep confirms none). Net: every LLM `skill_install` call errors, while the new hint strings (`downloads-find.ts:209`, `_browser_download_tool_snippet.ts:65`) actively steer agents into the broken tool. No test exercises the server routing path, so the unreachable branch is invisible to the green suites.

**B2 — Ungated arbitrary local-file read primitive (trust monotonicity; ADR-020 checklist #4), which B1's fix must not ship without gating.**
Once routed, the `path` branch (`skill-install.ts:107-137`) realpaths and imports **any** local `.md` file with no scope restriction, and the directory branch (`:138-152`) copies all files under any directory containing a `SKILL.md`. The LLM can then read the imported content back through the ungated `use_skill` tool (`server.ts:3339`), which returns `skill.content` to the agent. The equivalent Surface read (`host_read`) is L2-gated; this chains two ungated tools into an ungated `.md` exfil/read path. Additionally, the zip branch (`:79-105`) caps input at 25 MB but `importSkillFolder` (`skill-engine.ts:824-893`) has no decompressed-size cap — zip-bomb disk fill. Needs L2/confirm gating or a read-scope restriction + decompressed cap before wiring.

**B3 — Missing ADR-020 capability declaration while adding a tool + primary UI (blocking per dual-review instructions).**
The implementer prompt (`docs/audit/reviews/s40-quad-m1-dual-prompt.md`) and AFK plan contain no Surface/Compose/Autonomy/Trust/Channel declaration. This diff adds a new LLM tool (`skill_install`, Composition/skill) and new primary Side Panel chrome (FocusBand `thread_tools` primary slot, `focus-band-priority.ts:63-96`). Per the checklist: "blocking when tools/gates/primary UI are added." Declare before PR claim.
