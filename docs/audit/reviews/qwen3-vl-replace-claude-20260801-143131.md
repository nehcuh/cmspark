## Summary

The patch cleanly swaps TinyClick (Florence-2 ONNX) for Qwen3-VL Instruct on the L2 experimental locate slot, with safety gates intact: every VLM hit still goes through re-L2 human confirmation (`executor.ts:1082-1087`), all `computer.model.*` mutators retain the dual source belt (`validateWsMessage` + handler-level `SETTINGS_SOURCE_TYPES`), and the license door text now describes Qwen3-VL with a recalculated `LICENSE_DOOR_TEXT_HASH`. All six rejection gates (R1–R6) hold under live inspection and the new + adjusted unit suites pass. The most material concerns are an under-discriminating coordinate-normalization heuristic in `qwen-vl-worker.py`, a non-functional progress callback, a deleted disk-budget enforcement, and large coverage reductions in `computer-model-handlers.test.ts` / `computer-model-admission.test.ts`.

## Runtime / Architecture

- **Python worker protocol safety** — `[inspected]` `qwen-vl-worker.py` reads JSON-per-line, wraps every cmd in try/except, replies with `{id, ok, error, trace}`. No `eval`, no `os.system`, no `subprocess` — only `transformers` / `PIL` / `torch` calls against `model_dir` (locally downloaded) and `image_path` (capturer-provided). `qwen-vl-runtime.ts:67-181` `PythonLineTransport` uses a single long-lived child with seq-based pending map; on child exit it rejects all pending with `worker-exit` and clears `this.child` so the next request respawns (`ensureChild`). Recovery: a respawned child has no model loaded, so the next infer returns `model-not-loaded` → counts as a fault → circuit opens after 3 (`qwen-vl-runtime.ts:264-275`). Same self-recovery story as TinyClick.
- **Process lifecycle** — load (600s timeout) / infer (120s) / shutdown (5s) + SIGTERM are wired with per-request timers that reject on timeout and clear `pending` (`qwen-vl-runtime.ts:121-141`). `dispose()` sets `prepared=false; status="idle"` BEFORE awaiting `transport.dispose()`, so even a hanging Python shutdown can't keep the runtime "ready". No SIGKILL escalation — minor robustness gap if SIGTERM is blocked.
- **Coordinate heuristic correctness risk** — `[inspected]` `qwen-vl-worker.py:65-81` `_normalize` collapses to one branch via deeply redundant nested tautologies (each `if x ≤ 1000 and y ≤ 1000 …` re-checks already-established facts). Effective behavior: **if `coords ∈ [0,1000]²` AND `width > 1000`, always rescale as `x/1000 * width`**. Trace for a 1920×1080 screen with model returning pixel `(800, 400)`: outer guard `(800>1920 || 400>1080 || 1920>1000)` = TRUE → all subsequent guards are tautologies → returns `(1536, 432)` — wrong by ~700 px. The prompt explicitly instructs the model to emit pixel coordinates, but Qwen3-VL grounding training data is heavily biased to 0–1000 normalized boxes; whichever the model actually emits, this heuristic will be wrong for one of the two cases on common screen sizes. Human-gate contains the harm (the caption says "可能完全错误"), but this is a real correctness risk that warrants either a deterministic prompt-side ask ("reply with 0-1000 normalized") or a more discriminating heuristic (e.g., only rescale when `max(x,y) > some_width_threshold AND width > 1000`).
- **macOS admission wiring** — `[inspected]` `server.ts:3858-3876` replaces the hard `null` with an inline `resolveModelAdmissionSafe` call sharing `computerModelSession` and `execOpts?.broadcast`. The `stillEnabled` dep is fresh `getConfig().computer?.modelEnabled === true`. Windows path (`server.ts:3922-3932`) uses the legacy alias `resolveTinyClickAdmissionSafe` which now resolves to the same function. ✓ no dual wiring.
- **Inference concurrency** — `qwen-vl-runtime.ts:254-256` rejects concurrent infer with `qwen-vl-busy`; the locator folds that into `skipped`. ✓ matches ADR-020 "single-thread task; no multi-worker".
- **Stale holder fast-path** — `model-admission.ts:67-76` returns a fresh `QwenVlLocator` over the existing session without re-checking `stillEnabled`. Same as TinyClick. Disable/delete disposes+nulls the holder, so the bypass window is closed in practice.

- **Download progress honesty** — `[inspected]` `qwen-vl-download.ts:91-107` defines a `progress(n, total)` Python helper but **never passes it to `snapshot_download`**. The enum lists `"disk-full"` but no path produces it. Either enforce `fs.statfs` pre-flight (preferred) or remove the dead enum entry.

## Nits

1. `qwen-vl-worker.py:65-81` `_normalize` — collapse the tautological nested ifs into one readable predicate and add a discriminator (e.g., rescale only when `width > 1000 AND max(x,y) <= 1000 AND x*y != 0`); also consider pinning the prompt format to either pixel or normalized so the heuristic has a stable contract. Correctness risk on common 1366/1920/2560-wide screens is real.
2. `qwen-vl-download.ts:91-107` — wire `progress` into `snapshot_download` (e.g., `etag_timeout` heartbeat or `max_workers=1` + `file_size` listener) OR remove the `onProgress` plumbing + the UI percentage for Qwen downloads. Currently a UI dead-feature.
3. `qwen-vl-download.ts` — re-introduce `cfg.modelDiskBudgetMB` pre-flight (`fs.statfs` on the target dir) and emit the `disk-full` reason; otherwise drop the dead enum entry. 16 GB 8B variant on a thin disk will silently fail into `download-failed` with a misleading message.
4. `executor.ts:1091` — change `layer: "tinyclick"` to `layer: "qwen-vl"` so the denied-suggestion attempt aligns with the rest of the chain narrative (the `LocateLayer` union already permits it).
5. `model-admission.ts:20` `SESSION_FOREIGN` is in `ADMISSION_REASON` but never returned (the `sessionMeta` WeakMap mechanism was deleted with the tokenizer-pairing invariant). Either delete the enum entry or document it as a stable contract for future re-introduction.
6. `computer-model-admission.test.ts` — re-add at minimum: (a) concurrent first-build single-flight, (b) per-task close→reopen rebuild, (c) second-call-no-rebuild. `computer-model-handlers.test.ts` — re-add: (a) download↔delete mutex both directions, (b) delete-fail → DELETE_FAILED, (c) set_enabled three-arm (license_required / LICENSE_DECLINED / biometric-approved-then-disabled). These were the regression backstops for the I4-对抗 fixes.
7. `qwen-vl-runtime.ts:170-180` `dispose` — consider escalating to `SIGKILL` after a short grace if `SIGTERM` doesn't take effect within ~2 s; otherwise a wedged worker can leak the Python process while the runtime reports `idle`.
8. `qwen-vl-download.ts:100` `local_dir_use_symlinks=False` is deprecated in current `huggingface_hub` (≥0.23 renamed). Either pin a compatible version in user-facing copy or drop the flag.
9. `model-license.ts:97-125` — consider naming the upstream license family (Apache-2.0 vs Qwen license) explicitly per variant rather than "请以 HF 页面最新 LICENSE 为准"; the license door is the natural place to set expectations.
10. `QwenVlLocator` lacks a tiny unit test for the `TOO_LONG` / `FRAME_TOO_WIDE` / `ModelRuntimeError→skipped` branches (only `EMPTY` is covered). The new locator test file is the right home.
