## Issues

**bug — companion/src/acp/manager.ts:828-860 (cancel) + :438 (finishSession)**
Stop injects a **"完成" (complete) handback**. `cancel()` kills the CLI-bridge child; the `close` handler calls `finishSession(..., code=null)`; `partial: session.partial || (code !== 0 && code != null)` → `null != null` is false → partial stays false → the chat receives `【编程接力 · claude · review_readonly】完成` with a truncated transcript. This is the *default* transport for most agents (Claude/Gemini/Pi/Codex fall back to CLI bridge when ACP handshake fails), and it is doubly dishonest in Mode C: the terminal agent is still running the task after the bridge stops, yet the thread says "完成". Fix: set `session.partial = true` in `cancel()` before killing (the timeout path already does exactly this), and optionally emit a mode-C-specific handback note ("监视已停止；本机终端 Agent 可能仍在运行").

**bug — docs/coding-handoff-user-guide.md:94**
Doc lies: "未安装时会回退到 Terminal.app" (falls back to Terminal.app when not installed). Code explicitly refuses: `openDarwinWithPref` throws `terminal app "X" not found` → L0 degrade also throws → `{ok:false}` with paste hint and an error timeline item. The code is the honest behavior; the doc must be corrected to "shows an error and offers a paste command" — not silent fallback (a silent fallback would be the actual Ghostty-vs-Terminal lie the review was hunting for).

**bug — docs/coding-handoff-user-guide.md:4,58,186**
Broken relative links: `decisions/acp-dual-open-terminal-mode-c-2026-08-14.md` and `decisions/acp-shell-direction-dual-synthesis-2026-08-14.md` exist neither in this worktree nor in git at 41a442c, and the PR does not add them (they're untracked on main's disk only). Shipping a doc whose decision-SoT links 404 in the repo.

**bug — chrome-extension CodingAgentPanel.tsx:749, CodingSessionChip.tsx:35, CodingSessionShell.tsx:36**
Stop label lies in the `failed` state. `modeCLikely/modeCMonitorStop` is true whenever the *snapshot* is true (`openLocalTerminal === true`), so after `localTerminal === "failed"` the button still reads "停止监视会话" with title "仅结束侧栏监视桥；本机 Terminal 内 Agent 需在终端自行退出" — but no terminal agent exists to exit. The banner correctly handles `failed`; the button does not. The predicate should exclude `failed` (i.e., only `opened / opened_l0 / pending` — when failed, the bridge is the only process and "停止编程会话" is accurate).

**bug — companion/src/acp/manager.ts maybeOpenLocalTerminal + cancel**
Race: if the user clicks Stop while `localTerminal === "pending"`, `cancel()` does not abort `openLocalTerminalForAgent` (fire-and-forget promise). The host terminal + interactive agent can spawn *after* the stop, and the `.then` then mutates the closed session's timeline/emit. Stop should mark a cancelled flag checked before/after the open resolves, or abort the pending open.

**suggestion — companion/src/acp/handlers.ts:161 + CodingAgentPanel.tsx:424,800**
`agent_cwd_is_workspace: true` is hardcoded and the context bar labels git status "Agent 工作目录 git 状态（spawn cwd = workspace）". Re-picking the workspace while a session is live (更换 button stays enabled) changes `effectiveWorkspace`, but the running session keeps its old `session.workspace_root` as cwd — the label becomes false. Either disable 更换 while `live`, or compare against `session.workspaceRoot` before claiming agent-cwd parity.

**suggestion — companion/src/acp/manager.ts (timeline label) + open-local-terminal.ts (open-args-e)**
Ghostty/Alacritty/Kitty L1 claims are unverified. `open -na App --args -e bash -lc …` exiting 0 does not prove the command ran (the app may open a blank window; behavior is version-dependent), yet the timeline says "已打开本机终端（Ghostty · 交互）". Terminal/iTerm (osascript `do script`/`write text`) are reliable; open-args-e terminals are not. Consider wording L1 for `open-args-e` as "已打开（如未自动运行请粘贴命令）" or verify via a marker echo.

**suggestion — companion/src/acp/open-local-terminal.ts (prompt file)**
`cmspark-mode-c-*.md` (full page context + goal) is written to tmpdir and never unlinked. L0's paste line needs it to survive, but the L1 path could unlink after a successful open; at minimum note the leak.

**suggestion — chrome-extension CodingHandoffSettingsSection.tsx (path input)**
The custom-path input is uncontrolled (`defaultValue`), so after saving a custom path, switching the select to a preset leaves the stale custom text in the field; and a metachar-containing pref is silently normalized to "auto" by the companion with no user feedback (the select then snaps to 系统自动 with no explanation).

**nit — companion/src/acp/manager.ts (L0 label)**

**nit — CodingAgentPanel.tsx (git status freshness)**
