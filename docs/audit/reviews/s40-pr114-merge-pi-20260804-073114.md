## Nits
1. **companion/src/capability/shell.ts:201-210** (M1c nit 1, still open) — POSIX argv mode mis-handles `FOO=1 cmd` env-prefix and `~/path` args (verified live: `["FOO=1","ls"]` → ENOENT where `sh -c` succeeded). Doc comment at :168 overclaims. Consider rejecting `=`-prefixed/`~`-word first tokens; mention argv mode in the shell_exec tool description.
2. **companion/src/skills/skill-install.ts:152-155** (M1c nit 2) — zip_path caps compressed size only; no decompressed budget → a small zip can expand unbounded into the skills root. Apply `assertDirBudget` post-extraction.
3. **companion/src/skills/skill-install.ts:48-70** (M1c nit 3) — `downloads`/`下载` *segment* match is looser than "user Downloads"; combined with `use_skill` it's an ungated .md read chain. Bind to homedir/Downloads or Chrome default.
4. **companion/src/skills/skill-install.ts:123** (M1c nit 4) — content-branch `dest_path` falls back to `root` when file absent — misleading.
5. **companion/tests/skill-install.test.ts** (M1c nit 5) — zip_path branch never exercised (stub throws); add zip allowlist-rejection + size-cap coverage.
6. **chrome-extension/src/background/downloads-find.ts:185** (M1c nit 6) — `Math.max(limit, 20)` is constant 20; conflict scan covers only first 20 matches while query fetches 50/100. Harmless but misleading.
7. **companion/src/server.ts:3244** (M1c nit 7) — `skill_install` (writes disk + reads Downloads) has no L2 gate; bounded surface consistent with `use_skill`/`record_experience`, but confirm intent.
8. **New** — broad-search fallback returns `search_mode`/`count` but the tool description only mentions `conflict_hint_zh`; agents have no hint that `search_mode:"broad"` means regex-miss fallback. Minor doc gap.
