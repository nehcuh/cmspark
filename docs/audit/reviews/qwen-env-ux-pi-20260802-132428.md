## Nits (non-blocking)

1. **Dead config knob**: `pythonPreferUv` (`config.ts:147`, writable via `setComputerModelFields`) and `resolvePythonRuntime`'s `preferUv` param (`python-runtime.ts:141`) are never read — uv is unconditionally preferred; the advertised opt-out doesn't exist.
2. **Dead code**: `findPython()` in `qwen-vl-preflight.ts:124` is unused (preflight resolves via `resolvePythonRuntime`).
3. **安装缺失依赖 over-installs**: the settings button sends no packages, so the isolated branch auto-runs `ensureIsolatedPythonEnv` with the full default set (incl. multi-GB `torch`) even when only one hub package is missing — safe (allowlisted) and settings-gated, but heavier than preflight's precise per-missing-package commands, and executed without a size confirmation.
4. **修复/更新 label over-claims**: `ensureIsolatedPythonEnv` creates-if-missing + installs, but cannot repair a partially-broken venv (`uv venv` will just fail) — the "修复" path only works when the env is missing or healthy.
5. **`qwenModelDir` legacy heuristic** (`qwen-vl-download.ts`): a user-chosen root that happens to contain a child dir literally named `models` would place weights at `root/models/qwen3-vl-*` while the UI advertises `root` — edge-case location mismatch, no security impact.
6. **Capability declaration not inline** in this batch prompt — present in the master plan and verified in the r4 review; this batch adds no new tool/gate family beyond the reviewed scope.
