## Nits

1. **A3-3 enforcement point is ambiguous.** Pin 9 puts lease-thread binding in `message-router.ts`, but the natural chokepoint `applySummonerPayloadPolicy` (`summoner-acl.ts:133-150`) already validates `pack.apply` thread_id presence and lives in a file whose file-map row says "not in this batch / don't touch ALLOW". One sentence in the spec saying the binding lands in the router (or explicitly permitting a non-ALLOW edit to the payload policy) would prevent an implementer from reading the file map as "hands off summoner-acl.ts entirely."
2. **A2 owner-stamp mechanism unnamed.** Today `message-router.ts:563` stamps `llmLoopOwnerPanel` only `if (session?.panelId)`. Whether the overlay/summoner dispatch path carries a panelId — or needs a synthetic overlay owner stamp at chat.create — is the one real design decision inside A2. DoD A2-4 forces it to be gotten right, but naming the stamp site in the spec would save a false start.
3. **A1 residual:** pin 2 leaves `style-src 'unsafe-inline'` in place under the DOM-links branch. Acceptable at T3 (no script execution), but the spec could say so explicitly to preempt a future "why is unsafe-inline still here" revert.
