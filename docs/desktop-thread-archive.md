# 原生工作台：永久归档与恢复

此功能属于 **0.6.14 开发源码**，不会自动更新当前安装程序。它使用原生工作台的“对话”页；HTML Capture 卡和旧 Web／侧栏的列表语义不变。使用前分别核对 Companion、原生 host 和扩展的实际版本，发行状态见 [版本与交付状态](release-status.md)。

在普通对话行选择“归档”，先读取当前状态，再明确点击归档按钮。只有能核实对话空闲、当前连接及状态仍有效时才保存；忙碌或无法核实活动状态时不会写入。归档不发送消息、不停止正在运行的任务，也不授予新的目录或执行权限。

“已归档”视图可以按标题查询，或输入完整对话 ID 精确查找；列表最多显示64条，重名和超出首屏的对话可通过精确 ID 定位。打开一行仍能查看同一对话历史。选择“恢复”同样先核对状态，再明确保存；恢复后回到普通列表。

归档只修改同一 canonical 索引里的归档状态及更新时间，不复制或迁移消息与附件。它没有按归档年龄自动删除的规则，空对话自动清理也不会删除已归档项。归档不是备份：用户后续明确删除、移入回收站以及既有消息保留策略仍然有效；30天回收站规则不变。归档后进入回收站的对话，从回收站恢复时仍保留归档状态。

页面、目标、查询、文档或连接变化会使待保存状态失效。若保存后连接中断，界面不会猜测回滚或自动重试；重新读取当前状态确认结果。旧 Web、侧栏搜索和打开对话仍包含已归档的非回收站项；此批不增加 Web 归档写入口。

普通列表和标题搜索保留旧索引的读取兼容性：没有归档字段的重复行或旧时间格式不会阻断浏览，也不会在读取时修复索引。归档与恢复仍要求无歧义的当前状态；损坏或无法核实的归档标记不会被猜成有效状态。

桌面能力协议为v7，精确新增 `desktop.archive.list/state/set`；不兼容的旧原生 host 不能冒充已支持。两平台的真实键盘、历史、恢复和丢失保存回执验收必须与具体提交绑定，纯 Node／Linux 受控成功不能替代原生结果。[#476](https://github.com/nehcuh/cmspark/issues/476) 的工作区、本机 Agent 和 Chrome 等余项不会因归档组件通过而自动完成。
