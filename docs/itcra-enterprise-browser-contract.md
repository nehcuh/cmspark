Issue [#618](https://github.com/nehcuh/cmspark/issues/618), [ADR-029](adr/029-itcra-enterprise-browser-authority.md), source handoff v1.1 SHA256 `52010d7a4ba59134e33263b271040e10a762157b177b3073185b4f78adb068b7`. The opt-in source implementation was merged in PR #626; real enterprise acceptance remains incomplete under #618. The historical installed 0.6.13 build and the existing ITCra four-tool adapter are not evidence of this contract. See [release status](release-status.md); a source merge does not update installed software. Discover `contract_version:1`; a version string or successful health response alone is insufficient.

## Deployment and authority

Use one dedicated Companion process/data directory/port and Chrome user-data profile for each authenticated user or explicitly shared business identity. Never pair a personal browser with an enterprise process. Exactly one authenticated Chrome-extension peer is permitted; reconnect changes peer epoch and invalidates old sessions. ITCra maps its authenticated user to a subject-specific grant and instance; never accept subject/grant/endpoint mappings from Agent output. Pairing secret, grant token and human private signing key are separate credentials.

The extension generates `enterprise_profile_id` in local storage during ordinary BrowserBridge startup, before any enterprise grant. Cold service-worker restart retains it; a storage error fails closed and may retry. A local administrator reads it in the dedicated extension service-worker console (`await chrome.storage.local.get('enterprise_profile_id')`), then registers it:

```sh
CMSPARK_DATA_DIR=/private/enterprise/user-a cmspark-agent outbound-grant register-instance --profile-id ACTUAL_UUID --subject user-a
CMSPARK_DATA_DIR=/private/enterprise/user-a cmspark-agent outbound-grant issue --caller-id itcra-user-a --profile outbound_l1_interact --enterprise-config /private/policy.json
```

Create the restricted directory first. Registration is idempotent for the same profile and subject and refuses replacement. Its exclusive `enterprise-instance.json.lock` covers the fresh read through atomic commit; contention returns INSTANCE_BUSY without modifying registration or existing grants. A failed write returns INSTANCE_UNWRITABLE. A crashed writer requires offline administrator recovery after quiescing writers; never remove its lock automatically by age or PID. Cleanup checks lock identity and cannot unlink a successor's lock. Profile identifiers retain the existing identifier contract for compatibility; registration does not newly impose strict UUID formatting. Policy `instance_id/profile_id` must match its output. The grant token prints once; save it in a 0600 file. Policies have finite expiry no later than their grant, fixed subject/revision, precise origin/path boundaries and an Ed25519 SPKI PEM public key. No private signing key belongs in Companion or worker containers. Revoke with existing `outbound-grant revoke --grant-id ...`. Policy changes invalidate existing sessions, including during waits and before output.

Policy schema is strict; unknown keys are errors. `tools` narrows existing profile tools: create_tab, navigate, get_page_text, screenshot, click, type, scroll. `navigation`, `evidence`, `login` contain `{origin,path}`; `/app` matches `/app` and `/app/...`, not `/application`. v1 rejects every percent sign in the URL portion before query/fragment, including benign percent-encoded request paths, as well as traversal, backslashes and URL credentials. Decoding only a policy path does not make encoded request URLs supported. Queries do not widen scopes and are not recorded. Login and business scopes may share an origin: marker checks, not origin membership, determine readiness.

`ready/login_markers` contain visible CSS `selector` and optional exact `text`. A qualified site administrator must verify the markers represent authenticated business readiness and QR login. `actions` contain fixed id, click/type tool, read_only/write effect, selector and target `{tag,attributes,text?}`. Allowed exact target attributes: type, name, role, aria-label, data-action, href. At least one attribute/text constraint is mandatory. `type` only permits text/search inputs and rejects actual password/OTP/token/login/username fields. Optional max_length is 1–4096. A rule's declared read-only effect must be verified against the actual site; a wrong administrator classification is not automatically repaired by an LLM.

## REST and envelopes

All endpoints below use `Authorization: Bearer cmg_...`, grant-only. Prefix `/outbound-mcp/v1/enterprise`. JSON POST bodies are bounded at 64 KiB and reject unknown fields. Every response sets `Cache-Control: no-store`, including business data and errors. Success `{ok:true,data:...}`; failure `{ok:false,error_code:"HOST_LITERAL"}`. The legacy `/invoke` rejects enterprise keys with `ENTERPRISE_SESSION_REQUIRED`. Ordinary keys retain their original HITL behavior. A nonbranded runtime permit is refused with PERMIT_INVALID; a branded but mismatched/consumed permit fails its binding check. Neither outcome dispatches or downgrades to personal authority.

| Method/path | Input | Result |
| --- | --- | --- |
| GET /capabilities?subject=... | bound subject | contract_version, fixed identity/revision, tool subset, login/approval/restart/export support |
| POST /sessions | subject, change_id, request_key, url | 202; opaque session_handle and current state; no raw tab number/URL/title |
| GET /sessions/:handle?subject=... | exact bound subject | state, identity, expiry; presentation_challenge only while login_required |
| POST /sessions/:handle/login-snapshot | subject, presentation_proof | image_base64/size, human_only audience, no URL/title |
| POST /operations | subject, session_handle, request_key, tool, args | operation_handle, state, effect; immutable challenge/review for dangerous ready target |
| GET /operations/:handle?subject=... | exact subject | state/error, challenge or completed data; data_not_retained after restart |
| POST /operations/:handle/execute | subject, human_proof? | 202, durable execute request; no Agent approval boolean |
| POST /operations/:handle/cancel | subject | cancelled before dispatch; outcome_unknown if dispatch already claimed |

Operation args: navigate `{url}`; click `{rule_id}`; type `{rule_id,text}`; scroll `{delta}` nonzero integer ±2000; text/screenshot `{}`. No selector, coordinates, tab ID, script or policy supplied by the caller. Separate rule IDs for “next sheet” and “delete” route the same tool to different authorization states.

Reuse a request_key only for the exact same session/tool/arguments. A mismatch returns IDEMPOTENCY_CONFLICT. Repeating a completed normal execute returns its result without another effect. Retrying a consumed human proof is rejected, even before the asynchronous effect completes. Unknown dispatched results must be inspected by an operator; opening a new key is not a safe automatic retry strategy.

## Human channels

Ed25519 signs UTF-8 canonical JSON: object keys sorted lexicographically, compact JSON strings, arrays preserve order. Payloads here contain only strings and no floating-point numbers. Encode the 64-byte signature as unpadded base64url (86 characters). Proof is `{payload,signature}`. Use the canonical challenge returned by Companion, not a reconstructed Agent summary.

Approval challenge binds purpose=approval, grant_id, subject, change_id, instance_id, profile_id, revision, policy_digest, peer_epoch, session, operation, operation_digest, nonce, expires_at. Sign exactly `{...challenge,decision:"approve"}` or decision=deny. TTL ≤120 seconds and session expiry. `operation_digest` binds immutable parameters and the actual target/document/full navigation internally. ITCra's authenticated human backend fetches operation status directly, renders its review parameters and a verified rule label, checks user/RBAC/change permissions, then signs after a real popup decision. Signing is never an MCP/model tool. Cross-purpose, tampered, expired, replayed and cross-grant proofs fail before a new effect.

Login presentation signs the session's exact purpose=login_view challenge, without decision/operation fields. It is single-use before capture. Obtain the next challenge from session status. Do not expose presentation proof, login image or QR/tickets to Agent tools, evidence stores, access logs or screenshots in test artifacts. ITCra human endpoint requires independent authentication and matching subject/RBAC; execution grant possession alone cannot mint presentation authority. Send the returned image directly to the human-only UI with no-store, no analytics/body logging. Handle QR expiry by fetching a fresh challenge/image. The proof is also consumed when capture fails or readiness changes before capture; an old proof cannot capture a later relogin image. Fetch a new challenge rather than retrying the consumed proof.

## State, SSO and coverage

Open is asynchronous; poll until ready/login_required/blocked/unsupported. Prepare has no business effect. In login_required, prepare/execute preserve a pending task. A two-second monitor rechecks the same session and resumes a requested normal operation after verified readiness. For dangerous tasks that become ready, it generates the target-bound human challenge and waits; login does not authorize the action. Completed stages never replay. ITCra saves opaque operation handles in its review checkpoint and attaches the new result to the original task.

v1 supports configured main-frame redirects and same-origin QR markers. Login iframe/popup returns unsupported; never substitute a public-page login demo for enterprise acceptance. Unknown readiness markers do not produce ready. Web text omits login and out-of-scope frames; provenance declares source=visible_dom, coverage=incomplete, frames_read/total and workbook_complete=false. Canvas/virtualized sheets and original workbook completeness are not promised. Business screenshots require all observed frames in evidence scope. Non-active screenshot uses owned-tab CDP; fallback failure is explicit rather than another active tab's pixels. Document ID, frame set, full URL and navigation generation are checked around capture; changed evidence is discarded. Frame URLs are process-private snapshot/digest inputs carried between the trusted extension and Companion, not durable state or public status/review fields; public human review includes only the canonical site origin/path.

State file `enterprise-browser-state.json` is 0600. It stores bindings, claims, keys and digests, not images/text/private URLs/typed values/selectors. Limits: 128 sessions, 1024 operations per store; capacity rejects new work rather than evicting live keys. Session lifetime ≤8h and policy/grant expiry. Stop/restart explicitly terminates pending work/approvals; executing work becomes outcome_unknown. Completed metadata remains, plaintext is not retained. Corrupt/unwritable state fails closed. A normal completed 202 or ended polling response does not cancel accepted work; incomplete execute response cancels before dispatch where possible. Cancellation after dispatch cannot undo site effects. Reconnect requires a new session and deliberate recovery, never replay of old approval.

Errors include GRANT_UNAVAILABLE, SUBJECT_MISMATCH, ENTERPRISE_BINDING_INVALID, SESSION_AUTHORITY_CHANGED, ENTERPRISE_PEER_CHANGED/AMBIGUOUS, ENTERPRISE_BRIDGE_INCOMPATIBLE, NAVIGATION_FORBIDDEN/CHANGED, SITE_OR_TARGET_UNSUPPORTED, CREDENTIAL_FIELD_FORBIDDEN, EVIDENCE_FORBIDDEN, SCREENSHOT_SCOPE_INCOMPLETE/UNAVAILABLE, HUMAN_PROOF_INVALID, APPROVAL_ALREADY_CONSUMED/EXPIRED/TARGET_CHANGED, IDEMPOTENCY_CONFLICT, TAB_LEASE_LOST, SESSION_TERMINATED, CAPACITY, STATE_CORRUPT/UNWRITABLE. Internally generated owned-tab history overflow and missing/oversized frame metadata return TAB_HISTORY_CAPACITY and FRAME_UNAVAILABLE. Only module-private diagnostic errors expose those codes; raw Chrome/page exceptions, even with the same message, remain ENTERPRISE_BROWSER_UNAVAILABLE. Registration contention/write errors are INSTANCE_BUSY/UNWRITABLE. Failure never requests a desktop approval as fallback.

## ITCra integration and joint acceptance

Update ITCra app/cmspark_http.py, mcp_runtime.py, main.py and capabilities.js: authenticated subject→dedicated instance/grant mapping; opaque checkpoints; waiting-login human-only display; independent RBAC popup signer; cancellation and result-unknown handling. Worker SDK [examples/itcra-enterprise-client.py](../examples/itcra-enterprise-client.py) intentionally has no approval/presentation signing method. ITCra directory is currently not a Git checkout; its UI/RBAC changes remain owned by ITCra, not silently edited as part of this source patch.

Bundle matching Companion/extension artifacts and their hashes, Node22 runtime and all npm dependencies in advance using existing offline installers/build pipelines. No new startup download or external service dependency is introduced. Ship a separate identity data directory and ports in deployment manifests; do not reuse deployment-wide shared tokens/profiles. This source patch is not evidence of a released/offline-installed matching build.

Joint runner: `node scripts/itcra-browser-acceptance.mjs --itcra-url http://127.0.0.1:8080 --cmspark-url http://127.0.0.1:23401 --phase p0 --case all --report artifacts/itcra-browser-acceptance/report.json`. Supply `ITCRA_ACCEPTANCE_CREDENTIALS_FILE` (0600 JSON: subject, grant_file, itcra_driver_token_file; token files also 0600). No tokens on CLI. ITCra must provide authenticated POST `/api/cmspark/acceptance/run-case` instrumenting actual UI/site checks; it is a new test-driver requirement, absent from the current adapter. Driver returns case/run_id/status/evidence_kind=real_enterprise, explicit checks, sanitized evidence hashes and measured observations. Real SSO/UI/effects are required; missing driver, failed/skipped/missing cases or synthetic evidence make the whole phase fail. Single-case runs cannot claim a complete phase. A12 original-file hash/all-sheet-row coverage additionally required for phase=all; v1 workbook_export=false keeps it missing, not passed.

P0 required A1–A11,A13–A24. Individual case IDs and A16–A24 names from the handoff are accepted. Report stores metadata only. Isolated machine fixtures/test results remain classified simulated; they are not joint enterprise evidence. On 2026-10-14 the user explicitly authorized code integration after independent reviews and green CI, with real-system joint acceptance afterward. T4 enterprise-readiness claims still require human review and actual joint bake-off; no live grant/config/application replacement is performed by the code merge.

The joint driver must also provide authenticated GET `/api/cmspark/acceptance/evidence/:artifact_id`. Each listed evidence item has kind, artifact_id and SHA256 of canonical JSON receipt `{schema_version:1,run_id,case,kind,measurements}`. Measurements contain only whitelisted nonnegative integer counters/boolean observations (see runner INVARIANTS), matching the case response. No images, URLs, page text, tokens or arbitrary strings are accepted. The runner retrieves, validates and stores these receipts next to the report; hashes alone cannot pass. The driver and human reviewers remain responsible for the actual observation provenance, not simply labelling mock counters real.

Receipts must collectively back **every** case-required observation, including prompt/SSO/replay/effect counters. Appropriate trace/UI/effect/offline/workbook receipt kinds are mandatory; validated measurements remain in the final report. Missing receipt measurements fail the case even when the driver's assertions say passed. Capability workbook_export=false or absent hard-fails A12 before driver dispatch.

Target snapshots carry an ISOLATED-world private WeakMap node identity. Identical replacement nodes invalidate approval. Actual click/type/scroll synchronously recheck visible readiness/login markers and a finite dispatch deadline before effect. Serialized guard deadline ≤30 seconds/session expiry/approval expiry. A pre-effect READINESS_CHANGED on a normal operation returns to login waiting; dangerous approval is not reused. Monitor scheduling coalesces each operation, preventing slow browser responses/repeated execute requests from building duplicate queues. Navigation may recover an authorized navigation/login source with unknown markers; it does not require evidence export rights and returns no page data.

SSO waiting retains the requested business target only in process memory per operation. If a supported login callback lands on another allowed page, the service restores the original target at most once using an explicitly granted navigate tool; repeated wrong returns fail AUTH_RETURN_TARGET_MISMATCH. It never substitutes another document's text for the requested link. Restart retains no private destination and terminates the pending operation.

User-supplied enterprise SSO entry: `https://sso.cmschina.com.cn/login.aspx` (2026-10-13). Candidate login scope is origin `https://sso.cmschina.com.cn`, path `/login.aspx`; this is configuration input, not evidence of verified QR markers, redirect/iframe/popup coverage or a real login pass. Do not infer readiness from this origin alone.

[Policy template](examples/itcra-enterprise-policy.json) deliberately contains invalid replacement markers. Substitute actual registered IDs, finite expiry/public key, exact business/login boundaries and verified selectors; it cannot be issued unchanged.

Instance registration binds an immutable business `subject` as well as the dedicated profile UUID. Issue and live use reject a different subject; old registrations missing subject fail closed and require administrator migration to a fresh isolated instance. Multiple authorized ITCra humans sharing an explicitly shared business account map to this same subject through ITCra RBAC. Distinct personal subjects require separate registered profiles/instances. This topology does not prove the site’s actual SSO principal; real identity qualification remains a joint acceptance gate.

Continuation freezes the operation’s verified business URL. The extension keeps bounded process-private navigation history for owned tabs, accepting configured navigation paths outside login scopes or a verified ready document. This retains a clicked business destination through a subsequent main-frame SSO redirect; callback URLs do not replace a waiting operation’s frozen destination. Recovery inspects authentication before matching pending targets, restores at most once under explicit navigate authority, and requires a fresh target-bound human challenge for dangerous tasks. Neither the history nor operation URLs are persisted or returned in public operation evidence.

Local unauthenticated entry probe (2026-10-13): initial headless/headed HTTP/HTTPS loads returned ERR_EMPTY_RESPONSE. After the user requested a retry, fresh headed Chrome reached `https://sso.cmschina.com.cn/login.aspx` from both home entry schemes, status200, main-frame navigation. No visible iframe was present. A separate fresh headless inspection confirmed unique visible `#qrcode`, `#btnLogin` and `#loginBody`, plus one exact visible “扫码登录” label. These are observed login-marker candidates, not a verified authenticated ready marker. No QR pixels, image sources, credential values, page body or query/ticket URLs were captured. Actual human login, principal isolation and post-login continuation remain unverified.

Grant mutation consistency: authentication writes best-effort usage timestamps to private `outbound-grant-usage/<hash>.json` only; public grant listing overlays them for compatibility. It never rewrites authority JSON. Supported issue/revoke/revoke-all CLI mutations take an exclusive `outbound-grants.json.lock` before fresh load through atomic commit. Contention returns GRANT_STORE_BUSY; no successful revoke is reported on contention. After a writer crash, stop/quiesce all writers and verify committed state before an administrator removes that exact stale lock and retries. Never delete locks automatically by age, and never edit the grant JSON concurrently outside this protocol; policy changes use revoke/new issuance or an offline quiesced migration. Usage telemetry loss cannot restore authority.

Same-origin overlap limit: a changed URL in both navigation/login scopes cannot reuse an older ready destination when no trusted explicit navigation intent or verified current target exists. Internal business_target_unavailable clears stale destination; prepare returns RETURN_TARGET_NOT_RETAINED with no business evidence. Known explicit open/navigate targets survive a login redirect; verified same-URL modal login at a previously ready B or an explicit trusted business intent preserves continuity. This does not promise restoration for every cross-route login under overlapping paths. A new ambiguous A→B route requiring login before ready qualification needs an explicit trusted target/site adapter, rather than a guessed restoration to A.
