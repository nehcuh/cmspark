# 自研 Computer Use 与主模型视觉验收计划

GitHub: [#908](https://github.com/nehcuh/cmspark/issues/908) · 代码基线 [76be8dc1 / PR #907](https://github.com/nehcuh/cmspark/pull/907) · 2026-11-25

交付目标是在 macOS 和 Windows 上，用户只安装 CMspark，就能从普通对话打开白名单应用、填写、核对并停止。CMspark 自己执行桌面动作。配置的主模型负责理解任务，支持图像输入和工具调用时可以辅助看窗口。先取得原生基线，再验证图像是否值得发送，最后退出外部桌面后端。

## 1. 在 Mac 上量出原生基线

- 本机为 Apple Silicon、macOS 26.6.2。已安装的 1.8.0 为 ad-hoc 签名，标识为 `com.cmspark.agent`。本机钥匙串报告 0 个有效代码签名身份。#907 基于 `47306be4`，已产出候选 DMG。记录安装包提交、应用与扩展版本，让两端组件匹配。比较此次授权修复时使用父分支基线 `47306be4` 与 `76be8dc1`，将 1.8.0 用户的升级体验另记。
- 在可恢复的独立 Mac 测试会话中，从相同的干净用户和安装状态分别启动基线、候选包。经已安装 App、扩展和普通主对话进入，先只启动托盘，再首次使用桌面能力。记录哪个进程、哪个步骤触发辅助功能、屏幕录制及实际出现的其他系统提示。另计产品的全局启用、逐应用授权、任务确认。
- 让主对话打开已列入白名单的自有表单，读取标签，填写本轮标记，由目标应用自身回读内容。随后发起含等待和第二次测试输入的任务，在等待中按停止，核对停止回执、目标事件和最终内容。这样能发现停止后仍到达的输入。另测同会话重复读取、换应用、撤权、重连。报告每个场景的成功数/尝试数、各层点击数、首错和用时。
- 正式升级另用同一发行团队 Developer ID 签名的旧版和新版。核主 App 与实际宿主身份、签名要求及固定安装路径，旧版人工授权并跑通后原位覆盖，重新启动并逐项复测。单列首次从 ad-hoc 切换到 Developer ID 的结果。可用发行签名机产出两份包，这台 Mac 负责交互记录；等待签名期间继续 ad-hoc 功能验收。已安装用户的隐私授权应予保留。[Apple 签名要求](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)

## 2. 先走通一次主模型真正看图的原生任务

现有通用截图分析可复用当前对话模型，其消费者为 `screenshot` 和 `analyze_image`。原生 `host_computer` 的截图步骤将预览发往面板并密封证据，`describe` 才返回 OCR 文字。LCU 已有把工具观察图短暂送入模型上下文的实现，可提取其中与后端无关的图片传输和清理逻辑。[截图选模](../../../companion/src/llm/likely-multimodal.ts) · [主对话消费端](../../../companion/src/llm/adapter.ts) · [原生执行器](../../../companion/src/computer/executor.ts) · [原 LCU 图片消费（基线）](https://github.com/nehcuh/cmspark/blob/76be8dc1/companion/src/computer/lcu/result.ts)

- 标准控件沿用 AX / UIA，文字沿用本机 OCR。首个视觉任务选用自有窗口中位置可变的无文字图标，让目标应用记录实际选中的图标。仅在用户允许当前模型端点处理桌面图片、当前对话允许视觉且所选模型支持图片与工具调用时发送。换端点或撤权后重新核对同意。缺少条件、图像调用失败时，返回可用的结构化观察或明确指出需要人工选择。
- 只送经遮罩的目标窗口，保留窗口身份、帧、裁剪尺寸及坐标比例，屏蔽既有限制的敏感界面、浏览器单次授权画面和不可用的捕获。按单次工具观察传输，不把图像字节写入聊天历史或日志。对发往远程的像素明确展示接收方。确认台的审批预览只供人查看。
- 模型可以给出控件或候选位置。宿主转换 Retina / Windows 缩放坐标，复核目标和当前帧，按既有输入确认、预算、撤权与停止规则执行。观察到界面变化后重新定位。以脱敏自有图片和变化布局验证所配端点实际消费了图像、模型选择能改变预期控件、应用能独立验证结果；停止或撤权后丢弃迟到的建议。

## 3. 用对照决定何时发图

同一模型和端点、同一版本、权限、动作预算与初始窗口，A 组只给原生结构与 OCR，B 组额外允许主模型看目标窗口。分别测标准表单、无文字图标、自绘控件、操作后布局改变。使用同一批布局和填写值，交替 A/B 次序，逐次恢复初始状态。第一轮每类做 5 对以发现明确差异；样本不足时报告完成数和失败实例。

按任务类型比较独立回读成功数/尝试数、错点、人工介入、每次完成用时、图像用量与成本。拒绝与急停有各自的预期结果。对停止后输入、错窗输入、未经同意发图逐例核对。简单任务走结构化路径；视觉能稳定补上的类型才纳入按需看图。Windows 登录桌面复用同一任务及评分，补测不同 DPI，分别给出两端结果。

## 4. 从产品退出外部桌面运行时

- 优先结束旧 LCU 会话并释放桌面占用，移除桌面设置、对话启用项、`lcu_js` / `lcu_js_reset` 注册与服务端调度、发现/兼容探测、旧授权读写和说明。已安装用户的旧开关与授权不能激活新执行器或准许发送图片。覆盖升级后连同旧版客户端请求一起测试。
- 退出 Computer Use 专用 Qwen3-VL 点击定位、设置引导与运行时准入。工作中心的截图提取仍调用同一个 Qwen 会话，保留它需要的本地运行时、模型管理和用户已有模型文件。重新验证这项实际消费者。[工作中心调用点](../../../companion/src/activity/model-extract.ts)
- 在没有 LCU、ChatGPT 桌面运行时和 Qwen 权重的安装环境，从产品入口重复原生任务。基础操作用文本模型也能完成，视觉任务仅用已授权的多模态主模型。Cua Driver 和 UI-TARS 是历史调研参考，本计划不引入新的桌面驱动。浏览器 DOM 与通用 MCP 各自有独立用途。

## 5. 本轮实现与测量

原生桌面工具为 `host_computer`。L2 类别为窗口观察和输入，组合来源为原生 AX / UIA、OCR 与可选的当前主模型。认证侧栏主对话持有本次运行的授权。每次发图单独批准，模型候选点击另需原发起方核对标注预览。审批端点变化、窗口身份变化、撤权和停止都会使未执行的建议失效。LCU 工具和 Qwen 桌面定位器已退出。工作中心保留本机模型管理。
