# LCU 集成实施顺序

GitHub: #775。规格：`../specs/2026-10-25-lcu-computer-use.md`。

1. 锁定上游 v0.13.0 与真实 producer/SDK 合同，记录平台差异和原生未验项；Issue 先于规格。
2. 写惰性、可注入的安装发现/status 投影与配置契约，拒绝不支持平台和非固定命令；不执行本机已安装 runtime。
3. 实现按真实 run 隔离的 MCP session、初始化指令、两工具闭集、原生 elicitation 与 Stop/Interrupt 清理。连接与动作均不得自动重放。
4. 接认证 WS 配置/检测与设置 UI。默认关闭，启用生物识别；缺失依赖与上游支持/本产品已验状态分别展示。
5. 接当前主对话的真实 execution ID、能力白名单和交互确认；在首次模型请求前注入原始 instructions，给当前多模态模型传真实图片，像素不进持久化/日志。worker/outbound/summoner 不扩权。
6. 冻结必要 focused CPU / 正常 Program/build；只跑受影响模块。机器红先修机器/产品，不拿模型意见覆盖。
7. 恰好两路独立非作者审同一最终版完整受影响 diff 与必要机核报告。T3 采用当前用户已明确的独立两路门禁，不混入旧技能中的固定 vendor/第三第四路要求。
8. 完成可审阅实现后，真实桌面验收另绑定具体已装依赖/拥有应用/动作；未获该具体范围不运行本机原生实验，不声称原生已验。正式 CI 与 native 证据满足后再按既有授权合并并观察精确 main。

本计划不安装/换装 App，不改用户 live config、其他 agent 配置或无关未提交文件，不 tag/release。初次 managed worktree 因用户 checkout 缺少新主线 Git 对象而失败；fetch 公开 main 后已创建同一个目标 worktree，无代码/测试/实验预算消耗。工作区附件达 100 上限，重试一次注册仍失败；继续使用已创建目录，不再创建副本，不删其他附件。
