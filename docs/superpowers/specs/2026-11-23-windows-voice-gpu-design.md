# Windows local speech GPU support

GitHub: #892. User approved CUDA first, Vulkan cross-vendor, CPU fallback on 2026-11-23.

Windows x64 local Whisper will select an installed, fully verified CUDA runtime when an NVIDIA device is available, otherwise an installed Vulkan runtime, and finally the existing CPU runtime. AMD, Intel and other adapters are inventoried using Windows APIs; physical Vulkan capability and actual execution, rather than vendor names, determine acceleration. Virtual display drivers do not qualify as GPUs. Windows ARM64 and macOS/Linux retain existing behavior and receive no new support claim.

Runtime packages live in separate backend directories and never overwrite the CPU DLLs. Manifest keys `win-x64-cuda` and `win-x64-vulkan` use the existing archive/file download format and full per-file SHA256 and size checks. GPU components download only through an explicit UI action. Building a distributable Vulkan runtime from the pinned whisper.cpp v1.7.6 source is supported; its dependencies and archive are verified. No driver installation, live config edit or automatic download occurs.

One runner entry point serves prewarm, partial and final transcription. GPU argv omits both `-ng` and `-np` so the adapter can verify backend initialization in stderr; CPU keeps its existing options. Actual backend and device come from execution evidence, never hardware inventory alone. If a GPU initialization/inference fails or silently chooses CPU, use at most one bounded CPU fallback within the original overall deadline. Abort, timeout and invalid model/audio do not trigger repeated runs. Transcripts and raw audio never enter device status. Existing temporary audio cleanup is preserved.

The `voice.model.state.acceleration` DTO contains platform support, physical/virtual adapter inventory, installed backend availability, planned automatic backend, and a latest execution record (`backend`, `device`, `fallbackReason`, `ms`, `at`). Before an execution succeeds, the UI calls the backend a candidate, never active. Latest state is bounded and in-memory; changes reach the existing state channel. Old clients and old server payloads remain valid. Missing drivers, unsupported devices and damaged runtime files show a reason and retain CPU use.

The settings UI shows adapters, CUDA/Vulkan install buttons and progress/cancel, planned selection and latest actual backend/device. Multiple adapters are preserved; the backend's actual chosen device is reported without assuming Windows inventory order matches backend ordinals. NVIDIA may use Vulkan if CUDA is unavailable. AMD/Intel are labeled as Vulkan-supported where capability is found but not physically validated in this session.
