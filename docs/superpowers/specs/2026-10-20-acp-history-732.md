# ACP 最小历史元数据

GitHub: #732
状态：root 有限合同批准实施；源码、原生隐私和真实重启验收另记。

只保存原 session/thread/agent opaque IDs、mode、created/updated ISO UTC、observed_state 和可选 terminal_kind。**目标/工作区标签默认全部省略**，不保存输出、命令、环境、PID、协议会话、diff、授权和对话正文。历史与活动运行表分开，旧 ID 不能用于 start/prompt/apply/cancel，不自动 resume 或重建 PTY。

容量：全局256条、每线程32条、文件1MiB，回复32条且64KiB以内；先淘汰最旧的终态历史，不能淘汰真实活动记录制造空槽。容量不足只使历史不可持久，不改变原 ACP 准入与生命周期。

固定私有目录下 `acp-history.json` version1。严格拒未知字段、坏时间/状态、重复 ID、畸形/过大文件。拒 symlink/junction/nonregular/multilink/不稳定身份；POSIX owner/mode600，exclusive 空 temp 校验后写入、同目录原子 rename。失败不自动覆盖损坏原件；rename 后验证失败标 commit_unknown，不谎称旧值仍在。关闭 fd 先退休编号，只清理身份仍属于本次操作的 temp。

Windows 使用现有有界 PsRunner，固定只读 `Get-Acl -LiteralPath`，当前真实 SID owner，DACL 存在；只允许当前 SID/SYSTEM/Administrators allow，拒 null/未知/宽松/查询失败/reparse。临时空文件的实际 ACL 必须在内容写入前通过；不 SetAcl、不重写用户目录、不用 mode600 代替 NTFS。输出仅 PRIVATE/REFUSED/UNKNOWN，不含路径、SID、SDDL、错误正文。真实 NTFS 正控仍须精确 Windows CI；CPU ACL seam 不是该证明。

持久化监听已接受 proposal 和状态/终态变更，不监听正文频率。历史写失败不杀进程、不释放 slot、不改变 ACP 主结果；元数据异步写不成为原 shutdown 额外等待门。重新加载的无活动句柄非终态只显示“已中断；无法恢复原进程关联”，不声称已观测 OS 进程死亡。当前 manager 活动快照覆盖同 ID 历史，历史不能改变当前 UI 选择或权限。

`acp.enabled=false` 在任何 history 入口前拒绝文件 IO 与内容发布；在途操作禁用后停止写/rename/delete，并仅退休自己持有的 fd，私有空 temp 的至多一个清理 claim 留到后续启用。无迁移、权限修复或自动清旧文件。

UI-only `acp.sessions.list` owner/request 对应只读列表，原认证/真实线程存在/worker拒绝/await 后重查不变。前端绑定 request、thread 和原 selectionRevision，断线/禁用/切线程清理显示；A→B→A/迟到回复不能重选。历史单独折叠区，无旧 ID 动作按钮、无新一级入口和轮询。旧 peer 不支持则明确 unavailable，不能把缺字段视作零历史成功。

实际 manager→owned 文件→fresh loader、纯 consumer/JSX/effect 回归可开发；CPU、VFS、POSIX读写不冒充 Windows ACL/真实 Companion 重启/侧栏刷新。整票完成必须保留原对应实际证据。
