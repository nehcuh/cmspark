# 聊天采集漏记、多屏选窗与待办整理

GitHub: [#900](https://github.com/nehcuh/cmspark/issues/900)

本地实现和验收结果见文末。调研基线是 CMspark 1.8.0 和 2026-11-24 的主线 `cc977b0a`。下文现场记录对应升级前的实现。

## 本次漏采能解释到哪里

先修两件事。第一，让用户看见每张来源究竟走到了哪一步，并让慢模型与窗口采样独立运行。第二，让用户能选中一个具体的聊天窗口，在另一块屏上工作时仍知道它是否正在被记录。单独缩短轮询间隔或调整提示词都覆盖不了这两个问题。

| 现场证据（已去除聊天内容） | 对故障判断的影响 |
| --- | --- |
| 已启用自动采集，间隔为最低的 3 秒。已选择聊天应用，未设任何限定对话的布局。当前图片处理授权与所选目标匹配。 | 应用白名单已生效。历史漏记不能统一归因为忘开采集、标题名单不匹配或模型未授权。当前授权只能说明检查当时的状态。 |

## 第一阶段　让已配置的采集可验证、可恢复

**工作中心的第一屏回答三个问题**：正在看哪个目标、最近保存了什么、哪些来源需要处理。每个目标列出采集模式、最近检查、最近新增来源、最近识别结果及对应操作。失败保留到该来源恢复或被清理。对未成图的检查，只在本机按时间段和原因累计次数，例如等待前台、身份不明、标题不符、画面重复。避免记录经过的其他应用名称、窗口标题和正文。

| 工作中心看到的状态 | 用户能直接做的事 |
| --- | --- |
| 等待前台 · 最近检查 10:32 · 最近新增 10:26 | 测试此目标，等待用户手动切到聊天后显示本机实际范围 |
| 已存截图 · 等待识别 | 查看本地来源、队列进度或暂停模型处理 |
| 识别失败 · 输出达到上限 | 查看来源，缩小聊天区域或调整该模型的输出预算，按原授权重试该张 |
| 已识别 · 0 项行动 / 2 项待确认 | 前者查看识别文字，后者直接核对原句、负责人和反馈要求 |
| 来源已按保留策略清理 | 查看清理时间、原因和已确认事项的保留状态 |

状态随来源入库。对旧记录，只有现有证据支持的字段才回填；旧视觉来源有截图而无转录时显示“尚无转录，历史原因未知”。保留设置同时展示天数、实际用量和容量上限。此前已有来源既可能被按期或按量清理，也可能由用户主动清理，旧版本无法倒推出具体原因。

**把采样与模型识别分开调度。** 采样仍逐窗串行核验，合格的新画面裁剪、去重、落盘后即可结束本轮。识别消费已保存的来源 ID，初版一个模型请求并发就够。积压显示数量和最早等待时间，相同来源只排一次。队列随来源存储有界，不额外复制原图。暂停、撤权、目标变化、删除、过期或重启时重新核验来源及授权，授权变化后等待重新确认。只对可恢复的失败提供有界重试，输出上限和配置错误要带着解决办法返回用户。重跑同一来源应复用已有候选及确认结果。

**让“现在检查一次”测得到目标。** 当前按钮在工作中心立即检查全局前台，单击时焦点通常在工作中心。改为“测试此目标”，复用现有校准的手动切窗等待，显示命中的应用、窗口类型、预览范围与跳过原因。第一次只做本机预览；验证模型时使用内置虚构聊天样张，回执分别展示连接、转录解析和候选数。对真实来源重试继续使用已核对的接收方。

## 第二阶段　选中副屏里的那个聊天窗口

设置提供两个明确选择。**跟随前台聊天**沿用既有配置，只有在用户查看所选应用时记录。**固定可见窗口**单独启用，用户通过系统选择器选一个主窗或独立聊天窗，界面预览实际目标，并说明切到其他应用后仍会记录的范围。先在 macOS 验证一主一副两个独立窗口场景；多窗口各自显示所属屏幕、资格、最后新增和暂停入口，避免把整块显示器作为聊天来源。

1. **先确认窗口，再确认会话。** 记录应用身份和本次用户选中的窗口，校验所属进程、窗口生命周期和可见性。主窗口可以在不同群之间切换，固定该窗口后仍须在每帧验证获准会话。窗口关闭、应用重启或出现同名歧义时暂停，提供一次重新选择。固定窗口的失焦、遮挡、最小化、锁屏和安全输入要有各自的判定；首版对遮挡不明或不可见暂停采集。
2. **按用户看见的布局校准。** 在冻结预览上高亮标题与消息区，用户可调框并查看本机 OCR。优先用可核实的 AX/UIA 标题、消息区等结构建议区域，缺少结构时沿用手工双框。自动调整只产生预览建议。已核实的同逻辑布局发生纯 DPI 变化时，按窗口坐标转换并重新核对边界、标题和侧栏排除；无法通过时一键重校准。保留现有绝对像素配置可读，迁移不扩大已授权区域。
3. **区分聊天、登录和同应用的其他页面。** 配置时展示本机识别的应用、窗口、当前会话与消息区域。对限定聊天，缺少标题、消息区或有登录特征时不给下游图像。群人数、未读角标、昵称变化先提示新候选，由用户确认允许的变体。同名群及多账户重名时要求独立窗口或额外可核实标识。
4. **分别验证各平台。** macOS 优先验证用目标过滤器的 `contentRect` 与 `pointPixelScale` 统一裁剪坐标，实测跨屏、负坐标和 1×/2× 缩放。Windows 在现有前台 HWND、进程身份及 DPI 校验基础上，验证系统选窗后取得的单窗捕获对象及关闭事件。Linux X11 保留现有前台能力，Wayland 保留主动导入；新增绑定能力按平台实测开放。会议录屏已有浏览器共享选择器，其录制会话与后台聊天采集授权有不同生命周期。[Apple 窗口过滤器](https://developer.apple.com/documentation/screencapturekit/sccontentfilter) · [Microsoft 窗口选择与捕获](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture) · [现有录屏入口](../../../chrome-extension/src/sidepanel/voice/workbench-screen-capture.ts)

## 第三阶段　从消息证据提取待办

优先处理已确认消息区内的新增消息。普通文字先由本机 OCR 保留文本块、位置、阅读顺序与来源，大图中的文字、嵌图以及用户主动选择的视觉识别走已授权的模型。文本外发与图片外发分别使用已有授权。先持久化可用的识别结果，再做候选解析，这样模型结构出错后仍可手动整理、局部重试或核对原图。

| 示例场景（虚构） | 候选应怎样出现 |
| --- | --- |
| “小林，核对清单，把差异发给我。” | 保留行动、反馈及共用原句。若抽出两个可独立确认的行动，二者均可保留。重复截图不会重复建项。 |
| A 发出请求，B 下一条回复“我来做，周五下班前给你”。 | 展示相邻两条的来源及说话人，把负责人、反馈人、原始时间短语分别呈现。只有消息日期、时区及指代充分时才建议具体日期，供用户确认。 |
| “这个已经反馈过了。” / “如果客户同意再准备。” | 完成反馈关联原有事项，条件句保留条件供核对，避免重复分派为新待办。 |
| 截图只有群名、侧栏摘要或模糊缩略图。 | 明示证据不足，不据此猜负责人或承诺。用户可选现有“手动整理”或导入清晰截图。 |

去重先定位同一会话与重叠消息，再比较行动和证据片段。窗口标题和模型生成的人名不足以合并跨群事项。候选卡将“我的待办 / 我督办的”、待补负责人、原始截止短语、反馈去向和证据放在同一处。点击引用定位到原截图的消息区域。正式待办、具体提醒仍由用户核对确认。

## 设置与首次使用

主路径为 **选目标 → 看预览 → 保存并开启 → 查看第一张来源**。同一确认页展示应用、窗口或群、前台或固定模式、保留时间与容量，以及模型实际接收的是文字还是裁剪图。提供“仅保存设置”和“保存并开启”两个明确操作。现有用户先看到生效规则及最近运行情况，原配置按原语义加载。

识别方式按用途显示“仅本地留存”“本机识字后提取”“用视觉模型读聊天与图片”，分别说明本机与所选服务处理什么。模型地址、输出上限、OCR 语言、检查间隔、自定义提示词放在高级设置。优先补通复用视觉模型的输出上限，从失败来源打开设置、保存后读回生效值、返回并重试原来源。保留模型设置和隐私设置现有入口，两者都打开同一目标与同一份草稿。

## 实施顺序与验收

| 优先级 | 验收场景 | 如何判定 |
| --- | --- | --- |
| P0　来源状态与采样解耦 | 用自有样张让模型处理 25 秒，期间连续展示三个不同的、各跨过一次采样点的合格画面。另测重复图、零候选、超限、撤权和重启。 | 三个不同画面各有来源，重复图不新增；每张可解释识别结果。撤权后不得继续投递；重启后可恢复合格积压，手动重试不重复创建事项。 |
| P1　选窗与实际双屏 | 真实微信主窗口、独立聊天窗和钉钉分别测试。主屏编辑文档、副屏选定聊天更新；再将窗口跨屏、改变 DPI、切换其他群、最小化、遮挡、锁屏、关闭并重开。 | 对每次场景标记预期采或跳过。合格稳定画面在下一有效采样点被捕获，所有不合格画面均有原因且保存与模型调用为零。拿到真实双屏证据后再标记该平台支持。 |
| P2　待办质量 | 给自有或脱敏聊天标注行动、承办人、反馈、截止和证据，包含一条多行动、多轮承诺、同名群、完成通知、条件句与无待办对话。 | 分开报告行动召回率、准确率、重复率、无证据字段率；采集侧另报符合采样条件的画面数、实际新增数及保存到出候选的 P50/P95。基线与改动用同一批样本，禁止把未采到的消息算作模型误判。 |

本次用仓库隔离运行器验证了间隔、慢模型、范围匹配及视觉抽取四组共 30 项既有测试。另用生产解析与存储复现了同引文两个行动只保留一个。实际双屏、Windows 实机与改进后的任务准确率属于实施验收项。

## 11 月 24 日实现与验证

- **采集与识别**。采样器保存通过范围核验的截图后继续检查窗口。正文 OCR 和模型任务通过独立的单并发队列处理。每张来源持久保存识别状态、完成时间与行动数，或失败原因。视觉返回了有效转录后，即使候选结构损坏，原文也会保留。工作中心支持按原图排队重试、调整视觉输出预算和查看超过 30 张的历史。重启后重新检查原目标授权，恢复尚未投递的自动任务。投递途中中断的任务等待用户确认重试。
- **窗口范围**。macOS 15.2+ 通过系统选择器持有单窗过滤器。系统标题相同的窗口保留独立身份。每轮按顺序检查启用的窗口，每帧核对进程、可见边界、遮挡、锁屏、安全输入、标题和消息区。新校准布局记录逻辑尺寸，纯像素倍率变化时向内取整转换框，再做标题核验。关闭失效与服务重启后要求重选，支持逐窗暂停。Windows 和 Linux 继续使用各自原有的采集模式。
- **现场边界**。本机只有一个内置显示器。自有 macOS 窗口夹具观察到遮挡时跳过；锁屏时得到三次明确的锁屏回执。两窗口轮询、同名隔离、重选和 1× 到 2× 的精确裁剪通过隔离测试。仓库包含使用正式原生 helper、系统选择器、两块扩展显示器和自有蓝色窗口的验收入口，本次运行在硬件与桌面前置检查处跳过。真实微信、钉钉和双物理屏仍待实测。[双屏验收入口](../../../companion/scripts/test-mac-fixed-window-900.sh)
