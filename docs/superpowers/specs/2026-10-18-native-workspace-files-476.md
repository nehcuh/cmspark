## Five exact requests

All fields below are required except list.path. Reject unknown/duplicate/escaped duplicate/nested/coerced fields using the existing flat parser. `id` is a nonempty string within existing200 UTF16 units; `thread_id` is an existing safeThreadId in the current metadata visible set. No renderer absolute root, folder-picker result, env, shell argument, generic payload or user-asserted approval.

| Method | Fields after type | Meaning |
|---|---|---|
| desktop.workspace.state | id, thread_id | Fresh private canonical/root snapshot, retire previous workspace operation/read revision, issue a new current revision; no filesystem creation. |
| desktop.workspace.pick | id, thread_id, revision | Native selection and trusted-controller confirmation, then conditional bind. revision matches the current state snapshot. |
| desktop.workspace.list | id, thread_id, revision, path? | List explicit bound root, relative path default `.`. |
| desktop.workspace.read | id, thread_id, revision, path | Read one relative-path UTF8 text file under that root. |
| desktop.workspace.cancel | id, thread_id, operation_id | Cancel exactly this owner's pending pick identified by its original request id. Never cancel another owner/newer operation. |

For an enabled, available, valid canonical thread, every state snapshot issues a fresh opaque64hex process-local revision, whether bound or unbound. pick requires that exact current64hex revision; null never admits pick. Only disabled/unavailable state uses null and refuses pick; bound=false still refuses list/read. Request id is correlation only and cannot substitute for the current private snapshot. Revision is **not a grant**: each operation also checks native principal, target, enabled module, current canonical root and identity. Server-private root path/dev/ino/chain/updated_at never travel in this DTO. Tokens expire on replacement state, cancel/disconnect/revocation/document retirement/daemon restart; they are not restored across restart.

Relative path is a string governed by existing frame byte ceiling and OS limits (old workspace tool schema has no separate4096 bound). Reject NUL/absolute/drive/UNC/escaping paths before IO; resolve with existing containment rules, including realpath rejection of symlink escapes. Do not claim Windows semantics solely from host-path tests. Cancel's operation_id uses the same200 bound, validated/mapped by the native bridge like existing chat.stop run_id; a renderer cannot supply arbitrary server-native request IDs.

## Actor, selection and confirmation

One private workspace actor per authenticated native connection, with one target snapshot and one pending selection. It is not a legacy panel session. Every request checks registry authorization/current socket and uses the actual native document/request mapping. state replacement cancels the prior operation and drops its revision; read-only file actions do not create a picker or change binding. UI explicitly cancels on leaving/changing target; native controller also retires a pending picker/confirmation on document navigation/replacement. A cancel processed before final synchronous commit wins; a commit that already linearized is not retrospectively called rolled back. Lost delivery must be reported as unconfirmed.

pick takes no renderer path. **This amendment changes the native-workbench picker provider** from shared `pickFolderNative(WORKSPACE_FOLDER_PROMPT)` (Node→PowerShell/osascript) to the authenticated native controller's actual OS folder panel. The old shared picker and every legacy caller retain their bytes, platform behavior and120000ms budget; no production fallback from this new native provider to that shared picker. WORKSPACE_FOLDER_PROMPT remains fixed. The new operation has one120000ms absolute selection deadline starting at actor admission, including message delivery/panel setup, never reset by callback/reconnect. Confirmation45000ms and admission60000ms remain separate original stages. Module-off/stale/unknown/busy requests create no panel. Do not consume/populate globalLastPick.

Owned means the controller holds the actual typed panel/dialog instance, owns its lifecycle and binds it to its current native window/document; it does **not** mean the OS draws it inside the host PID. On macOS10.15+ Apple documents NSOpenPanel always draws in a separate system process. Use NSOpenPanel on AppKit main thread, canChooseDirectories=true/canChooseFiles=false/allowsMultipleSelection=false, and beginSheetModal for the current owned NSWindow. Only real `.OK` completion plus that panel's one file URL may create a selected result. User cancel, invalid/missing URL or platform failure cannot yield a selection. No NSApp.windows ownership assumption, osascript, System Events, AX/TCC changes, global UI scans or foreign-window control.

Windows uses SDK-typed IFileOpenDialog through COM on the existing native host's UI STA, with real Show(current owned HWND), single folder/file-system/path-exists selection, no cwd change or recent-item mutation. Only successful Show + GetResult + SIGDN_FILESYSPATH produces the selected string; free returned task memory and release all COM/event references. Cancel/close returns no GetResult selection. Its original dialog does not become a WebView or simulated path chooser. The modal UI must continue dispatching current-owner cancellation; no blocking wait or extra worker changes the deadline.

Before selection, after its completion, after confirmation settles and immediately before commit, require current owner/target/OCC and real idle activity. Canonicalize the selection, verify it is a directory, and retain private identity of root/ancestor chain. Existing SecurityConfirmationManager + native controller is the only approval queue. Add a fixed workspace purpose for this binding, matching thread_id, original request, action digest, snapshot revision, selected canonical directory and deadline. Final current/OCC/activity checks and synchronous persistence have no await between them. A committed write whose ACK is lost is unknown to UI until a fresh state read, never automatically repeated.

## DTO, UI and failure truth

state returns only thread_id, bound, redacted directory display name, opaque revision and closed availability/activity status. list returns relative path/name/type/truncated; read returns relative path, actual bytes, inert text and complete/redacted flags. No absolute root, default-data/home path, env/PID/source reference, wholeThread or raw fs error. Reuse redactSecrets and final JSON UTF8 frame guard. A secret-redacted relative name is not exposed raw or reconstructed as an openable real path; reject a secret-bearing requested relative path before lookup. Redacted text is labeled and not claimed byte-complete. Undeliverable/oversized replies are finite failure, not successful truncation or an early fake terminal.

Successful replies have exact common `type:<method>.result,id,thread_id,ok:true`. state adds only `state:{bound,display_name,revision,module,activity}`; module is enabled/disabled/unavailable, activity is idle/busy/unknown. pick adds `outcome:committed` plus that fresh committed state. list adds `revision,path,entries,truncated`; each entry is exactly `{name,type,path,readable}`, type dir/file/other, and redacted/unopenable path is null/readable:false. read adds `revision,path,size,text,complete,redacted`, size a nonnegative actual-byte integer within512KiB. cancel adds `cancelled:boolean,operation_id` (false means no matching pending operation, not a rollback). Failure has only common identity, `ok:false,error_code`; binding failure also adds the honest finite outcome denied/cancelled/conflict/unavailable/unconfirmed. No nested arbitrary error object.

Use a fixed error enum: WORKSPACE_INPUT_INVALID, WORKSPACE_STALE, WORKSPACE_CONFLICT, WORKSPACE_BUSY, WORKSPACE_ACTIVITY_UNKNOWN, WORKSPACE_MODULE_DISABLED, WORKSPACE_UNBOUND, WORKSPACE_CANCELLED, WORKSPACE_DENIED, WORKSPACE_MISSING, WORKSPACE_UNSUPPORTED, WORKSPACE_CHANGED, WORKSPACE_UNAVAILABLE, WORKSPACE_UNCONFIRMED. A formatter must not inspect or echo arbitrary error.message/path. No new passive diagnostics carrying file content or directory paths.

UI has one thread-bound workspace area, explicit choose/cancel/refresh, directory navigation and read-only text. Captured document, target, request id, revision and epoch protect A→B→A, late success/error, cancel, page change, new document and disconnect. None auto-replays picker/commit/read on reconnect. Reopen/status is the source of truth after lost ACK. File content is textContent; links/navigation/downloads never turn the privileged WebView into a file browser. Existing chat/resource/Stop/confirmation stays intact.
