## 1. 单一产品范围与不变量

用户显式设置 N 并分别批准每次启动后，不同已有 agent-id 的 bridge 会话可以同时存在；可分别查看、取消、收集原有来源明确的 handback。`offered` 多个成功不是同时运行；准备中、取消 ACK、UI state=closed 都不等于进程退出。

默认 `acp.enabled=false`、默认 N=1、review_readonly 默认、原 propose/start/apply 逐次 critical force_confirm、原安全 token/绑定与 worker/orchestrator HARD_DENY 全保留。cruise/god-mode/三旗不能豁免；无批量 API、队列、自动启动/重试/选下一个、合并确认、free shell、自动 apply/push、新 runtime、PTY 字节入模型或默认模型/live 配置改动。

## 2. 精确容量与生命周期

**配置：** 既有 `acp.max_concurrent_sessions` 从 literal1 扩为整数联合 `1|2|3|4`；缺省为1。只接受真实数值整数；0/5/小数/NaN/Infinity/字符串/布尔/null 都非法，不夹取/取整/把非法值静默当1。`config.set` 与 `saveConfig` 在任何持久化前拒绝非法显式更新并保留旧配置；不能让现有 sanitize catch 吞错后写空 servers。磁盘加载遇非法值沿既有 ACP fail-closed 路径禁止新启动、不重写原文件；既有进程占位继续保留。无独立 thread/agent 容量旋钮。

**执行计数：** 以当前 manager 实际 session 对象对应的私有启动占位为准，而非 running state、PID、UI记录或 `runningCount=Math.max(...)` 的推测。每次新准入须满足 `globalActive < N && threadActive < N && sameAgentActive === 0`，然后同步保留唯一占位；两者之间无 await/事件回调。占位私有绑定原 session 对象、固定 thread_id/agent_id 和当前拥有的准备/子进程，不是新 grant 或可恢复 ID。agent 定义沿原 `session.agent_id` 标识，不按展示名、CLI basename、输出文本或 provider 自称合并身份。

占位从 Windows 准备/任何 await/真实 spawn 前开始，直到无子进程的准备失败真正结束，或最后一个该次拥有的子进程真正 close。取消、timeout、流错误或 teardown 失败可以先返回失败/closed，但仍持有本占位；只取消/关闭该对象拥有的 child/prepare，不释放或杀其它会话。释放按同一占位身份幂等，replacement 与重复 close 不减别人计数。ACP auto 探测→CLI fallback 沿已有行为，必须先确认 probe 实际退出，**同一逻辑占位跨 fallback 连续保留**；不能在探测 close 与 CLI spawn 之间临时放空。未证 probe 退出时不得 fallback。

降额不杀或忘记现存占位。例：4→1且仍4活跃，四者继续；3/2/1活跃时仍拒绝新准入，直到0才可新准入1。降额时出现 active>N 是存量过渡，不是新准入成功；升额不自动启动任何 offered。配置失效/关闭主开关同样不将 live slot 清零。

**提案元数据：** 原 #722 offered15min、懒回收、4/thread、64/process 是当前基线；#728 明确引入的新合同改为非终态4/thread、16/install，并按 `(thread_id,agent_id)` 非终态去重。非终态包括 offered/confirmed/running/handback，以及 state已closed但仍有准备/child占位的对象；真正closed且已释放不计。这是明确的提案行为变化：默认N=1仍可有四个不同agent的offered，但原#722允许同agent四份offered的旧正控不再符合新pair去重合同，须保留旧证据并更新为四个不同agent，不能偷偷称原字节行为未改。达到界限拒绝新提案，保留既有记录，不淘汰执行/确认。升级时若旧64预算遗留>16，保留存量并只阻止新提案至低于16；不批量删除旧提案。

只有 offered 且没有准备/child/协议占位时沿既有15min惰性回收；原 fixed expired owner反馈后再删该 offered/cache。确认等待不占执行槽，但仍是原 offered，15min不续期；晚批准必须重查同一对象/快照/owner/worker/开关/时效和最终容量。确认前预检只读，无占位/执行/假成功；确认后真实 start 同步复查再占位。未知时钟/非法metadata保守拒绝，不能扩容量。

## 3. 最小旧 Mode C 兼容口径（已批准的最小规则）

两个 bridge 路径目前都会调用 `maybeOpenLocalTerminal`，快照true会开外部终端或记录embed意图；不能默默忽略已确认的快照来伪装纯bridge。

最小规则：**N>1 新启动仅允许 `open_local_terminal_snapshot === false` 的 bridge。** true或旧缺省不明者在确认前以既有 typed busy 拒绝，提示用户显式配置 bridge-only 并重新提案，不替用户切开关/改快照。N=1 保留原 Mode C 行为和 Stop 诚实文案。升额前仍持有 snapshot=true 的启动占位也不与新并行启动混合，直至其受管 bridge 真正 close；不能从 bridgeclose 推断外部终端 Agent 已退出。

现有 PTY `live/closing` 单槽、单 relay、owner/consume descriptor/256KiB流控和启动来源 metadata 均原样。纯 bridge 不打开、抢占、关闭或读取既有 shell/embed 终端；用户显式终端操作仍由原 PTY owner/互斥路径裁决。无需多PTY、多embed、terminal session map、新终端内容渠道或终端健康探针。

## 4. 最小数据合同与 UI 迁移

不新增 batch/list/restore/启动 API，不改原 state 枚举或 tool start 的既有完成返回语义。WS/ui_start、prompt→followup、显式followup与tool start必须用同一个只读 admission与真实reserve路径；原 per-object pending-confirm fence、owner/snapshot复核和逐次L2不能只修 UI一路。

唯一新生命周期 wire 字段：现有 session event/status DTO 可选 `execution_phase: "preparing" | "running" | "closing" | "released"`，只由真实占位/owned-child生命周期生成，不由客户端设置。preparing=已占位尚未真实 owned launch；running=受管 bridge 的真实启动事件已发生，不证明配置CLI登录/模型可用/Agent健康；closing=取消/失败但未真实close；released=该占位真正退休。旧peer缺字段时保持未知，不把state=running直接当健康。原 confirmed、offered 是非执行状态；不以 N/phase 给新授权。typed拒绝继续复用 ACP_SESSION_BUSY / ACP_CONCURRENCY_LIMIT 与原有限 data；同 owner 可给既有holder id/agent/state，跨线程只固定摘要/可行动suggestion，不增加 paths/goals/输出/凭据。

前端新增 `codingSessionIdsByThread: Record<string,string[]>`，保存同thread首次有效接受事件的有序、唯一、可查看ID集合；进度更新不重排。原 `codingSessionIdByThread` 保留为**当前查看选择**，降低既有consumer迁移风险；旧单值只初始化为存在且owner一致的一元素集合，不读取磁盘、不复活进程。新事件更新其本身并加入所属集合，不偷换有效选择；没有选择时可按已冻结的首行规则初始化一次，不自动启动或替用户选下一运行目标。现有inactive-rich16rows/256KiB预算不扩大；state=closed但phase=closing的对象仍属active，不进入旧终态压缩/消失路径，phase及有限identity在真正released后再按原预算处理。compact marker继续挡迟到复活；数组移除已compact不可查看项，但不删除原终态marker/未完成diff/真正active记录。

在 canonical reducer 增加一个纯 UI `activeCodingSelectionRevision`，仅实际改变当前查看对象时递增，用于同thread A→B→A，与现有 activeThreadSelectionRevision 合用。它不持久化、不上wire、不参与后端权限/执行代次。所有异步操作的闭包均绑定 thread+session+两个选择revision；迟到ACK/error/manual-entry/apply/启动结果可更新其正确record，不能抢当前view、清新error或恢复旧内容。不得用 Date.now/仅useEffect或旧row对象相同来代替该 fence。

FocusBand仍一个coding chip、一个primary槽；显示当前thread真实offered/准备/bridge运行/关闭中数量与当前查看对象，旧字段缺失明确未知。列表在现有面板区域滚动；320px/S96/FocusBand高度及输入顶栏预算不增加。原更多/打开面板CTA只开面板，仍0propose/start/PTY。每个动作使用选中sessionid而非全局“最近会话”。

## 5. 结果、原流程与失败域

每次输出/collect/handback保留session、agent、thread来源；现有 `frameAcpHandback` delimiter neutralization、长度上限、partial/error与每thread taint语义不变。并发成功不会清别一路taint，只有原下一条真人消息边界清除。不给合并无来源的“可信汇总”，不因failed一路中止其他已准会话/全轮tool loop。AUTH/OWNER/worker/安全拒绝不降级；仅原容量有限码保持recoverable。

保留 Windows 每个 owned launch 自己的 Job/句柄与 POSIX owned进程组；不改全局kill、PID迟到重试或默认超时。未实际启动的会话不得记pid/产出，prepare-cancel不生成虚假进程结束回执。`hasProjectThreadActivity`、collect/status、shutdown等消费也必须以仍拥有的claim/child判断，不能stateclosed就释放忙碌保护。历史视图如并入#735，只是观察数据，不能加入执行占位或自动resume。

## 6. 必须亲证的验收与声明边界

1. 默认1不重叠；合法1..4/非法更新0持久化；N=2/4不同agent真实两/四占位。CPU真实manager producer先RED→GREEN，不能只测手写计数函数。
2. 两个独立L2同时批准，最终同步检查+reserve只准N；同agent跨thread≤1；thread/global两门、4/16提案、旧>16过渡、降额4→1、取消/准备失败/同步observer cancel/teardown失败/迟到close/替换对象均守界。
3. 原 #607六种 init/new failure、success、failure、cancel、startup-cancel 保留；扩为同agent始终拒、N=1不重叠，N>1仅不同agent可占余槽；probe→fallback不重叠、真实close前不复用该slot。只更新旧“永远global1”的过时consumer，不能删close/PID/owner断言或延原预算。
4. 实际handler/UI事件链：offered四行、两启动、独立stop/collect、thread切换/同thread ABA/迟到结果、queued confirmations、旧单值迁移/缺phase兼容/compact marker/来源taint；控制型DOM/SSR不冒 mountedbrowser。
5. 一次必要共享host/normalbuild/lockedARM，两路盲非作者；精确head/main全部CI，真实Windows owned bridge子进程重叠/取消一方另一方仍活/prepare cancel/同agent负控与原native门禁必须通过。CPU/ARM seam、CLI argv推导或多个offered绝不能当实际Windows/配置CLI成功。
6. 原生owned fixture只证明生产通道上的受控进程事实；真实命名CLI、登录、provider/模型就绪正控若未实跑仍 NOT_RUN，不冒真实agent健康/CLI正控。不开本机测试浏览器/PTY/daemon/provider来补表。无事实支持不得wholeClose #739或声称用户已可同时运行；父#70/#476/#563和其他票不随本叶自动关闭。

## 8. 实施期有限 owner 裁决（#739）

- 唯一新增生命周期字段仍为 readonly `execution_phase`。既有 followup/prompt 的 `parent_session_id` 仅由 owner 已核实、原parent对象仍当前、真实result对象同thread且parent精确相等时 echo；早owner拒绝、foreign/replaced/result-mismatch不回显。它仅用于反馈关联，不授L2或owner权限。
- UI最多64个私有未settle操作（16元数据×4既有操作类）；重复／满时拒绝，不淘汰、不排队、无新timer/retry。forwarding success、terminal event或Stop ACK都不能清另一个仍待唯一handler回复的操作。仅它自己的reply、确切forward failure或真实connection失效退休。
- 每次发送锁存thread选择修订与coding选择修订。无correlation的legacy消息不借用当前修订、不清新错误或抢view；真实row可显示明确“回执关联未知”，compacted marker不恢复富文本。主启动仍保留原12秒本地CTA恢复，它不退休pending操作。
- 占位由真实spawn事件前标 preparing，真实owned spawn后才为running；有PID的exitCode/closed UI不取代child close。未产生PID仅在实际failed-spawn error证据后可释放，普通preparing阶段不能因pid缺席就放空。
- 所有原privilege、确认、超时、token、workspace与受管子进程策略保持。真实Windows、精确head/main CI、独立两票与必要共享ARM均是后续门禁，作者不能自批。
