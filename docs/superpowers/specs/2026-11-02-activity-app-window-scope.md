# 工作中心：稳定应用选择与指定聊天范围

GitHub: #825
状态：A/B/C 设计已获独立 agent 验证与 GLM-Claude APPROVE_WITH_NITS；实现与最终原生验收进行中。
目标版本：0.8.0。用户已授权延后发布，并将本票纳入当前版本。

## 用户目标

Windows 上的微信、企业微信、钉钉、飞书、QQ 运行应用不会因最小化、隐藏或临时没有窗口而从选择器消失。可限定主窗口内的群聊/联系人，也可为独立聊天窗口设置范围。支持最短 3 秒检查及读取聊天中可见图片。

## A. 应用发现与检查间隔

- Apps 枚举同一交互会话中可解析可执行路径的运行进程，按原路径摘要去重；保留敏感应用排除。发现资格与截图的可见、非最小化、焦点及权限资格分离。
- 不返回可执行路径、窗口标题或聊天正文。显示名称、稳定身份和窗口状态；状态不等于可采集许可。
- 排序后有界最多 4096 项，后端与 wire 一致；超过上限明确失败，不默默给出不完整列表。搜索名称/身份与常见聊天软件别名，过滤后分页；已选应用在列表缺失、搜索和翻页后保留。
- 最短检查间隔 3000ms，UI 下限 3 秒；保留已有默认值与用户实时设置。上一轮截图/OCR/模型处理未完成时跳过，不并发、不补发积压任务；不承诺每 3 秒都完成一张截图。

## B. 可校准的聊天范围

不以通用 UIA 名字搜索、聊天侧栏出现名字或云模型猜测作为当前对话授权。采用用户明确框选的聊天内容区域与其内的标题区域，适用于主窗和独立窗；这是可见标题筛选，不声称取得软件内部唯一会话 ID。

每个受限应用可保存多个明确布局 profile。布局键为实际窗口 class + PNG 宽高，同一键只允许一份配置。profile 包含像素坐标内容矩形、标题矩形、允许的完整 OCR 标题。窗口尺寸/布局改变须重新校准，不按百分比自动放大允许范围。

保存前读取一次最新 activity.state，对比打开表单时的配置与图像目标指纹，以新鲜 revision 提交；来源更新不清草稿，真实配置变化或写冲突仍拒绝，取消/断连不提交。图片鉴权摘要按实际 resolver 的有效字段优先级计算并稳定排序自定义头；OCR 保持既有主模型授权语义。

一次性预览由用户显式请求：倒计时供手动切到所选应用，沿用真实被动截图与身份/权限检查；不激活窗口、不建来源、不调用模型。设置页显示冻结原图，先框聊天内容（含标题、排除侧栏），再框标题，显示本机 OCR 实际比较值供核对；必须精确匹配完整标题，不做子串/模糊/自动去后缀处理。

校准数据不完整时禁止受限应用退回整窗采集。范围开关关闭须用户明确操作。

每次自动采集：

1. 原 HWND/PID/会话/启动身份/路径/前台/权限/遮挡与截图前后检查。
2. 在同一冻结原图上核布局键与所有整数矩形边界，标题须完全包含于内容矩形。
3. 用既有 Windows crop-only 接口裁标题，在本机 OCR 并按同一投影函数精确比较。
4. 匹配后裁聊天内容；核裁剪 PNG 尺寸与配置一致，避免原生 crop clamp 静默改变范围。
5. 只有聊天内容裁剪图可返回 adapter，入库或进入 OCR/视觉/Qwen；其它聊天侧栏像素不得进入后续处理。
6. 不匹配、读不到标题、缺少语言、布局改变或配置撤销均不保存、不送模型；临时原图/标题图/裁图 finally 清理，状态给出可操作原因。

预览和标题预检只经已有认证通道及本机处理，不改实时配置。保存仍使用原 revision 与 generation fence；来源确认、模型目标授权和默认关闭规则保留。

## C. 聊天内图片

视觉模式读取允许内容区域中已经显示的嵌图/截图文字，维持不可信内容提示、literal transcript 引用与用户逐项确认。不开原图、不滚动、不取未显示附件；缩略图不可读时不编造，可由用户主动导入清晰截图。本机 OCR 模式也只处理内容裁剪图。
