# 聊天自动知识注入

GitHub: #873

自动模式从当前用户消息提取检索词。先用现有文档元数据或当前站点缩小候选，再从正文确定相关片段。元数据和站点只提供候选，无法单独触发注入。自动候选遵守当前站点范围，明确勾选资料优先。空查询、匹配关闭或匹配失败时，使用明确勾选的资料。

知识正文仍经过原清理和不可信资料包装。自动片段有单篇长度上限，归入原 8,000 字符预算。分组选文使用同一正文门槛。已授权的站点操作防重规则按真实目标处理。手动模式、全选模式和外部 MCP 的显式授权投影沿用原路径。

Chrome 对话的来源详情展示当时实际注入的片段及选择方式，并可打开当前原文。来源记录与消息一起保存。旧记录仍显示已有来源信息。

分组重新认证使用 `cd companion; node scripts/knowledge-route-eval.mjs --strict`。20 条查询使用既有独立文档标注。聊天分栏逐一验证实际片段在原文和发出的提示中，认证查询须交付扁平路径漏掉的相关尾部，逐条查询的相关来源损失最多一篇。严格模式同时要求原全文文件夹、原全文分组、聊天文件夹、聊天分组四栏通过。
