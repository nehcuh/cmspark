# 会议画面证据与可选视觉模型

GitHub: [#894](https://github.com/nehcuh/cmspark/issues/894)

状态：设计待评审。面向 GPU 1.7.2 之后的独立版本，不修改当前发行候选。

## 问题与选择

现有桌面会议将选中来源的画面保存在浏览器，声音进入连续转写，纪要只处理逐字稿和用户参考笔记。因此录制成功不代表理解了 PPT、图表、代码或表格。原始识别稿和纪要引用核对必须继续保留。

首版选择“转写主时间线 + 本地变化截图 + 可选图像模型提取 + 文字纪要融合”。录制、回放和纯文字纪要不需要视频模型。新增的“会议画面理解”角色可选择已经保存的多模态模型；不强制下载或另购模型。完整视频上传、运动和动画的细粒度分析另列后续能力。

这一选择参考 [Screenpipe 的实际会议摘要管线](https://github.com/screenpipe/screenpipe/blob/b2f787a8463478f8548f36a87204c8788ecf8b1a/crates/screenpipe-core/assets/pipes/meeting-summary/pipe.md)、[anarlog 的转写／纪要分工](https://github.com/fastrepl/anarlog/blob/d63676cf82f8d15d423dd62e8e8bf44758f20b5f/README.md#how-ai-works)和 [Google 官方视频处理文档](https://ai.google.dev/gemini-api/docs/video-understanding)。这是适配本项目的工程选择，不声称存在社区统一最优方案，不复制 Screenpipe 代码或采集范围。

## 用户流程

1. 桌面会议开始前，可勾选“保留画面要点（本机）”，默认关闭。仍由浏览器选择共享来源；不请求第二个来源，不扩展到其他桌面应用。麦克风和纯音频会议保持原流程。
2. 在录制期间从同一视频轨道获取变化帧，也可点击“标记当前画面”。显示已经保存的要点数与达到上限／采样不可用状态。帧错误不终止音频转写；共享撤销、停止、页面关闭时必须停止采样并释放资源。
3. 结束后，会议页展示本场录屏关联的画面缩略图与时间。默认建议最多 12 张分布在已保存范围的代表图，用户可取消、选择与预览；显示这是选中画面的理解，不是整段视频的完整理解。
4. 点击“理解所选画面”，先显示实际模型、接收地址、图片数量／范围和发送的相邻转写。确认后才调用图像模型。没有可用模型时提示前往模型设置，纯文字纪要仍可生成。
5. 成功结果作为独立画面证据保存。用户可查看原帧、识别文字和说明、时间与不确定点，也可移除不准确证据。再生成纪要时，在原有确认中列出新增画面材料及文字接收方。
6. 纪要中的画面要点带来源时间，可打开对应本地要点；本地播放器可定位时跳到录屏对应时间，不能定位时如实保留时间与原帧。画面证据变更后旧纪要标记待更新。

## 模型与数据边界

模型中心增加可选 `meeting_visual_profile_id`，空值表示不启用视觉模型，不自动继承聊天模型。它可以与聊天或会议纪要选择同一已保存配置。解析、密钥和实际请求仍在 Companion 内；UI 只显示已去凭据的接收地址。

复用现有 OpenAI／Anthropic 图像输入传输能力，使用会议专用事实提取提示和严格输出检查。不得复用浏览器页面操控提示，不得将 metadata／passthrough fallback 或空、截断输出当成识别成功。图像能力不按模型名称推断：明确展示未验证、实际失败或已完成本次图像处理。模型选择不等于能力认证。

首版不新增跨平台 OCR 依赖。能独立验证的本机 OCR 是后续优化入口；先交付通过实际图片验收的可选视觉路径。图像模型负责提取画面事实，现有文字纪要模型负责与转写融合。

原始录屏继续留浏览器本地。发送音频或文字的旧确认不授权发送截图。屏幕文字、OCR、视觉说明均是资料，不能作为系统指令、工具调用或配置写入来源。

## 本地采样与存储

沿用 `desktop-meeting-media` 已授权视频轨道与 `recordScreenTracks` 录制起点。低分辨率帧差负责筛选候选，去除重复静态画面和短暂抖动；不把光标或小人像区域变化等同于整页变化。具体阈值由 PPT／代码／小数值样本验证，不引用通用电影切镜阈值作保证。

首版硬边界：每场最多 240 张、合计 32 MiB；单张最长边不超过 1600、编码后不超过 512 KiB；分析每次最多 12 张。超限停止保存新画面并显示最后覆盖时间，不静默删除前面的证据，不影响录屏本身。空图、编码失败、轨道未就绪和写盘失败单独计数并说明。

帧记录包含 `meetingId`、`recordingId`、稳定帧 ID、相对录制起点的媒体时间、尺寸、编码格式与原始图片 SHA-256。用媒体／采集时钟计算时间，不用模型完成时刻替代。记录和显示采样覆盖状态，不把整场时长当已理解范围。

浏览器录屏库升级为新增独立帧 store；旧录屏仍可列出和读取。删除某录屏时清除其关联帧。删除画面证据不删除原始录屏；删除会议时清除服务端关联视觉结果，既有独立录屏保留规则不被暗改。数据关联和不可恢复帧显示缺失，不能引用另一场会议的图像。

## 确认、任务与取消

准备视觉请求只提交图片元数据和哈希清单，不调用外部服务。返回的短期一次性确认绑定模型配置修订、模型／接收地址、meeting ID、所选帧有序清单与邻近转写快照。确认执行时校验实际图片字节与准备清单，不接受增图、换图、换接收方或跨会议复用。

图像在本机上传／验证后，按有界串行任务提取；显示逐帧成功、失败和剩余状态。请求有总预算、单次超时与 AbortSignal，不无界排队、不自动切换到其他接收方。用户取消、关闭对应任务或连接断开后不得继续发送后续帧；已完成结果保留实际部分范围，不冒充完整成功。视觉任务默认在录制结束后进行，避免挤占实时 ASR GPU。

外部错误不回显凭据、整张图片或服务端原始响应。旧任务晚返回不得覆盖新选择、其他会议或已经删除的证据。产品设置与 live config 不因测试或默认迁移而自动改写。

## 视觉证据与纪要

服务端保存独立视觉证据文件，包含帧 ID／哈希、录制时间、模型身份、实际状态、识别文字、事实说明与不确定项。图片字节默认只用于本次视觉请求，不另写服务端长期图片库。

不得向 `original-transcript.json` 或逐字稿追加模型描述。用户笔记、识别原稿、编辑稿和视觉证据保持各自来源。原始识别稿可回看；图片中的提示注入不能改变这些规则。

纪要输入指纹、准备确认、过期判断及保存后的 stale 检查加入视觉证据内容与稳定来源。没有视觉证据时保持旧文字流程和旧指纹兼容。合计材料仍受现有输入上限约束，不静默截断。

视觉材料使用专门标签／时间引用，不能把“页面展示的候选方案、计划或指标”直接认定为已同意决议、已分派责任或已完成事项。语音与画面冲突时列待确认，不擅自纠正原稿。默认纪要的可核对依据必须覆盖新增视觉来源；不能为通过输出而放松旧逐字稿依据检查。用户模板继续约束结构，不能扩大材料权限。

## 验收与发布

用同一受控录屏比较纯转写与视觉增强，记录画面事实召回、错误决议数、引用回查、耗时、帧数和实际发送量。样本至少包括静态 PPT、快速换页、代码滚动、表格小数字变化、图表且语音不复述、光标／人像噪声、语音与画面矛盾和来源撤销。采样必须记录漏掉的范围；稀疏截图不声明证明所有动作顺序。

测试须穿过真实浏览器同源录制、帧存储／旧库升级、预览选择、明确确认前零图片外发、真实图像模型提取、独立证据持久化及最终纪要引用。模拟 HTTP／模型用于协议和拒绝条件，不代替图像质量验收。缺少可实际使用的图像服务时明确阻塞该项，不把 mock 称为实测。

回归包括纯音频、外部 ASR 的原确认、停止最后分块、共享撤销、配额和写盘失败、取消／断线、跨会议帧与确认、旧任务晚完成、材料变化后过期、删除和模型改动。两端 typecheck、相关完整测试与生产构建、原有 Windows/macOS/Linux 原生 CI 按原 DoD 通过，再独立评审、合并、同提交发布预演和正式发行。

不改变当前 GPU 1.7.2 发布候选；本功能使用后续版本。Windows 本机 ASR 的 4080 SUPER 实测不算本功能的图像／视频理解实测。
