## 3. Local read contract

Read only `SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall`, direct children, on local HKCU and HKLM. On 64-bit OS use explicit read-only Registry64 and Registry32 views in fixed order HKCU64, HKCU32, HKLM64, HKLM32; on 32-bit OS open each hive's Registry32 once. Dispose every base/root/child handle in finally. No recursive key traversal, remote base key, hive loading, other-user impersonation, elevation or registry write. Missing root or concurrently deleted entry is ordinary absence. Access denial/other read failures preserve old candidate sources but produce the bounded incomplete summary below.

[Microsoft RegistryView](https://learn.microsoft.com/en-us/dotnet/api/microsoft.win32.registryview?view=netframework-4.8) documents separate 32/64 views and their alias on 32-bit OS. Explicit view selection is a discovery decision, not a new authorization source.

Read only DisplayName and DisplayIcon. Do not read or execute UninstallString/QuietUninstallString, and do not read InstallLocation for launch-path guessing or directory scanning. Accept raw REG_SZ/REG_EXPAND_SZ bytes as text with no environment expansion; other value kinds do not qualify. `%SystemRoot%` stays literal and fails drive-root eligibility, not expanded. A literal percent in a qualifying filename is not itself a command marker.

[假设: bounded native reader] A small fixed literal embedded C# interop in this existing PS script uses `RegEnumKeyExW` to fetch one child name per bounded call and `RegQueryValueExW` to query the length/type before bounded byte retrieval. No dynamic DLL name/source, generic registry framework, package or helper binary. This avoids materializing all child names via GetSubKeyNames/Get-ChildItem and avoids loading arbitrarily large values before checking their length. A bounded reader implementation with equivalent pre-allocation guarantees may replace these mechanics only after contract review; no unbounded API followed by `.Take()` masquerades as the same guarantee.

The key-name buffer is fixed 256 UTF-16 code units including termination; oversized/error result marks incomplete and is never resized/retried. Value retrieval has at most two calls (size/type then fixed capped buffer); mutation to larger/wrong type between calls is rejected without reallocation/retry. Decode exactly returned even byte length, accept optional single trailing UTF-16 NUL, reject embedded NUL/control characters or invalid UTF-16; do not assume the API supplies termination. [RegEnumKeyExW](https://learn.microsoft.com/en-us/windows/win32/api/winreg/nf-winreg-regenumkeyexw) specifies per-call enumeration and unordered keys; [RegQueryValueExW](https://learn.microsoft.com/en-us/windows/win32/api/winreg/nf-winreg-regqueryvalueexw) supports the size query and warns string termination is not guaranteed. Complete transport/compiler failure remains nonzero, not a success with unavailable metadata.

## 4. Finite literal DisplayIcon grammar

[假设: deliberately conservative supported grammar]

After removing outer ASCII spaces, admit either:

- A double-quoted full path, optionally followed immediately by comma + signed decimal icon index of one to six digits. No embedded/escaped double quote or text after the suffix. Quoting permits spaces and commas inside the path.
- An unquoted full path without whitespace or double quotes, ending `.exe`, optionally followed immediately by the same icon-index suffix. Commas inside the path are literal; only an anchored suffix after `.exe` is removed.

Examples: `C:\Apps\App.exe`, `C:\Apps\App.exe,-1`, `"C:\Program Files\示例,应用\App.exe",0`. Reject unquoted whitespace paths conservatively, trailing arguments, `"C:\App.exe" /quiet`, icons/DLLs/directories/missing files, relative/drive-relative/root-relative paths, URLs, UNC/device/extended namespaces, control characters and alternate-stream colons. Case-insensitive `.exe` check. No shell/Invoke-Expression/Start-Process/command parsing, no stripping arbitrary arguments, and no fallback to an uninstaller executable. A quoted pathname with characters such as `&` is just a full literal filesystem path; it is never invoked. Unsupported common unquoted paths with spaces are an explicit range limitation, not claimed supported.

Path must be absolute drive-rooted with backslashes, contain no `.`/`..` component, and be 1–1024 UTF-16 code units after suffix removal. Local-drive classification precedes existence probing; reject mapped remote/unknown/no-root drives. [假设: conservative local identity] Allow fixed/removable/CD-ROM/RAM local drive types; reject any reparse point in the path or its ancestors before following it. Read ancestors from root down and stop at first reparse, then require a regular existing non-reparse file. This is Registry-only conservative extraction, not a change to general apps.add symlink/UNC rules. It prevents a drive-rooted string from silently traversing a junction into a remote target. Do not claim physical-file identity or atomic freedom from filesystem mutation: subsequent selection still goes through actual existing add-flow canonicalization/signature/hash/guard gates.

DisplayName must be nonempty after trimming, at most256 UTF-16 code units, with no controls; otherwise omit that entry instead of inventing a fallback name or truncating user data. Existing `.exe` filename is a discovery candidate, not PE/main-program validation or launch permission. An inert regular `.exe` fixture tests this boundary without running the file.

## 5. New fixed Registry-only budgets and ordering

[假设: new product extraction limits, not measured throughput guarantees]

| Bound | Exact proposed value | Reason |
| --- | --- | --- |
| Child names considered across all views | 4096 | finite snapshot memory/work; no recursive scan |
| Native key-enum calls | at most4096 successes plus one termination/error observation per root (four roots max) | bounded native work, no arbitrary growth/retry |
| DisplayName raw data | 2048 bytes | capped query before allocation; final name256 separate |
| DisplayIcon raw data | 4096 bytes | literal path1024 + quotes/index headroom, no oversized-value allocation |
| Admitted Registry candidates | 512 unique paths | bounded new source output/UI, excludes duplicates already from earlier sources |
| Registry serialized candidate-array segment | 1,048,576 UTF-8 bytes, including brackets/commas | below existing16MiB runner envelope; actual JSON escaped-byte measurement |

**Aggregate stdout budget (R2 correction; original runner ceiling):** `M = 16,777,216` counts the complete actual stdout UTF-8 wire bytes, not only Registry or decoded characters. Define `W(payload)` using the actual existing compact JSON serializer/escaping and output encoding/emitter, including outer object/array delimiters, every comma/property separator, summary and actual emitted newline and any BOM/preamble. Determine/pin this wire overhead from the actual WindowsPowerShell5.1 producer test; never assume zero newline/preamble cost or change the encoding to make a calculation pass. If exact new-envelope cost cannot be established, retain the old-only fallback rather than append unbudgeted data.

Serialize/count the original old-source `{apps:[...]}` baseline once with the same existing emitter policy; call its complete wire cost `L`. Preserve every old row and its serialization, without shortening strings, clipping/reordering existing sources or adding a new old-source cap. If the baseline itself exceeds `M`, keep the original maxBuffer rejection (no Registry partial-success recovery). Otherwise reserve the exact maximum necessary valid finite summary property overhead `S`, including its comma/key/status/reasons/escaping. Registry admission space is `min(1,048,576, max(0, M - L - S))`; each proposed row must also satisfy the exact **whole-envelope** `W({apps:[old,new],registry_summary}) <= M`, accounting for the inter-source comma, standalone Registry segment brackets and actual JSON encoding. Count escaped bytes before append; the standalone Registry segment cap does not imply total safety. Do not repeatedly reserialize all legacy rows for each Registry row; bounded incremental accounting must be proved equivalent to the final whole serialization. Final serialization must still be checked before any output is written. Never slice JSON, increase maxBuffer or extend20s.

If a full-summary reservation cannot fit but a truthful fixed `partial/[OUTPUT_LIMIT]` summary with zero Registry rows can fit, emit unchanged old rows with that summary and skip Registry additions. A prevented first eligible row, or deliberately unattempted Registry scan because no admission space remains, can likewise return `partial/[OUTPUT_LIMIT]` with **zero newly admitted rows**; partial is not contingent on a new row having been admitted. If even the necessary truthful partial summary cannot fit while old-only wire output fits, emit the **exact original old-only shape** (no Registry row and no registry_summary). Absence then means null/unreported, never complete/unavailable. No fake “complete” note is substituted merely because its spelling is shorter. These optional-summary fallbacks preserve previously successful legacy output instead of turning an old valid result into maxBuffer failure. An old-only baseline over `M` still follows the unchanged rejection contract.

These values are conservative ceilings, not representative enterprise corpus measurements or a promise that4096 reads finish in20s. Native CI must prove ordinary owned fixtures under unchanged20s; actual timeout remains rejection. Registry values can exceed these proposed limits, hence pre-read size caps are necessary; the Windows documented size is not a safe allocation limit. [Registry size limits](https://learn.microsoft.com/en-us/windows/win32/sysinfo/registry-element-size-limits).

Stop enumeration when a key/candidate/output budget prevents further complete processing; return admitted prefix and an honest partial summary. Limits must reserve JSON separators/escaping before appending, not slice completed JSON, truncate strings or corrupt UTF-8. Unsupported/malformed entries are normal omitted metadata; oversized values/fields that exclude otherwise inspectable entries set VALUE_LIMIT. At exactly a numerical boundary, if exhaustion cannot be proved within the allowed call observations, report partial conservatively; do not claim completeness from a full budget.

Keep running then StartApps candidates first with existing case-insensitive identity dedupe. For Registry, fixed hive/view precedence above; sort the bounded names captured within each view by ordinal-ignore-case with ordinal tie-breaker before value extraction. The first eligible path wins among that bounded snapshot. Final Registry path keys use the same lowercase absolute-path identity as existing collector; no AUMID or bundle ID comes from Registry. Duplicates from earlier sources do not consume new candidate/byte budget. Native key enumeration is unordered and concurrent edits are possible: stable precedence/sorting does not promise a globally complete or atomic registry snapshot at a cap. At caps the omitted subset can vary; summary discloses incompleteness.
