## Authority and six read methods

Move the exact six prototype method names into the sole `desktop/capabilities.ts` source: system.ping, thread.list, thread.peek, mcp.list, skill.list, knowledge.list. Issue snapshots this frozen set and a version value initially 1; a renderer cannot upgrade it. Registry retains bootstrap 30s, challenge 10s, capacity 64, 32-byte secret, 16-byte capability ID and HMAC-SHA256 canonical domain from the approved plan. No additional grant family, durable token, permission preference or security confirmation dialect is introduced.

A dedicated `/desktop` WS route uses the existing loopback HTTP listener and frame-size cap, but a separate WebSocketServer({noServer:true}), connection/auth map and desktop handler. Convert the existing legacy WSS to its own noServer instance and register exactly one HTTP upgrade dispatcher: only exact `/desktop` with exact native Origin `cmspark-desktop-native://local` goes to desktopWss.handleUpgrade; all other paths go through the unchanged legacy origin verifier and legacyWss.handleUpgrade. Reserve this path: legacy origins on it fail. Desktop sockets never enter legacy wss.clients/wsAuth/clients, even before authentication, and legacy sockets never enter desktopWss. Branching inside a shared WSS connection callback is insufficient because automatic client enrollment already happened. Preserve the shared listener readiness/MCP startup/close order and all other existing legacy paths, resolver and authentication. Native Origin is merely routing: a local process can spoof it, and only the registry-issued proof grants access. A desktop-looking surface field or pairing secret alone never suffices. Do not add desktop to surfaceFromOrigin or the permissive summoner helper.

Native protocol is strict JSON with these exact auth frames. Server's first message is `{type:"desktop.challenge.request"}`; native replies `{type:"desktop.hello",capability_id,protocol_version:1}`. Server replies `{type:"desktop.challenge",capability_id,connection_id,protocol_version:1,nonce}`; native reconstructs the approved JSON-array signing input and replies `{type:"desktop.authenticate",capability_id,protocol_version:1,proof}`. Capability, connection ID and nonce are lowercase ASCII hex generated by daemon; connection ID belongs to the actual socket. Unknown keys/types, duplicate singleton fields, mismatched negotiation, unknown/unissued/revoked/expired IDs, foreign/replayed proof and app requests before auth fail closed. Initial auth deadline uses the existing challenge 10s budget, not an unbounded extra hello timer. Server emits `{type:"desktop.ready",protocol_version:1}` only after registry authentication. Native code owns all auth frames; renderer sees none of their fields.

Post-auth requests reuse the six method type names and an optional string `id` correlation; only thread.peek also accepts a nonempty existing `thread_id`. No surface, trust, config, grant, credential, mode or arbitrary operation fields are accepted. Request correlation uses existing WS ID constraints; thread IDs use existing thread validation. Runtime verifies exact principal/method before and after awaited reads, so disconnect/revoke/reconnect cannot deliver stale results. Errors are finite desktop error codes without secret-bearing exception bodies. No method falls through to the general message router. No unfiltered server push, config.updated, confirmation, tool or chat stream reaches this socket. The sole daemon-to-native controls are strict `{type:"desktop.window",view:"compact"|"workspace"}` and `{type:"desktop.close"}` frames, sent only by the trusted launcher directly to its current authenticated native connection. Verify live exact principal/host ownership at send and receive; never use legacy broadcast, accept a renderer-provided target or remint. Repeated explicit tray desktop.open uses desktop.window to focus/change the existing host; explicit daemon shutdown uses desktop.close. Unknown keys, stale replaced host, disconnect and renderer attempts to send these controls are rejected. These frames control only window lifecycle, not business operations or approval.

Projection is key allowlisting, never object spread. Text remains untrusted; use existing secret redaction where text is displayed and render only text or existing sanitized Markdown. Reuse existing rail cap 64 and thread.peek 2000-character distilled preview cap; report `truncated` when capped. No raw message transcript or tool argument/result DTO is added.

## Trusted launcher: exact new internal operation

Add internal `desktop/host-launcher.ts`, available only to daemon runtime. Existing authenticated local tray may request `desktop.open` with only optional correlation id and view `compact` or `workspace`; native hotkey calls the same launch operation. Actual lifecycle-stamped surface must be tray AND Origin must be the exact tray sentinel. Extension/panel, summoner, desktop read channel, HTTP, MCP and renderer cannot call it. This command requests a window, not a mint API: response is finite launch/ready/error state, never bootstrap/session/secret/pipe/PID. Concurrent opens share one in-flight launch promise before any issuance; subsequent opens focus or change view of that same host. View changes never remint or widen methods. Existing Chromium shell remains an explicitly separate restricted fallback; native failure must be visible and must not silently invoke it.

Mint only after locating and integrity-verifying the bundled native host and launcher addon. A local C Node-API addon, loaded into the daemon (not node-addon-api or a secret-forwarding helper process), creates the anonymous bootstrap pipe and launches the intended host. Windows uses CreatePipe plus STARTUPINFOEX/PROC_THREAD_ATTRIBUTE_HANDLE_LIST with only the intended bootstrap read handle and separately declared process-liveness handle. Clear inheritance before WebView2 starts any renderer children. macOS uses close-on-exec and explicit posix_spawn file actions; only intended child bootstrap descriptor survives exec. Close parent duplicates promptly. Sibling and descendant inheritance tests are mandatory; Node spawn stdio arrays are not accepted as proof. The inspected official Node22.23.2 libuv Windows process source uses STARTUPINFOW/CreateProcess with inheritance enabled and no handle allowlist.

Bootstrap is one bounded JSON record followed by EOF, native-only: capability_id, secret, loopback desktop WS URL, protocol_version, issued_method_set_version, plus Windows-only parent_handle as a canonical unsigned decimal handle representation. The launcher serializes the already-inherited SYNCHRONIZE-only actual-parent handle value into this nonsecret field; it is never discovered by handle scanning, argv/environment, supplied PID or OpenProcess lookup. Child rejects missing/noncanonical/invalid/not-process/wrong-access handles and binds exactly the allowlisted inherited handle; no DUP/VM/TERMINATE access or alternate parent is accepted. New parser envelope limit 4096 bytes is explicit and must be approved with this contract. Values never enter argv, environment, URL query, renderer, file, clipboard or logs. URL is exact local listener endpoint, not caller-selected. Native consumes/closes the bootstrap endpoint before creating WebView; only native memory holds its credential afterward. Registry-owned mutable key is zeroed on revoke; no claim to erase immutable JS strings, OS buffers or every native copy.

Addon/native monitor actual owned process handles and daemon lifetime, not renderer pagehide, guessed PID polling or unrelated process matching. Windows grants child only SYNCHRONIZE access to a duplicate of the actual parent process handle; Mac observes its actual parent and registers parent-exit observation before processing bootstrap; a parent exit or reparent race refuses bootstrap rather than accepting launchd/new parent as issuer. Host closes on daemon death; daemon revokes/closes sockets on normal child exit, crash, kill, spawn error and explicit close. Native close exits this host; late exit callbacks cannot revoke a replacement host. Failed launch revokes before releasing singleflight. Fresh daemon discards registry. A live host reconnects only with a fresh nonce/new connection ID; close immediately invalidates its previous principal and cancels only origin-owned confirmations through existing manager. No confirming/writing operations are exposed in this issue.

## Native document and platform artifacts

macOS host is Swift AppKit/WKWebView, native URLSessionWebSocketTask and CryptoKit. Windows host is Win32 C++/WebView2, WinHTTP WebSocket, BCrypt HMAC and system JSON APIs; no .NET runtime, Electron/Tauri, new npm wrapper or copied Chrome profile. Native bridge validates expected main-frame document generation AND exact pinned bundle origin for every request/reply; document navigation invalidates outstanding renderer requests. Pin macOS cmspark-desktop://app/ bundle-only scheme; Windows https://cmspark-desktop.invalid/ bundle-only virtual-host mapping with restrictive access; the only main-frame document is the exact https://cmspark-desktop.invalid/index.html file, not a directory-index fallback. Navigate, main-frame start/completion, renderer Source and the HTML response key bind to that exact document URL; CSS/JS remain relative to the unchanged origin base. No file/http/remote navigation, path traversal, subframes, new windows, downloads, external scripts or production DevTools. Host exposes no auth/mint/confirm response API to JS. Explicit external links use native validated user-action opener; URL navigation never carries privileged document identity. Native bridge allows only six read methods and local compact/workspace layout changes. Responses are JSON-encoded into an owned document callback, never script-string interpolation from content.

Bundled HTML/CSS uses the existing accepted paper/ink visual language, visible conversation/resource navigation, 1040x760 workspace, 360x420 compact and 760px layout breakpoint from parent. It is a read-only view with explicit empty/error/offline states, conversation preview and resource lists. Do not reuse the legacy complete summoner HTML with hidden live chat/write/HTTP endpoints. Same visuals do not imply writable functionality. No default App/browser replacement or live config migration during development/tests.
