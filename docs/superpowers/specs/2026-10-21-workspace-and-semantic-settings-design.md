## 原始需求与交付边界

用户允许重新考虑整体布局、主界面和功能菜单，必要时推翻原布局，但必须先看到设计稿与设计理由。用户同时指出“一句话改设置”应有 AI 语义理解，提供可能符合意图的设置候选。

此前已确认的业务基线：外部聊天应用无接口，通过指定 APP 的截图、OCR、语义理解、后台定时采集生成候选待办；用户整理确认；统一查看来源、截止时间、处理与反馈，并按确认规则提醒。

本次交付：可交互的静态设计稿、菜单迁移映射、语义设置行为草案及交互核对。所有人名、消息、事项、连接状态及设置值均为示例。候选方案为预设演示，没有调用模型、采集聊天、发送消息或修改真实配置。

源稿：[workspace-design.html](../../design/prototypes/2026-10-21-workspace-design.html)；[设计评审与验证记录](../../audit/reviews/2026-10-21-workspace-design-review.md)。源稿由会话的交互预览环境呈现，独立打开需要相应的预览包装；它不是已接入产品的页面。

## 每个界面先回答的问题

| 界面 | 首要问题 | 核心动作 |
| --- | --- | --- |
| 今日 | 今天什么需要我处理或反馈？ | 打开事项或整理候选 |
| 待办 | 谁交代了什么、何时向哪里反馈？ | 整理、跟进、确认处理/反馈状态 |
| 对话 | 我现在要完成什么工作？ | 发消息、添加上下文、继续执行 |
| 资料 | 我的工作材料在哪里？ | 打开知识、会议、文件和网页上下文 |
| 活动记录 | 哪些应用在被采集，覆盖到哪里？ | 暂停/恢复、核对采集范围和证据 |
| 设置 | 怎样让 CMspark 更符合我的工作方式？ | 描述目标、比较候选、核对后应用 |

## 整体布局与选择理由

已确认按入口分工：完整工作中心首次进入“今日”，浏览器侧栏首次进入“对话”；后续恢复用户上次位置。正式实现复用扩展完整工作页与现有会话能力。

完整工作区采用有文字的左导航、主内容区和按需出现的来源详情。导航只放长期工作目的地：今日、待办、对话、资料、活动记录；设置固定在底部。模型、技能、MCP 等是使用或配置能力的入口，不与所有工作目的地平铺。

来源是 CMspark 的关键内容：每条事项显示 APP/群/提出人，详情进一步显示消息时间、原文、截止、提醒、处理和反馈去向。来源信息不用只藏在悬浮提示中。处理完成和反馈完成分别记录，防止遗漏“做完以后回群里反馈”。

窄侧栏保持单列对话、上下文选择、少量当日事项和打开工作中心的入口。完整筛选、批量整理与来源比较进入完整工作页。停止执行、待确认、录制反馈优先于普通提醒；业务迁移不能破坏现有安全和会话归属。

采用 taste 的 `achromatic-ledger` 方向，seed `20261021`，保留项目系统字体、中性底色、炭黑主动作和既有焦点/链接色。主界面的识别特征是“事项旁边的来源和反馈链”，无需额外展示数据图表或装饰性指标。与抽样样式的不同之处：保留短连接状态栏，用于真实后台状态和窄屏导航；不采用财务页的数字字体、统计卡和问候式标题。

### 为什么这样取舍

1. 按用户的工作目的组织入口，可减少在工具名称之间来回查找。
2. “今日”只是待办的筛选投影，同一事项在不同视图共用身份，不复制第二套业务记录。
3. 来源详情贴近事项，减少用户回忆“谁在哪个群说的”的负担。
4. 宽屏用于并排核对，窄屏只显示列表或详情中的一个区域，保持文字和控件可读。
5. 保留对话作为核心工作入口；个人待办的引入不夺取正在进行的对话，也不把 Agent 执行清单混为个人事项。

## 功能菜单迁移映射

| 现有能力 | 提案入口 | 必须保留 |
| --- | --- | --- |
| 新建、最近、搜索与管理对话 | 对话；主导航保留继续工作快捷入口 | 标签/分组、归档、回收站、批量操作、现有共享数据源 |
| 浏览器标签页 | 对话的添加上下文；资料中的完整入口 | 明确区分浏览器标签页与对话标签 |
| 知识、知识图谱 | 资料 → 知识 | 导入、整理、关系来源、全文列表及图谱访问 |
| 会议 | 资料 → 会议 | 开始/停止、导入、转写、笔记、纪要、导出、说话人和模板；录制时全局一键返回 |
| 附件、导出和生成文件 | 资料 → 文件；对应对话中的原入口 | 文件归属和保存结果 |
| 技能、场景与专家 | 设置 → 本机与工具；对话中的本次能力选择 | 当前对话使用与全局安装配置分开 |
| MCP、应用 | 设置 → 本机与工具；对话中的本次能力选择 | 连接、安装、授权和状态不能因重排菜单改变 |
| 现有任务板 | 对话 → 执行记录 | facts/intents/hints 与真实执行归属，不直接改名为个人待办 |
| 代码与终端 | 对应对话的工作区和执行记录 | 会话、文件、终端和结果归属，停止与确认 |
| 现有八类设置 | 设置中保留原类别与稳定深链 | 草稿、独立保存、权限、配对、许可、下载等原有流程 |
| 新增待办、督办及提醒 | 今日/待办；设置 → 待办与提醒 | 用户确认、来源、责任、时间与反馈去向 |
| 新增记录服务 | 活动记录；设置 → 记录与隐私 | 采集边界、敏感排除、暂停、清理、故障与最近成功时间 |

设计稿用文字反馈演示资料和能力入口的位置，没有重做会议、知识图谱、编程及权限流程。正式实现必须逐入口验证，不能把说明文字当作这些流程已实现。

## 语义设置：从体验目标到候选方案

用户表达的是目标或症状，而不必知道精确设置名。例如“少打扰我，但别漏掉重要待办”可以对应不同提醒策略。系统应先给可比较的解释，而非直接选择一个开关写入。

拟议流程：

1. 接收用户描述及必要上下文，读取允许编辑的设置目录、脱敏当前值、能力状态和依赖。
2. 模型生成受 schema 约束的候选方案：意图解释、设置 ID、建议值、理由、范围、代价和前置条件。
3. 本地校验设置键和值、互斥关系、可用能力、权限和当前配置版本；无效建议不进入应用流程。
4. 有多个合理解释时展示候选；缺少关键条件时提出澄清问题。
5. 用户选择方案和具体项目，查看当前值与建议值及其影响。语音识别结束只填入描述，不自动应用。
6. 用户确认后沿用各设置既有保存和授权流程，读取并核对实际结果，分别显示成功、失败、待完成和未知状态。

### 三个交互样例

- **提醒目标**：重要事项即时、每天两次汇总、仅临期提醒。应说明哪些提醒被延后以及系统通知权限/免打扰的影响，不能承诺绕过操作系统。
- **聊天隐私**：严格本地处理、本地采集后人工整理、只禁止原图外发。明确区分原图和 OCR 文本；本地模型不可用时不能默默退回云端。
- **语音错字**：开启识别后纠错、尝试本机识别、先检查设备。说明模型数据范围、额外处理时间以及单独下载/启用的前置步骤，不能承诺换引擎一定更准确。

设计稿使用明确标注的预设样例模拟这些候选，任意其他输入进入澄清示意；该机制不是正式语义服务，不作为 AI 能力实现证据。

### 状态与约束

- 输入、生成中、候选、变更草稿、应用中、已核对保存、部分成功、失败、结果未知分别建模。
- 模型未配置、离线或失败时保留输入及普通设置浏览，不用规则命中伪装 AI 推荐成功。
- 用户对某些变更取消勾选后，只应用剩余项目；下载、许可、配对、密钥和信任等操作单独完成。
- 候选生成期间配置已变化，必须重新读取并核对差异，不能用旧建议覆盖新设置。
- 保存失败保留草稿；部分成功逐项展示。未知结果先查询实际状态，不盲目重试副作用。
- 撤销只用于可逆且有明确旧值的设置，仍需校验当前状态；权限、安装和外部副作用不承诺通用撤销。
- 不向语义模型发送真实密钥、凭据或与理解设置无关的聊天原文。
- 重要事项分类、免打扰例外、默认提醒规则目前仍是待设计的产品能力，不能把示例值描述为当前已存在配置。

## 视觉、可访问性与响应式

沿用根 DESIGN.md：系统无衬线字体，14px 正文、13px 来源和标签、12px 辅助说明，24px 页面标题，4px 基础间距。中性导航、细分隔、克制背景层级；颜色用于状态和焦点，状态同时有文字。无外部字体、装饰图片、渐变或自动入场动画。

宽屏以事项列表与来源详情并列；中屏折叠主导航；390/320px 单列，点击事项进入详情，可返回列表。设置候选由横向三列改为纵向排列。预览使用原生按钮、表单、输入和复选框；键盘焦点可见，更新回执使用适当 live region。正式弹层需要按原有 Modal 合同验证 Escape、初始焦点及焦点返回。

## 技术与实施约束

这是设计阶段，没有添加前端运行依赖。shadcn/ui Nova 与 Lucide 可在后续代表切片中验证；不能仅为换皮整体替换 React/Plasmo、状态管理、传输、确认管理器或数据库。Motion、可调分栏、拖拽库和 Zustand 按实际需求另行决定。

新增个人事项、候选和提醒应由 Companion 持有同一权威状态；完整页、侧栏和桌面入口只投影同一数据，不各建独立业务副本。
