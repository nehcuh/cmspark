### Key finding on caret-blink

Single cell flip in 64×64=4096 grid: identity = 4095/4096 = **0.99976** (>0.99, >0.999, <0.9999); variance ≈ (1/4096)×(255−mean)² ≈ 15.87 → stdev ≈ **3.98** (>1.0). 

**Pi's original worry is correct**: OR trips on caret-blink via id≥0.99 even when stdev is low; AND does NOT trip because stdev rises above 1.0 with even a single cell flip. Grok's "OR + tighter id 0.999" doesn't help — 0.99976 > 0.999 still FP. Only id≥0.9999 escapes caret-blink, which is exact-match-only and useless for real frozen-contentful detection.

### Frozen-contentful is a separate threat class

High stdev + identity≈1.0 — neither AND nor OR-with-sane-threshold catches it. Right detector is **temporal** (3+ consecutive identical captures, or ANR probe). P2's per-frame classifier is the wrong layer.

### Decision: Option A

1. Pi's original threat (occluded blank) — fully caught by AND.
2. Caret-blink — AND correctly skips; OR over-flags. Dev workflow (terminals/editors/IDEs) has constant carets — OR FP cost is real and ongoing.
3. Frozen-contentful — defer to temporal detector in later iteration.
4. Grok's "tighter-id OR" doesn't escape caret-blink at any usable threshold.

R1 **partially closed** by P2: blank/occluded + 0-byte/dim + CGContext-draw covered. Frozen-contentful open as follow-up (not a P2 blocker).
