### 4. Recursive restart with args.driftRestarted — depth=1 proof
Re-derived from §4.3.1 + §4.3.3 against locate-chain.ts:196-206:

- Outer call: `args.driftRestarted` unset/undefined → `restarted = false`.
  `rect0` snapshot at chain entry; per-layer guard fires on drift.
- `restartChainOnce()` checks `restarted` (false on outer) → captures fresh,
  releases old, recurses with `{...args, shot: fresh, driftRestarted: true}`.
- Inner call: `args.driftRestarted === true` → `restarted = true` at line
  one. Any second drift inside the inner call → `restartChainOnce` throws
  STALE_SCREENSHOT.

Max recursion depth = 1, proven by args-flow alone (no closure state). The
closure-scoped `let restarted = false` would have reset on each recursive
entry — Grok blocker 2 is real and the args-bound fix is the correct
resolution. Agree with the design.

One sharpener for the implementer: the existing `staleOnNotFound?: boolean`
arg is already in the type; `driftRestarted?: boolean` joins it cleanly.
Do NOT couple them — a restart-from-drift carries `staleOnNotFound:true`
cooperatively, but they are independent dimensions.

### 10. Anything missing that would let a regression slip?
Three small items, none blocking:

(a) **witnessVerdict survives restart.** On L0 drift-restart, the inner

(b) **L1 OCR path: same rect0 discipline.** Brief §4.3.2 lists L1 OCR
    success return at line 422 AND L1 OCR re-probe at line 446. Both
    return after a `shot = fresh` A1 re-capture at line 417-420 / 437-444.
    The drift guard fires AFTER that fresh re-capture, so rect0 vs the
    fresh shot.rect is the right comparison. Implementer: ensure the guard
    is placed AFTER `shot = fresh` (not before) on these paths, or the A1
    re-capture itself trips the guard spuriously.

(c) **L2 TinyClick path: no A1 re-capture.** Line 467-491 has no
    `trackCapture` between chain entry and return. The drift guard here
    compares the original entry shot.rect to rect0 — trivially equal, so
    the guard never fires. This is correct behavior (no drift possible
    without an intervening capture), but the test plan should include one
    L2 case where the WINDOW moved without chain re-capture to prove the
    guard still fires when `shot.rect` is mutated externally. (Currently
    impossible — `shot` is `const`-ish inside the function — but the
    invariant is worth pinning.)

These are implementer reminders, not blockers. The plan is sound.
