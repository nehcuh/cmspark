F1 [NIT] Post-spawn TOCTOU check is forensic-only for one-shot CLI
---------------------------------------------------------------
File: companion/src/host-use/darwin/host-integrity.ts:143-150

spawnHostBin's post-spawn inode/dev comparison runs AFTER
execFileAsync resolves — i.e. AFTER cmspark-host has already
executed and returned its stdout. If substitution happened
between the pre-spawn hash check and execve, the substitute
binary already ran with the privileges of the spawning process.

Contrast with swift-tray-bridge.ts:182 — there `this.kill()`
terminates the long-running tray daemon post-detection, which
is preventive (the daemon would otherwise keep running). For
a one-shot CLI, there is no "keep running" state to abort.

The PROTECTION is the pre-spawn hash check (catches
pre-existing substitution). The post-spawn re-stat is a
forensic tripwire only — surfaces the attack for logging but
cannot prevent the substitute from having executed.

Prompt explicitly required mirroring the swift-tray pattern,
so this is not a deviation. Documenting the asymmetry so
future reviewers don't over-trust the post-spawn guard.

Recommended fix (optional, post-G1):
  Add a one-line comment to host-integrity.ts:143-150 noting
  that the post-spawn re-stat is forensic for one-shot CLI
  (substitute already executed); preventive layer is the
  pre-spawn hash check. Mirrors swift-tray-bridge.ts:176-184
  pattern by policy, not by protective equivalence.

Severity rationale: not BLOCKER because (a) prompt required
the mirror, (b) pre-spawn hash check is the load-bearing
defense and IS preventive, (c) no regression vs. v1.3 Batch 1.

F2 [NIT] ComputerErrorCode union missing SKYLIGHT_* / CGEVENT_*
---------------------------------------------------------------
File: companion/src/computer/types.ts:151-185

The union type ComputerErrorCode does not include
SKYLIGHT_SPI_UNAVAILABLE, SKYLIGHT_POST_FAILED, or
CGEVENT_CONSTRUCT_FAILED. The binary emits these codes;
assertInjectOk constructs `new ComputerError(parsed.error_code
?? "INVALID_ACTION", ...)` (darwin-adapters.ts:78).

This compiles only because parsed is typed Record<string, any>
— `parsed.error_code` is `any`, bypassing the union check at
the constructor boundary. Runtime is fine (tests pass; the
.code field is a plain string on the wire). But:

  - A typo in a future error code (e.g. SKYLIGHT_SPI_UNAVAILBLE)
    passes typecheck silently.
  - exhaustive switch statements over ComputerErrorCode won't
    include the SkyLight codes — if executor.ts ever adds a
    switch (err.code), it will hit `default` instead of a
    dedicated branch.

Recommended fix (post-G1):
  Add the 3 codes to ComputerErrorCode union:
    | "SKYLIGHT_SPI_UNAVAILABLE"
    | "SKYLIGHT_POST_FAILED"
    | "CGEVENT_CONSTRUCT_FAILED"
  Tests already pass; this is pure type-safety hardening.

Severity rationale: NIT because runtime contract is correct,
only static type discipline is weakened. No production
behavior change.

---------------------------------------------------------------
Q1: Are the 3 distinct error codes correctly partitioned?
---------------------------------------------------------------
YES. The partition is semantically correct:

  SKYLIGHT_SPI_UNAVAILABLE — dlopen/dlsym failed ONCE per
    process; binary cannot post any events on this OS.
    LLM action: surface upgrade prompt to user.

  SKYLIGHT_POST_FAILED — SPI resolved but a specific post
    returned false. Indicates per-event delivery failure
    (target PID dead mid-batch, render process crash, etc.).
    LLM action: retry with fresh window-list lookup.

  CGEVENT_CONSTRUCT_FAILED — CGEvent constructor returned
    nil. Indicates resource exhaustion or invalid coords
    (negative large ints, etc.). LLM action: abort —
    coordinates likely malformed.

Collapsing SKYLIGHT_POST_FAILED and CGEVENT_CONSTRUCT_FAILED
would lose actionable signal: post failure suggests retry,
construct failure suggests malformed input. The split is
worth the 2 extra tokens in the error_code string.

The fail-fast at dispatch (host.swift:544) ensures
SKYLIGHT_SPI_UNAVAILABLE returns before any CGEvent
construction — so the per-call codes can NEVER be emitted
when SPI is unavailable. Clean state partition.

---------------------------------------------------------------
Q2: Does assertInjectOk() introduce silent failure modes?
---------------------------------------------------------------
NO. Comparing against the previous inline pattern
(parseComputerJson + checkOk at each call site):

  - assertInjectOk is a strict composition of the same two
    helpers, in the same order, with the same label propagation.
    Test "F9: parseComputerJson + checkOk compose to same
    behavior as assertInjectOk" (computer-darwin-inject-contract.test.ts:100-112)
    pins this equivalence.
  - The label argument defaults to "inject" if omitted — same
    default the inline pattern used implicitly.
  - No try/catch swallowing — rethrows ComputerError verbatim.

The only behavioral difference is the binary's stdout now
gets parsed even on nominally-successful spawns. The previous
inline pattern in some inject methods (e.g. click() pre-swap)
also parsed + checked; this is just factored out. No silent
failure introduced.

Q3: TOCTOU gap in spawnHostBin vs swift-tray-bridge.ts?
---------------------------------------------------------------
NO new gap; same design as swift-tray-bridge.ts. See F1 above
for the forensic-vs-preventive asymmetry documentation suggestion.

The implementation correctly mirrors:
  - open fd → sha256 from fd (not path) — closes stat/read race
  - spawn via realpath (pre.realpath, not bin) — closes
    path-substitution TOCTOU between hash and exec
  - post-spawn re-stat — surfaces substitution during the
    hash→execve window

No additional gap introduced. The hash check covers the
"binary was substituted before we looked" case; the realpath
spawn covers the "symlink swap between hash and exec" case;
the post-stat covers the "substitution during execve" case
(forensic only).
