**Fixes applied** (per Claude Code + Grok final reviews):

1. **Null-safe dlsym** — `unsafeBitCast(dlsym(...))` without null check could produce `.some(fn@0x0)` and crash on first call. Fixed: guard `if let sym = dlsym(...)` before cast.

2. **Failure propagation** — 7 swap sites at `host-skylight.swift` inject paths discarded `slPostToPid` Bool with `_ =`. Fixed: each now `if !slPostToPid(...) { return cuError("SkyLight SPI post failed", code: "SKYLIGHT_SPI_FAILED") }`. Also fail-fast at the dispatch level if `cuResolveSkyLight()` returns false.

3. **Dead variable removed** — `slPostEventRecordToFn` was resolved but never called, and signature was likely wrong (yabai/cua treat as event-record SPI, not `(pid_t, CGEvent?)`). Removed. Documented at declaration site as deferred work.

4. **RTLD_GLOBAL → RTLD_LOCAL** — single-shot CLI doesn't need symbol leakage. Tighter.

5. **Right-click mouseType fix** — was using `.leftMouseDown/.leftMouseUp` even when `btn == .right`. Now uses `.rightMouseDown/.rightMouseUp` when `action == "right_click"`. Critical for non-Chrome targets too.

6. **Threat model corrected** — line 9 falsely claimed S-P0-2 was "mirrored at host-bin.ts". host-bin.ts only does path resolution (S-P0-1); spawn at adapter.ts:138-144 is bare execFile with no integrity check. Rewritten with explicit table showing asymmetric coverage (tray has S-P0-2, host does not).

7. **Library validation A/B result (NEW FINDING)** — Built two binary variants: flip=true and flip=false. Both resolve `SLEventPostToPid=true` on Tahoe 26.5.2. **Confirms Grok's hypothesis**: Apple library validation allows loading Apple-signed dylibs, SkyLight is Apple-signed, so flip is NOT required. Production target is `cmspark-host-skylight-nolibval` shape — preserves full v1.3 Batch 1 hardened-runtime + library-validation lockdown, no S-P0-2 regression.
