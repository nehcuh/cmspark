## Q2 — Hard error without F6?

**Policy:** Acceptable for permanent unavailability (unsupported OS / SPI removed). Matches adversary’s “no fallback” option (adversary:405–414). D6 keeps a future L2 HID path if Tahoe transient rates force it (plan:50, :188).

**Availability:** Yes, pure hard-error can regress availability on **transient** SPI failure on supported OSes—no retry. That trade-off is intentional and defensible for v1.3 **if** failures are near-zero on Tahoe.

**Contract is not sufficient as implemented:**

- Plan claims companion surfaces `error_code` for LLM messaging (plan:186–187).
- Inject path collapses failures to spawn errors only; structured `cuError` with `error_code` (`host.swift:517-520`) never reaches `ComputerError` with that code.
- `rethrowDarwinExecError` always uses `INVALID_ACTION` (`computer/darwin-adapters.ts:82-86`).
- Message “requires Tahoe 26.5+” is wrong for Tahoe users with transient SPI failure.

**Must add during plan fix / implementation:** after inject, `parseComputerJson` + `checkOk` (or equivalent) so `SKYLIGHT_SPI_FAILED` becomes a typed `ComputerError`, with copy branched on OS vs generic SPI failure.

## Q3 — F7 first + auto-rewrite: git-diff sound?

**Order is mechanically sound for N7** (plan:315–318): build script exists before integrity gate; F1 rebuild rewrites constant.

**Yes, local build dirties git.** F7 in-place sed/perl on `host-integrity.ts` (plan:198–201) means every `build-host.sh` run mutates a tracked source file. Developer must commit that constant with any intentional host rebuild—or stash/discard accidental rebuilds. Tray today only *prints* the hash (`build-tray.sh:71-72`); auto-rewrite is better for forgetfulness, worse for dirty trees.

**CI tension (N3 residual):** `companion/dist/` is gitignored (`.gitignore:13`); binary is not the oracle. “CI runs `build-host.sh` + asserts `host-integrity.ts` updated” (plan:203–206) conflicts with non-reproducible codesign (plan:206, adversary:433–437): CI rebuild may produce a different SHA than the developer’s committed constant. During implementation, CI should be either:

- **(A)** “if `host.swift`/`host.entitlements` change → `host-integrity.ts` must also change in the PR” (no CI rebuild of SHA equality), or  
- **(B)** CI rebuild only checks post-build `hash(binary) === constant` in *that* workspace (not equality to developer’s machine).

Do **not** require developer SHA == CI SHA until D8.

## Q6 — Verdict

### **MODIFY BEFORE IMPLEMENTATION**

Required plan patches (block start):

1. **F5 path** → `companion/src/computer/darwin-adapters.ts` inject sites (~497–559); drop `ensureForeground` only there.
2. **F4 scope** → integrity must cover computer-use spawn (shared helper used by both `defaultDarwinRunner` and `computer/darwin-adapters`, or check inside `resolveHostBinary` / a single spawn wrapper).
3. **Failure contract** → inject must parse stdout `{ok, error_code}` and throw typed `ComputerError("SKYLIGHT_SPI_FAILED", …)`; LLM copy must not always say “upgrade to Tahoe.”
4. **TCC recovery** → `tccutil reset Accessibility com.cmspark.host` (match `host-Info.plist:6`).
5. **CI SHA** → choose (A) or (B) above; do not claim cross-machine SHA equality.
6. **Plist** → explicitly keep `LSMinimumSystemVersion=14.4`; document support matrix (host apps vs SkyLight inject).

**Conditional during implementation (after patches):** CGEvent nil → `CGEVENT_CONSTRUCT_FAILED` (plan:70); Stage 3 remove `CMSPARK_SKYLIGHT_FORCE_FG` (plan:72–73, :238); auto-rewrite fail-closed on sed miss (plan:201); G1 Chrome step load-bearing (plan:225); partial-sequence recovery docs (plan:250); developer note that `build-host.sh` dirties `host-integrity.ts`.

**Not reject / not re-research.** C-minus shape, N2 removal, Tahoe-only claim, F7-first order, and honest G2 tests are sound.
