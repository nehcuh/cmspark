## Q1 — Error code taxonomy: keep three, do not collapse

**Answer: Keep the three-way partition. Do not collapse `SKYLIGHT_POST_FAILED` into `CGEVENT_CONSTRUCT_FAILED`.**

| Code | Meaning | When it fires | LLM action |
|---|---|---|---|
| `SKYLIGHT_SPI_UNAVAILABLE` | Resolve failed (dlopen/dlsym) | Dispatch-level fail-fast before CGEvent construction | Permanent for this OS: upgrade / unsupported |
| `SKYLIGHT_POST_FAILED` | Bound SPI present but post helper returned false | Defensive: `fn == nil` or `event == nil` after resolve | Transient / internal — retry once; do **not** say "upgrade OS" |
| `CGEVENT_CONSTRUCT_FAILED` | `CGEvent(...)` returned nil | Construction site before post | Rare system pressure; distinct from SPI |

**Honesty note** `[inspected]`: `SLEventPostToPid` is `Void`. `slPostToPid` only returns `false` when `fn` or `event` is nil:

```swift
func slPostToPid(_ pid: pid_t, _ event: CGEvent?) -> Bool {
    guard let fn = slPostEventToPidFn, let ev = event else { return false }
    fn(pid, ev)
    return true
}
```

After successful `cuResolveSkyLight()` at the inject case, and after `guard let` on every CGEvent, **`SKYLIGHT_POST_FAILED` is effectively unreachable in the happy path**. That is fine — it is a defensive belt, not a live SPI-status channel. Collapsing it into `CGEVENT_CONSTRUCT_FAILED` would mix "couldn't build event" with "couldn't call SPI", which are different root causes if either guard ever fires.

**Do not** re-introduce a single `SKYLIGHT_SPI_FAILED` umbrella for LLM copy. Plan v2 called that out: upgrade messaging must not apply to post/construct failures.

**NIT**: `slPostToPid` comment still says "caller must fall back to HID" — HID path was removed (F6). Comment is stale; fix in Stage 3 drive-by. Not load-bearing.

## Q2 — `assertInjectOk()` silent-failure modes?

**Answer: No new silent-failure modes vs the previous broken inline pattern. One documentation drift.**

**What was fixed (load-bearing):** old inject paths discarded stdout and treated exit 0 as success. Host always `print(out); exit(0)` on structured `cuError` (`host.swift` ~569–570). F9 parse+checkOk closes that hole.

**Production path** `[inspected]`: all five methods use:

```ts
stdout = await spawnHostBin(...)
const parsed = parseComputerJson(stdout, "inject")
checkOk(parsed, "inject")
```

**`assertInjectOk` itself** is exported and tested, but **not called** by the five inject methods. Comment claims "Used by every inject path" — false. Tests prove composition equivalence (`parse + checkOk === assertInjectOk`). Functionally identical; no silent drop.

**Failure surfaces correctly:**

| Failure | Path | Result |
|---|---|---|
| Integrity / TOCTOU / exec throw | `catch` → `rethrowDarwinExecError` | `ComputerError("INVALID_ACTION", …)` |
| `{ok:false, error_code}` | parse + checkOk | `ComputerError(error_code, …)` |
| Malformed JSON / non-object | parseComputerJson | `ComputerError("INVALID_ACTION", …)` |
| Missing `error_code` on ok:false | checkOk default | `INVALID_ACTION` |

**Minor type hygiene** (not a silent failure): `ComputerErrorCode` union in `types.ts` does **not** list `SKYLIGHT_SPI_UNAVAILABLE` | `SKYLIGHT_POST_FAILED` | `CGEVENT_CONSTRUCT_FAILED`. `checkOk` passes `parsed.error_code` via `Record<string, any>`, so runtime works and F9 tests pass `[executed]`, but the type system lies. Executor already forwards `err.code` as a string to the LLM (`errorCode: err.code`). **Recommend 3-line union update before Stage 3 ship**; not required for G1.

**Test gap (honest, low risk):** G3 tests exercise `assertInjectOk` only, not `MacInputInjector.click()` with a mocked `spawnHostBin`. Production methods clearly call parse+checkOk; residual risk is future refactor deleting the inline pair without switching to the helper. Prefer wiring inject methods through `assertInjectOk` in a tiny cleanup commit (DRY + comment truth).

## Q3 — TOCTOU gaps vs `swift-tray-bridge.ts`

**Answer: No new TOCTOU gap beyond the tray pattern's known residual. One behavioral difference is inherent to CLI vs long-lived spawn.**

| Step | tray (`swift-tray-bridge`) | `spawnHostBin` | Match? |
|---|---|---|---|
| realpath → open fd → fstat → hash from fd | yes | yes | yes |
| pre-spawn refuse on hash mismatch (no auto-rebuild) | yes | yes | yes |
| spawn via realpath | yes | yes | yes |
| post-spawn inode+dev re-stat | yes | yes | yes |
| on post mismatch: kill long-lived proc | yes (`this.kill()`) | N/A — `execFile` already finished | CLI residual |
| swap-back race (malicious during exec, restore before post-stat) | residual | residual | same |
| content rewrite in-place same inode | residual | residual | same |
| T4 unit-tested | production-tested honesty | same honesty comment | yes |

**Dev hatch split is correct:** `CMSPARK_SKIP_HOST_INTEGRITY=1` ≠ `CMSPARK_ALLOW_HOST_BIN_OVERRIDE`.

**Scope honesty:** `host-integrity.ts` header says "do not call execFileAsync on cmspark-host directly elsewhere." Computer-use **non-inject** paths (window-list, screenshot, OCR, ax-probe, …) still use bare `execFileAsync` `[inspected]`. That matches Plan F4 (inject + `defaultDarwinRunner` only). Comment overclaims; residual S-P0-2 expansion is Stage 4, not a C-minus regression.

**SHA pin** `[executed]`: `dist/cmspark-host` SHA256 `84f89e26…d437a3` matches `CMSPARK_HOST_SHA256`. Integrity T2 spawn of `security-check` returned `ok:true`.
