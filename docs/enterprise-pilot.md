# 企业材料试点（0.7.0 开发中）

跟踪：#450（试点输入）、#452（网页适配）、#453（核对器）、#454/#455（两个场景）、#457（首发验收）。两种场景均为发布阻断验收项。当前示例是配置示范，不是已完成的企业验收，不修改现用配置或自动安装应用。

## 配置准备

由试点负责人复制 `docs/examples/pilot-contract.v1.json` 到独立试点数据目录的 `pilot-contract.json` 后编辑。正式数据目录默认为 `~/.cmspark-agent`；隔离试点可使用 CMSPARK_DATA_DIR。不要将企业正文、凭据、原始 query/fragment 或业务真值提交到公开仓库/Issue。

- origins 只写精确 HTTP(S) origin：协议、主机、端口；无路径、query、fragment、userinfo、wildcard。示例 `.example.test` 不能用于真实采集。
- system_key 是来源平台命名空间，与业务系统 ID 不同。target.system_id 表示业务系统。跨系统同号 ID 不自动合并。
- 一个 origin 有多个环境时，每行配置 environment_selector 与 environment_literal，必须实际读取该精确 selector 且文字能唯一判别环境。不能只凭域名或从 non-prod 截出 prod。
- collection_scopes 为每个必需集合登记实际 document/selector 范围和精确 empty_marker。static_declaration_v1/1 是试点负责人对静态完整范围的声明，不会遍历分页/虚拟列表/iframe。真实结构不满足时不得使用它宣称完整，应在 #452 另做适配。
- source_bindings 的来源范围必须能明确展示双方 native ID 对应关系。示例中 code/tests/defects 的 requirement 端点是各平台对需求的 native reference；tests_commit 是测试平台与代码平台的 commit 引用。架构端点 system@revision 是本地派生身份，来源仍需两项原始值。mappings 只能由试点负责人维护，不能由模型自授。
- required_fields 是在固定 schema 上增加必需项；建议共享两场景的配置先留空，默认 schema 已要求基线材料。pass_values 必须匹配平台实际通过值。
- 默认可变字段 24 小时、CMDB 业务时间 15 分钟、测试业务时间 24 小时。调整窗口需要负责人明确决策。业务时间应为可无歧义解析的带时区时间，采集时刻不能代替业务时间。
- 当前业务时间接受 `YYYY-MM-DDTHH:mm:ssZ` 或 `YYYY-MM-DDTHH:mm:ss+08:00` 等完整格式，可有 1–3 位小数秒；不接受仅日期、小写 z 或无分钟偏移。标准文字互相包含时，用例对应会保守标为未核实，需在真实试点中处理，不能用整页共现替代明确对应。
- 可选 runtime_not_applicable 仅对事先明确没有运行资产要求的场景生效，必须给理由；模型提交 N/A 不生效。

当前通用聊天中的成功页面读取也会形成同会话的有界持久证据，并非只在两个 Mission 中保存。计划只读、已停止、会话已删除和非原子 DOM 回退不会新增证据。

同一会话首次 draft_create 原子锁定配置快照。改配置要新建会话，旧证据不会按新配置重新解释；首次创建前的读取不追补完整覆盖。每个 scope 限 64 条 Observation、单条规范化正文 64 KiB、16 草稿、总文件 4 MiB（含请求重放记录），先触及的上限生效，不逐出旧引用。容量满请保留原草稿并新建会话处理剩余任务，不删除旧引用来冒充齐备。

## 两个首发验收包

负责人在私有试点记录中填写实际 OS/版本、CMspark 提交、企业模型 endpoint 的非敏感标识/模型版本、许可数据范围、契约 SHA-256、页面结构、操作者和业务真值。Issue 只记录脱敏的运行 ID、结果及失败类别。

| 场景 | 正例真值 | 必验负例 |
| --- | --- | --- |
| 变更材料 | 同一目标系统/环境的发布、构建、制品、架构依赖/影响、CMDB 资产及业务时间；每项可回到来源 | 错环境/业务系统、不同 build、过期运行态、缺业务时间、分页/截断、没有源关系、容量不足 |
| 研发关联 | 需求/完整标准、标明创作的故事、网页验证代码身份、测试运行及标准到用例映射、缺陷状态 | 错需求/commit、未覆盖标准、未知用例、失败测试、无引用代码链接、未知缺陷是否为空、跨 scope 引用 |

两者都走产品入口选择对应 Mission Pack，在无 Codex、无 shell/CU、无多 Agent 运行时条件下执行；变更页面保持既有授权。记录真实工具轨迹与最终 Markdown/JSON，人工逐项核实引用范围、时间和对应关系。齐备待复核不等于已发布变更或研发完成。合成测试只验证契约/调用链，不替代该记录。

另验：中途停止、只读计划模式、重连/重启读旧草稿、响应丢失幂等重试、并发 revision 冲突、旧版忽略新目录后再次升级、未知 schema 原文件保留。MCP 作为可选入口在 #456 单独验证 grant/session、撤销、授权子集和 URL 脱敏；不成为独立模式依赖。
