## 1. 两条产品线（不要混）

| | **听写+（L-B）** | **会议记录（L-C）** |
|--|------------------|---------------------|
| 入口 | 主对话 composer 🎤 | **个人工作台 → 开始会议** / 侧栏「会议」/ `/meeting` |
| 产物 | 草稿文本（不自动发送） | 本地会话转写 + 结构化纪要 |
| 长录 STT | 连续听写可用浏览器或本机，聊天外部转写见 §2.8 | 工作台麦克风与导入录音默认在本机转写，可在会议转写设置中选择外部服务 |
| 说话人 | 无 | 手动 / 实验性「发言人N」 |
| Pack | **不得**改 voice / 热键 / ack | 仅 skills + 纪要 prompt |

全局 **max-1**：会议录音中禁用听写；听写中无法开始会议录音。

## 2. 听写+

### 2.1 形态

在「设置 → 输入与交互 → 聊天听写」选择听写语言。默认普通话，英语口述可选美式英语。DeepSeek 文件转写会自动识别语言。会议使用会议页的「字幕语言」选项。

1. **经典短听**（默认）：点按 🎤，约 ≤45 秒，无静默续听  
2. **连续听写**（设置 opt-in）：更长口述；浏览器自动续听；本机可分段 / 渐进假设  
3. **按住热键（D2）**：设置中开启；**按键盘录制**组合键或选预设；**按住说话、松手结束**；默认关  
4. **实时出字**（设置）：浏览器 = Web Speech interim；本机 = M2 渐进假设（见 §2.5）

时长：软提示约 5 分钟；硬上限默认 15 分钟（设置可调，绝对上限 30 分钟）。

### 2.2 ASR 纠错

- 默认 **关**；听写：停录后可选一枪「识别纠错」（不是润色）  
- 会议：勾选 **「录制 AI 纠错（参考上文）」** 时，每段原始转写先显示，后台使用上文做 **correct_only** 同音字/术语消歧，并单独展示建议；不等待纠错才出字，不自动覆盖原始转写（与听写共用开关 `asrRefinerEnabled`）
- 只发**转写文本**给当前 Companion LLM，不发音频  
- 失败则保留识别原文；不会边听边做「润色/扩写」 

### 2.3 按住热键（D2）

| 项 | 说明 |
|----|------|
| 默认 | **关闭** |
| 设置方式 | 勾选启用 → **「按键盘录制」** 或点预设 chip |
| 建议键 | mac：`⌃⇧Space` / `⌥Space`；Win：`Ctrl+Shift+Space` |
| **禁止** | bare `fn`、单独 `Meta+V` / `Win+V` |
| 前置 | Companion 已连接 + **Side Panel 打开且获得键盘焦点** |
| 行为 | 按下 → 开始**连续**听写管线；松开 → 结束并可选纠错 |
| 互斥 | 与点按 🎤 同一会话；会议录音进行中会拒绝 |
| 反馈 | 侧栏内时长/状态；开始时系统通知「CMspark · 草稿」 |

OS 级全局热键（失焦仍按住）属后续增强。

### 2.5 本机组件（cmspark-whisper）与模型

本机听写分两层，都可在 **设置 → 输入与交互 → 聊天听写** 完成：

| 层 | 内容 | 如何就绪 |
|----|------|----------|
| **本机组件** | `cmspark-whisper` + 动态库 | 安装包优先内置；若提示「未找到」→ **「安装本机听写组件」**。Windows：HTTPS 自动下载 + sha256 pin。macOS：安装包内置或从本机 **Homebrew whisper-cpp** 拷贝（需已 `brew install whisper-cpp`） |
| **模型权重** | ggml-small / medium / large-v3-turbo | 设置页下载到 `~/.cmspark-agent/models/whisper/`；下载完成自动设为活动模型；已下载模型会被自动识别（设置页状态探测） |

下载源默认 huggingface.co，网络受限时在 **设置 → 输入与交互 → 聊天听写 → 模型下载源** 改填镜像（如 `https://hf-mirror.com`），或设环境变量 `CMSPARK_HF_ENDPOINT`（优先级更高）。
本机模型不可用时：默认**当次会话自动改用浏览器听写**并显示横幅（非静默、不改配置）；可在设置关闭「本机模型不可用时自动使用浏览器听写」。  

聊天听写设置中的「麦克风」可为本机、系统和外部转写选择输入设备，修改后点击底部「保存」。浏览器听写使用 Chrome 的麦克风设置；会议采集使用其各自的输入设置。模型推荐参考本机内存与 CPU 核心数，实际速度取决于推理后端。

打包：`build-package.bat` 在缺少 `companion/dist/bin/cmspark-whisper-win-x64.exe` 时会按 `assets/whisper-binary.manifest.json` **自动拉取**（`CMSPARK_WHISPER_AUTO_FETCH=0` 可关）。  
Windows pin 与 [whisper.cpp v1.7.6](https://github.com/ggml-org/whisper.cpp/releases/tag/v1.7.6) `whisper-bin-x64.zip` 对齐。

### 2.5.1 Windows 显卡加速

Windows x64 的聊天听写设置会列出显示适配器和显存。先保留已就绪的 CPU 本机组件，再根据显卡主动安装加速组件：NVIDIA 优先 **CUDA**，AMD／Intel 和其他兼容显卡尝试 **Vulkan**；NVIDIA 也可使用 Vulkan。CUDA 包约 443 MB，经 HTTPS 下载和完整校验；Vulkan 约 7 MB，安装包随附，仍需点击安装。程序不自动安装显卡驱动，不自动下载组件或更换活动模型。

**下一次自动选择候选**表示根据硬件、驱动和组件检查得到的计划。**最近一次执行**显示真正转写成功的 CPU／CUDA／Vulkan、GPU 名称、时间和耗时，尚未运行时显示暂无记录。组件已安装或显卡已发现都不代表 GPU 已成功执行。虚拟显示、软件渲染、驱动异常或组件文件校验失败会显示原因；GPU 尝试失败时可在同一请求时限内回退 CPU。取消按钮只取消它显示的后端安装。

当前实体硬件验证为 RTX 4080 SUPER；AMD／Intel 的识别和 Vulkan 路径已覆盖，实体卡执行仍待验证。Vulkan 要求显卡驱动提供兼容实现；无法运行时保留 CPU。Windows ARM64、macOS 和 Linux 没有因本功能新增 GPU 支持承诺。实测输入、速度与限制见[本机验收记录](audit/windows-voice-gpu-20261123.md)。

### 2.6 本机 Whisper 渐进假设（M2）

开启 **本机听写** + **连续听写** + **实时出字** 时：

| 项 | 行为 |
|----|------|
| 采集 | 16 kHz PCM 流式上传（AudioWorklet 优先） |
| 临时字 | 会话内 snapshot → Whisper **重解码** → 草稿 interim |
| 定稿 | 约 **8s** 窗口结束一次 final（非整段等停） |
| poll | 按上次推断耗时自适应（约 1.4–6s） |
| **诚实边界** | **不是** decoder-token 真流式；medium 临时字会偏慢 |
| **large-v3-turbo** | **无**渐进临时字（仅终稿）；CPU 上短音频也可能耗时较长；设置根据硬件资源推荐模型 |

浏览器听写路径：Web Speech 字级 interim（厂商云 STT 残留，见 v1 ack）。

### 2.7 文字 / 语音改设置

设置页顶部支持短命令，例如：`开启连续听写` · `开启实时出字` · `浏览器听写` · `打开会议` · `打开场景`。可键盘输入或点「语音」口述（不进聊天、不 auto-send）。

### 2.8 聊天外部转写

在 **设置 → 输入与交互 → 聊天听写** 可选择「外部转写」。启用后，这次聊天麦克风录制的音频会发到所填的转写地址。会议音频使用独立的转写服务配置。说话人分离在本机处理。

两种接口不要混成「DeepSeek 的聊天兼容就是转写」：

| | **DeepSeek 官方转写** | **OpenAI 兼容转写** |
|--|----------------------|---------------------|
| 地址 | 空、`/v1` 或完整路径都会收成 `https://api.deepseek.com/v1/tools/asr`。聊天补全地址不算转写地址 | 空地址收成 `https://api.openai.com/v1/audio/transcriptions`。其它主机只在你写的路径后补一次 `/audio/transcriptions` |
| 请求 | 只上传一个 `file`。不发送模型名，也不发送语言 | 上传 `file`、已保存的 `model`，以及听写语言的 ISO-639-1 主标签（`zh-CN` 发送 `zh`）。不发送流式、提示词或温度 |
| 出厂停止线 | 120 秒和 8 MiB（8,388,608 字节）。保存时不能再高 | 官方主机 `api.openai.com`：文件 25 MB（25,000,000 字节，按十进制），文档没有统一时长，所以时长出厂为空。其它兼容主机用同一组出厂数字，但说明写成「本机停止线」 |
| 模型 | 设置页不显示模型框，已保存的名字保持不动，请求里也不带模型 | 设置页显示已保存的模型。可见默认仍是 `whisper-1`。官方指南另推荐 `gpt-transcribe`，并写 `whisper-1` 将于 2027-02-26 关闭；这里不自动改掉已保存的名字。模型留空则这次不发送，也不会偷偷换成 `whisper-1`。语言留空则省略该字段，不另造 `zh` |

录音仍是 16 kHz、单声道、16-bit PCM WAV。谁先到停谁：时长或文件大小。已录的前缀打成一份 WAV，只发一次，不按静音再切，也不拆成会议。到点后界面写「已到录音时长上限」或「已到文件大小上限」，并接着「正在转写已录的这一段」。两道同时越过时两句都出现。本机听写的 45 秒、2.5 MB、90 秒推理和侧栏 95 秒等待不套到外部转写上。

32 MiB（33,554,432 字节）是这一次聊天录音在 Companion 里能留下的最大 WAV，用来保护进程内存。它不是服务商的上限，也不是无限容量。其它兼容主机可以把体积调到 32,044 与 33,554,432 字节之间，时长可以留空，或设为 1 秒到 30 分钟。留空时只按体积停。官方 OpenAI 主机不能超过文档里的 25 MB。DeepSeek 不能超过文档里的 120 秒和 8 MiB。保存一个更大的数字会被拒绝，原来的配置保持不变。

请求超时默认 180 秒，可设 30 秒到 600 秒，覆盖地址解析、上传和等待响应。服务返回 HTTP 408 或 504 时也会提示超时。本次请求停止，侧栏再多等 10 秒收取结果。本机听写仍等 95 秒。

录音中连续 15 秒没有下一块，视为管道断了：不上传已录片段，并说明没有发送音频。说话中间的短停顿只要还在送音频，就不算这一种。

取消：

- 还没发出：删除缓冲，输入框不插入文字。文案是「已取消，没有发送音频。」
- 已经开始 POST：停止等待，丢掉迟到的文字。文案是「已停止等待。音频可能已经到达你填写的服务器。」不能把它理解成对方一定没收到。
- 断线、关掉侧栏或把引擎切走，同样停止这一次，不自动改回浏览器或本机，也不自动再发。

密钥、地址和模型与聊天模型分开保存，没有「沿用聊天钥匙」的开关。密钥写在这台电脑的 `~/.cmspark-agent/config.json`，文件权限与现有聊天密钥相同（配置文件仅本人可读写，目录仅本人可进入）。这不是系统钥匙串，文件内容也没有再加密。侧栏只显示密钥是否已保存，不显示原文。保存设置不会去连接该地址，也不能证明它支持转写；设置页没有「测试连接」。上限说明只解释数字从哪来，不是对你的账号做过探测。

这次没有拿真实的 DeepSeek 或 OpenAI 转写服务做准确率测量，指南不写识别准或不准。本机 Whisper 的速度和准确率优化仍是以后的单独计划，不在这条外部转写里改。

打开原有的「识别纠错」后，只有转写出来的文字会再发给聊天模型。音频不会因此再上传一次。纠错失败保留原文。

## 3. 会议记录

### 3.1 从个人工作台开始

从侧栏顶行或插件弹窗点击 **工作台**，在完整页面办理当天的事项。再次点击会切回已有的工作台标签页。

| 首页操作 | 使用路径 |
| --- | --- |
| 开始会议 | 打开会议记录，选择桌面会议、麦克风或导入录音。结束后核对逐字稿、接收方和发送范围，再生成纪要。 |
| 录屏 | 选择浏览器提供的共享来源。停止后可预览、下载 WebM 或清除本机记录。 |
| 实时转写 | 打开麦克风转写，按段查看识别结果。保存的逐字稿可从「最近会议」重开。 |
| 翻译 | 输入文字，核对模型、接收方和目标语言后发送。会议页也可以逐段翻译已保存的原文。 |
| 待办 | 在「活动记录」选择允许采集的应用并开启采集。在「待办」核对聊天候选的原文，确认后成为正式事项。 |

侧栏「会议」、场景里的「打开会议工作台」及 `/meeting` 均可直接进入会议。进入页面后，由用户点击开始录制。

**外部会议软件**　在会议页选择桌面会议。如需录自己的发言，保留麦克风选项。只旁听时可以取消。核对转写服务后选择会议软件窗口或整个屏幕，并在共享选择器中勾选声音。共享整个屏幕时，其他应用的提示音也可能进入逐字稿。窗口没有声音选项时，可重新选择支持共享声音的屏幕。浏览器或系统未提供音轨时，工作台会提示重新选择。

录屏保存在当前浏览器配置的本机录屏库。转写会使用同一份会议声音；如使用外部转写，接收方会收到所选来源的音频。停止后核对逐字稿，再确认纪要接收方和发送的文字。

**PPT、表格和代码演示**　开始桌面录制前，勾选「保留画面要点（本机）」。换页后停留约一秒有助于保存稳定画面。只改一个数字、短暂显示弹窗或快速滚动时，可点击「标记当前画面」。自动留存最多每五秒一张，每分钟另检查一次，重复图片去重。每场上限为 240 张或 32 MiB。最后留存时间及失败次数显示在会议页。

录制结束后，在「模型与服务 → 会议画面理解」选择已配置的视觉服务或支持图片的命名模型。返回会议页，选择最多 12 张截图，点击「理解所选画面」。展开各时间点可查看将发送的原图和相邻转写。核对模型名称和接收地址后，点击「确认发送并识别」。完整录屏保存在本机；口头讨论可直接按原流程生成文字纪要。

生成纪要前可移除误读的画面证据。文字纪要模型会收到确认范围内的逐字稿、模板和画面识别文字。点击纪要里的画面时间可核对本机原图，播放器支持定位时也可跳到相应片段。会议中展示的提案、预览代码或预算数字应结合发言中的决议核对。

| **P4 纠错/分段** | 段定稿 **opt-in AI 纠错**（上文上下文 + correct_only）；段间空行分段；结束时可选自动智能分段 |

### 3.3 会议录制操作要点

1. 先确认 **本机语音隐私** + **会议隐私**（双 ack 后「开始录制」才可点）  
2. 在 **设置 → 输入与交互 → 聊天听写** 下载本机组件和模型。会议面板会提示需要的组件，并提供「启用本机转写」。
3. 可选：勾选 **录制 AI 纠错（参考上文）**、**结束时智能分段**  
4. 录制中段失败：若为 soft 类错误，banner 会说明 **本段字已丢失（不可恢复）**，后续段继续；结束仍默认删音频  
5. 点击 **结束并生成纪要**。最后一段转写保存后，核对所用模型和发送的材料，再确认生成。结束后也可单独生成、智能分段或选择模板。

### 3.3.1 录音与参考笔记

- 点击 **导入录音**，选择浏览器能够解码的 WAV、MP3 或 M4A 等文件。默认分段在本机转写，结果追加到已有文字。
- 在 Chrome 扩展导入录音时，可以在 **设置 → 模型与服务 → 会议转写** 选择外部服务，并填写服务协议、地址和独立密钥。OpenAI 兼容服务还需填写模型名称。每次导入都会列出文件、模型和实际接收地址，确认后才将音频分段发送。桌面召唤器的录音导入使用本机转写。
- 外部转写按顺序处理每段，最多 45 秒一段。服务失败或用户中止会停止后续发送，已完成的文字仍然保留。面板会区分本段未发送、服务已收到请求及是否到达未知。
- 参考资料：在独立的参考笔记区输入文字，或导入 **.docx / .md / .txt**。单文件不超过 7 MiB、解析文字不超过 100000 字；超限会拒绝并提示，不截断冒充完整资料。旧版 .doc、照片和扫描件不在这次解析范围。
- 参考笔记可以是会议手记、术语、议程。它们与原始转写分别保存，不会作为另一份录音转写直接覆盖原文。
- 在 **设置 → 模型与服务 → 会议纪要** 可沿用默认对话模型或选择已配置的文本模型。确认生成后，所选模型处理转写、模板和参考笔记。带参考资料的结果保留独立校正稿、修改依据、笔记补充和待确认冲突，原始转写仍可查看。
- 修改转写或笔记后，旧纪要标记待更新。重新生成失败时保留材料，不用旧纪要冒充本次成功结果。

### 3.4 诚实边界

- **不是**飞书/Otter 级多方 diarize SLA  
- **系统/会议软件混音**：未做产品能力，见 [parking 调研](superpowers/specs/2026-08-08-meeting-system-audio-parking.md)  
- 纪要 LLM **不得臆造**未出现的出席人/决议；已有标签可沿用  
- **近实时**是 Whisper 重解码假设，不是厂商级字级流式；CPU 上 medium 临时字会偏慢  
- **3 小时**为产品硬上限  
- AI 纠错是 **段定稿后** 的 correct_only（可带上文消歧），**不是**边听边全量 LLM 改写，也不是语义润色（ADR-024）  
- 工作台内的麦克风与导入录音共用「设置 → 模型与服务 → 会议转写」。启用外部服务后，每次开始前会显示音频范围、模型和接收地址。桌面召唤器继续使用本机识别。

### 3.5 数据位置

`~/.cmspark-agent/meetings/<id>/`（权限收紧）：`transcript.json` 保存当前编辑稿，`original-transcript.json` 独立保留识别原文，`reference.json` 保存参考笔记及文件名；另有会议元数据和纪要。AI 纠错稿不会替换识别原文。

### 3.6 转写错误 resource_conflict / 本机识别

源码已合入 [#494](https://github.com/nehcuh/cmspark/issues/494) 的持续采集与有界识别队列，适用于侧栏与召唤器的连续会议入口。识别一段音频时继续采集，界面显示积压秒数、已处理范围、已保存原稿段数与排空状态；识别仍按段完成，不是字级实时转写。安装包是否包含这项改动请核对[版本与交付状态](release-status.md)。

- **容量与停止**：PCM 队列上限约 60 秒。识别持续赶不上、达到三小时上限、输入中断或连接异常时会停止采集并明确标出原因，不承诺无限积压或无损连续录满三小时。正常停止后仍需等待已接收音频排空；取消、失败或断开时以界面标记的已保存范围为准。
- **会话争用**：`resource_conflict` 表示识别资源仍被其它会话占用。先停止占用资源的听写/会议并等待其结束，再重试；连续采集持有的识别资源不会被另一个入口强行抢占。模型、组件或内存问题会单独报错，不能把失败视为完整转写。
- **音频留档**：连续采集协议不保留原始录音文件。需要完整音频留档时，请另外保留原录音，通过「导入录音」处理。

### 3.7 纪要模板

- 会议工作台可展开 **「纪要模板（可选）」** 粘贴自定义 Markdown 模板（本地记住上次内容）。
- 留空则使用默认：TL;DR / 决议 / 待办 / 风险。
- 模板只约束**输出结构**，不能让模型编造转写中没有的事实。
