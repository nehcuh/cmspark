# 开发交付物模板

针对用户给的需求/页面现象/代码片段，按下列结构产出：

## 1. 结论先行
- 问题/目标一句话 + 推荐方案一句话

## 2. 实现拆解
- 表：`改动点 | 影响面 | 风险 | 测试点`
- 明确标注哪些改动需在真实仓库由主对话执行

## 3. 代码 / 页面走读
- 基于实际读到的代码/页面：逻辑链路、可疑点、与需求的 gap
- 引用真实行/段落做证据

## 4. Bug 定位（如涉缺陷）
- 复现线索、根因假设（证实/待验证）、最小修复方向

## 5. 质量门禁清单
- 功能 / 边界 / 错误处理 / 性能 / 兼容性 逐项核对
- 每项给「通过 / 待补 + 建议」

## 6. 交主对话执行的显式列表
- 明确列出需要真实权限的动作（改码、跑测试、提交），不假装已完成

规则：页面验证须注明 tabId/证据；**不得声称**已改代码/已跑测试/已有仓库权限。
